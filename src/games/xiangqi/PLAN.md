## 二、要做的事（在 `logic.ts` 的纯函数之上加，不重写走法生成）

1. **`rules.ts`**：局面指纹（含走棋方）、重复局面三次判和、**长将三次判负**、非法走子的一句话原因
   （蹩马腿 / 塞象眼 / 象不能过河 / 兵不能后退 / 送将 / 飞将）、将军应将状态机。
2. **`notation.ts`**：中文纵线记谱。红方纵线从右往左「一~九」，黑方从左往右「１~９」，
   进 / 退 / 平，前后子消歧（「前马」「后炮」），复盘面板与残局讲解都用它。
3. **`ai.ts`**：六档 `novice | easy | normal | hard | master | hell`，全部建立在
   `allLegalMoves` / `applyMove` / `statusOf` 之上；置换表、杀棋优先、开局库、迭代加深限时。
4. **`endgames.ts`**：188 课残局静态数据（紧凑串编码）+ 8 个章节；每课带主题、限步、一句讲解。
5. **`solve.ts`**：`mateSearch` 强制将死搜索 + **首着解集枚举**，用来做「唯一主线解」的可解性断言。
6. **`session.ts`**：落子确认状态机、残局连胜阶梯、`level → AI 档` 映射、`initialLevel` / `?level=` 解析、
   悔棋 / 认输 / 求和的双人同意状态机。
7. **`view.ts`**：棋盘画布（2D，木纹 + 极轻投影）、「将！」徽章、被将脉冲、合法点小圆点、
   半透明预览子、44px 热区、`prefers-reduced-motion` 降级。
8. **`index.ts`**：装配 —— `mountLevelGame` 挂 188 课 + 自由对战（六档 + 双人同屏）+ 残局连胜。
9. `meta.ts` 补 `campaign` / `levels: 188` / `platform`，`guide.ts` 按 8 章重写；测试新增 ≥ 35 例。

## 四、188 课的章节（8 章，大小之和 = 188）

将死入门 / 一步杀 / 二步杀 / 困毙 / 马炮配合 / 双车错 / 巧渡兵 / 和棋要避开。
章节名用中文原创描述（「一招定音」「双车并进」这类），不甩生僻术语。

**可解性验证**：`endgames.test.ts` 逐课跑 `solve.ts`：
① 声明的 `mateIn` 步数内红方有强制杀；② 少一步就杀不掉（步数是紧的）；
③ **首着解集只有一个着法**（唯一主线解，等价的将军次序体现在后续着法上）；
④ 困毙课单独断言终局是 `stalemate` 而不是 `checkmate`；⑤ 和棋课断言最优只能逼和。

## 五、长将怎么判

`rules.ts` 记录每一步之后的局面指纹与「这一步是不是将军」。同一方**连续将军**且
「(将军着法, 结果局面)」这一对出现第三次时判该方负，UI 提示「换一条进攻路线试试」。
非将军的重复局面出现三次判和。两条都是纯函数，各自有测试。

## 六、真·无尽为什么不做

象棋一局的终点由将帅决定，没有「同一盘无限续下去」的维度：硬加计时或无限补子都会改掉象棋本身。
用**残局连胜**替代——连续通关残局计数，输一课结束，最高连胜写 `save.recordEndlessBest("xiangqi", n)`。

## 八、落地之后与计划不一样的地方

写完跑起来才发现的三件事，都记在这里，免得下次再踩：

1. **六档一开始根本分不出高下**。固定 seed 对局里大师打简单只有五五开。挖下去是三个毛病叠在一起：
   一是只有地狱档做迭代加深，其余档位一次搜到名义层数，时间一到就只剩半层残缺的排名；
   二是地狱档的穷举杀法算在时间预算里，残局里搜索一开跑就判超时，直接退回贪心着法；
   三是评估里「谁在保护谁」用 `rawMoves` 数，而它永远不会返回自家子占着的点，
   于是每个被盯上的子都算成白送，噪声比子力差还大。三处修完：大师打简单 12:0，地狱打普通 10:1。
2. **对局测试不能看真表**。迭代加深挖多深取决于时钟，同一份代码两次跑出来的战绩不一样。
   `ThinkOptions.now` 换成「问一次走一格」的假时钟之后，预算等价于固定结点数，换台机器也是同样的棋。
3. **残局数据里的收官标记有 32 条是错的**。生成时记的是「有没有将死」，
   可强制胜里有一半黑方是被困毙的（走到底根本没挨将）。标记按主线实际的收官方式重算了一遍，
   `endgames.test.ts` 每次跑测试都会重验，改坏立刻红。
