# 1.2 第 22 步 · C 档 —— `poop-hero`「便便超人」升级计划

对着 `docs/plan-1.2-step22-C-poop-hero.md` 写。只动 `src/games/poop-hero/**`,
不碰 `landlord-cards` / `fishing-star`,不引入任何依赖,保持 2D。

## 一、现状审查(1.1 的事实)

1. **核心动作**:跑 / 跳 / 蹲 + 冲刺清扫 + 扫一扫两种清洁动作;纯函数全在
   `logic.ts`(物理、评分、事件队列、自动通关机器人),关卡数据在 `levels.ts`。
2. **188 关**:8 章确定性生成,目标类型只有一种 ——「清到 requiredRatio 再进净化门」;
   后段靠密度、追逐、滑地板、管道、废纸团加压,没有第二种任务目标。
3. **coop**:两人同屏、同一套动作,只是「一起清、一起到门口」,没有分工,单人也玩得完。
4. **endless**:一段接一段的线性街区,成绩是自己算的分数(清洁数 / 星 / 距离),
   记在 `save.recordEndlessBest("poop-hero", 分数)`。
5. **教育元素**:只有「把脏东西变成花」的隐喻,没有垃圾分类、洗手这类真常识。
6. **手机**:摇杆 + 冲刺 + 扫一扫已经是网格布局,但键位尺寸是写死的媒体查询,
   没有一处纯函数能被测到。

## 二、1.2 要落地的东西

| 项 | 做法 |
| --- | --- |
| 手感常量化 | 新建 `tuning.ts`,移动 / 跳跃 / 清扫 / 冷却 / 惯性 / 清洁车全部集中,冻结成 `HANDLING`;`stepWorld` 继续切 ≤1/120 子步,补 30fps vs 60fps 位移差 < 2% 的用例。 |
| 垃圾分类 | 新建 `trash.ts`:可回收 / 厨余 / 其他三色桶 + 18 条真实分类数据;关卡里散落垃圾,门前摆分类站;投对给额外星星,投错只温和提示、不扣分、东西还在手上。 |
| 三种新关卡 | `mission`:限时清扫(倒计时更紧)、护送清洁车(推车到净化门才算完)、暴雨天(`weather:"storm"`,摩擦更小、惯性更大,不放断口)。只加在第 100 关往后。 |
| 合作深化 | `coop` 两人分工:鸭梨只清扫、康康只搬运分类;共同目标条 = 清扫进度 + 搬运进度;三星要求「清完 + 运够 + 不超时」,单人模拟拿不到三星。 |
| 无尽 | 「打扫不完的城市」:区块随机拼接,脏乱度随时间上涨、清东西能压下去,涨满就结束;成绩改记 `save.recordEndlessBest("poop-hero", blocks)`。 |

## 三、题材继续收紧(最重要的一条)

- 「臭臭怪」→「豆豆怪」,「臭味潮」→「尘土风」,一切与气味有关的字眼从文案里去掉。
- 豆豆怪造型统一成**圆润豆豆 + 笑脸 + 粉彩色**,不用棕色写实;泥洼改成浅蓝水洼。
- 结算、失败、提示一律正向,配 `trash.ts` 里的卫生小提示(洗手、分类、擦干净)。
- 前 99 关的**几何与数值一个都不改**(用例里用摘要哈希钉死),只把措辞洗干净。

## 四、平台与手机

- `runtime.ts`:`createDisposer`(rAF / 定时器 / 监听统一登记,`destroy` 归零)、
  `padMetrics`(360px 下摇杆与清扫钮的格子尺寸,热区 ≥ 44px、不重叠)、
  `resolveInitialLevel`(`api.initialLevel` 或 `?level=`,越界 clamp,直开第 N 关)。
- `prefers-reduced-motion` 关抖动与拖尾。

## 五、测试

新增 ≥ 18 个用例:手感常量与帧率无关、分类表逐条正确、投错只提示不扣分、
三种关卡类型规则、合作三星必须两人配合、无尽脏乱度曲线与区块拼接、
前 99 关摘要不变、`destroy` 归零、360px 布局。用例只增不减。
