# 12-C · `gold-hook`「金矿钩钩」1.2 升级计划

只写本款，不动别人的目录，也不动窗口 3 的看板文件。

## 一、现状审查（对着 `docs/plan-1.2-step12-C-gold-hook.md` 第三节逐条答）

1. **钩子摆动是匀速还是带阻尼？公式在哪？**
   匀速。`logic.ts` 的 `triangleWave()` 是一条标准三角波，角速度恒为 `swingSpeed` 度/秒，
   到端点直接折返，没有任何阻尼项。这是有意的：阻尼摆在端点会慢下来，
   小朋友按「看着停住的那一下」出手命中率反而虚高，匀速摆才是真在练节奏。
   下钩速度是 `EXTEND_SPEED = 165`（1.1 里一放就是满速）；
   回收速度 `retractSpeed(w, s) = BASE_RETRACT * (1 + 0.3s) * 10 / (10 + w)`，
   上下夹在 `[MIN_RETRACT, EMPTY_RETRACT]`。规格要的 `v = v0 / (1 + w * mass)`
   就是它：`v0 = BASE_RETRACT * (1 + 0.3s)`、`mass = 1 / WEIGHT_UNIT`。

2. **关内商店几件、价格曲线合理吗？**
   三件：炸药 25 + 10/件（上限 5）、力量水 70 + 60/瓶（上限 3）、幸运石 55 + 45/块（上限 3）。
   1.1 里价钱**不随章节走**，第 188 关和第 1 关一个价，后期钱多得花不完。
   「不买也能过」成立（目标金额是模拟器**不带任何道具**跑出来的上限乘系数），
   「不买过不了」不存在。1.2 要补的是章节涨价，让后期的钱重新有去处。

3. **目标金额怎么定的？有没有靠运气的关？**
   `levels.ts::buildLevel()` 先用确定性贪心模拟器 `simulateRun()` 把这一关跑一遍，
   拿它能挖到的钱乘 `targetRatio(i) = 0.42 → 0.72`。所以「目标一定拿得到」是构造出来的。
   没有靠运气的关：埋点是 `mulberry32(seed)` 定死的，同一关每次进去一模一样；
   宝箱的价钱虽然是 60–320 随机，但也是同一颗种子摇出来后固定住的，
   而且模拟器算目标时用的就是摇完的那个值。会跑的地鼠**不计入**目标金额（`takeMoles: false`），
   纯当赚头。

4. **无尽层生成可复现吗？越深有没有新东西？**
   可复现，`endlessLayer(n)` 的 seed 是 `460001 + n * 7717`。
   1.1 里越深只是「矿多一点、时间紧一点」，没有新矿物也没有新机制 —— 这是 1.2 要补的。

5. **触屏是点一下还是长按？**
   点一下（`canvas` 的 click + 底部「放绳」按钮），没有长按。误触率低，
   但 1.1 的底部按钮在 360px 上会**换行成两排**，且高度只有约 35px，够不到 44px 热区线。

6. **地鼠轨迹可预测吗？**
   可预测。地鼠走的是同一条 `triangleWave`，左右匀速跑、到头折返，
   折返那一下几乎是停住的，就是最好的出手窗口。攻略里已经写明。

## 二、1.2 要补的东西（缺口清单）

上一轮已经落地的：手感常量（`EXTEND_RAMP` / `grabHitch` / `emptyRetractSpeed`）、
三层视差 `PARALLAX`、章节涨价 `priceAt`、泥泥矿与双层晶、照明圈 `lightRadius`、
每 5 层补给 `supplyChoices`，加 27 个单测。这一轮补剩下的：

| 缺口 | 怎么补 |
| --- | --- |
| 绳子还是一条直线 | 抽 `ropeSag(weight)`，绳子画成二次曲线，抓重物时中段下垂，空钩绷直 |
| `prefers-reduced-motion` 没接 | 抖动与跳数动画都关掉；照明圈本来就是静态径向渐变，只补断言防回归 |
| 泥泥矿滑手：每帧模型与闭式公式不是同一条曲线 | 统一成指数模型 `1 - e^(-rate*t)`，速率下调，并给一小段「刚抓到不滑」的宽限 |
| 结算没有跳数动画 | 抽 `tallyFrames()` 纯函数，`≤ 800ms`，点一下立刻跳到终值 |
| 360px 顶部字号 12px、底部按钮换行且不足 44px | 顶部 chip 与时间字号钉死 ≥ 14px；底部收成一行、`min-height:44px` |
| 无尽成绩记的是金币不是层深 | 改记 `save.recordEndlessBest("gold-hook", depth)`；1.1 的金币成绩读一次搬到本款自己的新 key，不覆盖不删除 |
| 钩住的矿画在原埋点上 | 跟着钩尖走（1.1 起就有的渲染 bug） |
| `twinValue()` 与 `index.ts` 实际发钱的比例对不上 | 以实现为准统一成对半 |
| CSS 前缀是 `gh-` | 按规格改成 `gdh-`；样式全在本款局部 `<style>` 里，不动 `src/styles.css` |
| `meta.platform` 空着 | 按实测填：键鼠有空格 / ↓ / Enter / B / Esc，触屏点画面即放绳，两边都能玩 |

## 二之二、续作这一轮补的（对着规格第九节收尾）

上一轮把第四～八节的东西都落地了，剩下第九节「平台接线」还有两个洞，这一轮补上：

| 缺口 | 怎么补 |
| --- | --- |
| 没有「直开第 N 关」的入口 | 本款的地图走平台 `mountLevelGame`，而它只吐一个 `destroy`，没有从第 N 关开始的口子。所以 `mount()` 现在返回 `{ destroy, openCampaignLevel(n) }`：不经过地图直接把那一关摆上来，结算给「下一关 / 再玩一次 / 选关地图」。星级仍旧写平台那份 `l99` 存档（`saveStar`），小星星只补比历史最好成绩多出来的那几颗 —— 直达不是刷星的后门。壳层传 `initialLevel`、或地址栏带 `?level=N`，一进来就直达 |
| 幸运石的「提高稀有矿刷新」只有函数没有调用方 | `rareWeightMult` 之前只被单测调用。现在无尽下潜会带着身上的幸运石块数生成矿层（`endlessLayer(depth, luck)`），钻石 / 宝箱 / 巨型金块 / 双层晶刷得更勤；**配额仍按没带幸运石的那一版算**，不然买幸运石就等于自己给自己加价。闯关 188 关一颗矿都没动 |

另外用真浏览器按 360×720 / 375×667 / 320×640 三个视口跑了一遍主链路，抓到两个只有在真排版里才看得见的洞：
「收工」按钮一直杵在底部那一行（`.gdh-btn` 是 `inline-flex`，把浏览器给 `[hidden]` 的 `display:none` 盖掉了），
六格挤一行的结果是「放绳」两个字被推出屏幕。修法是补 `.gdh-btn[hidden]{display:none;}`，
再把「收工」挪到顶部那一行去挨着「🎯 目标」——它俩本来就是同一件事。
现在三个视口下顶部与底部都各是**一行**、热区 44px、字号 14px，「收工」露出来时也不溢出。

顺带把 `destroy.test.ts` 里那份 DOM 桩抽成了 `domStub.ts`，新的 `platform12.test.ts` 和它共用一份 ——
两个文件各抄一遍的话，桩很快就会漂成两套。既有用例一条没删。

两路实现的分工（`logic.ts` 与 `depth12.ts`）**不是重复**，合流说明记在这里：
`logic.ts` 是 1.1 就有的内核（摆动 / 回收 / 估值 / 模拟器），1.2 一个公式都没改；
`depth12.ts` 只放 1.2 新加的那一层（手感常量、视差、章节涨价、新矿、照明圈与补给、跳数）。
两边都被 `index.ts` 接齐，同一件事只有一套数：双层晶的单次价在 `ORES`、全价在 `NEW_ORES`，
`TWIN_SHELL_SHARE` 把两者钉成二比一，`feel12.test.ts` 守着这条。

## 三、不做的

- **对战不做。** 抓矿是回合式的：一个人放绳、拉回、算钱要好几秒，另一个人只能干等，
  同屏对战的节奏被拉成「你一趟我一趟」的回合制，两个孩子挤在一台设备前会无聊。
  这一步的力气花在纵深与新矿上更值。
- **不做真透视。** 钩子角度是这个玩法唯一要瞄的东西，一透视就瞄不准，只做视差与明暗。
- **前六章的抽签袋一个字不改**，新矿只掺进第七、第八章和无尽的后段。
- 不引入 three.js、不引入物理引擎、不引入任何 npm 依赖。
