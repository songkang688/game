# 1.2 第 13 步 · C 档 —— `monster-crisis`「小怪物危机」施工记录

计划见旁边的 `PLAN-1.2-13C.md`（含规格第三节六问的现状审查）。这一份记实际做出来的东西、
实测数据，以及跟计划不一样的地方。

## 一、1.1 → 1.2 变了什么

1.1 是**塔防**：五条横道，你在左边摆颜料罐攒钱、架泡泡炮、垒棉花墙，主角只是道上的一个补刀位。
1.2 按规格改成**玩家角色亲自上场的动作防守**：

- 战场从「五条横道」换成 **360×240 的俯视竞技场**，家在正中间，小怪物从四面八方围上来。
- 你就是场上那个小人：**左下摇杆走位、右下 🎨 技能钮出手**（电脑上 `W A S D` + `F`，
  双人再加 `↑←↓→` + `L`）。自动瞄准最近的那只，孩子不用同时管走位和瞄准。
- **一件建筑都不摆了**。变强只有一条路：每 3 波从三张成长卡里挑一张。
- 判负条件从「颜料罐被搬光」改成「家里的元气罐被抱光」；popped 的小怪物会掉**元气糖**，
  攒够 6 颗能补回一罐 —— 打得凶就守得住，这条正反馈是 1.1 没有的。

`meta.blurb` 里 1.1 那句「摆路障、架炮台」已经改掉；`levels.ts` 八个章节的简介
（`desc`）也一并改口成新玩法的说法 —— **波次数据一个数都没动**，改的只有给孩子看的那句话。

## 二、目录新增了什么

| 文件 | 干什么 | 有没有 DOM |
| --- | --- | --- |
| `arena.ts` | 竞技场引擎：走位、出手、五种怪物行为、碰撞、波次、结算 | 无（可无头回放） |
| `growth.ts` | 关内成长三选一：卡池、按稀有度抽、算手感数值 | 无（纯函数） |
| `pool.ts` | 通用对象池 + `swapRemove` + 粒子预算 / 设备档位 | 无 |
| `arenaSim.ts` | 无头机器人：证明 188 关真打得过、干等一定会输 | 无 |
| `copy.ts` | 竞技场版结算文案 + 禁词表 | 无 |
| `domStub.ts` | 界面用例共用的 DOM 桩（node 环境，不引 jsdom） | 只在测试里用 |

`index.ts` 整个重写成新运行时；`logic.ts` / `sim.ts` / `levels.ts` 的**波次与难度数据原样保留**，
它们现有的 85 条用例继续跑绿 —— 现在这三个文件的职责是守住**关卡数据的难度曲线**，
新玩法的可解性由 `arenaSim.ts` 另证。

## 三、三选一卡池

| 卡 | 效果 | 上限 | 稀有度 |
| --- | --- | --- | --- |
| 🖌️ 长手刷 | 颜料弹飞得更远（每层 +28% 射程） | 4 | 常见 |
| ⚡ 快手腕 | 装填变快（每层 ×0.82） | 3 | 常见 |
| 🎨 多彩喷 | 一次多甩一发（扇形展开） | 3 | 稀有 |
| 🧲 吸吸糖 | 元气糖的吸附半径 +26 | 3 | 少见 |
| 🫧 护盾泡 | 身上多一个泡泡，被撞先破泡泡 | 2 | 少见 |

同一次抽三张**互不重复**、满级的卡退出池、同一个 seed 抽出来的三张永远一样（`growth.test.ts`）。
没有「一条路线碾压」：攻速最猛但只有 3 层，多向每层多一发但很稀有，两张一起吃才是真的铺满屏；
射程和吸附各自解决「够不着」和「捡不到」，跟输出线不冲突。

## 四、对象池实测（规格第十二节要的性能数据）

一趟 420 秒的无尽（跑到第 20 波，涂掉 356 只小怪物）：

| | 借出次数（下限估计） | 实际造过的对象 | 同时在场峰值 |
| --- | --- | --- | --- |
| 小怪物 | 345 | **24** | 8 |
| 颜料弹 / 泡泡 | 2611 | **32** | 9 |
| 元气糖 | 357 | **16** | 15 |
| 粒子 | 1849 | **32** | 20 |
| 合计 | **5162+** | **104** | — |

1.1 是 `push` + `splice`，这 5162 次每一次都是一个新对象；1.2 一共只造了 104 个，
往后再打多久都不长个 —— 造过的对象数只跟同时在场的峰值有关。
同屏怪数还有硬上限 `MONSTER_CAP = 46`，粒子按设备档位降到 24 / 60 / 120（开了
「减少动态效果」直接降到 12），低端机少画一点但一样能玩。

## 五、跟计划不一样的地方

1. **波次时间轴压到 0.5 倍**（`SPAWN_TIME_SCALE`）。`levels.ts` 那份出场时间是给塔防用的
   （一波八只拖十六秒，怪要走完整条道），照搬到竞技场里场上永远只有一两只，不像动作游戏。
   压紧之后同屏峰值从 2.6 抬到 4.1。**关卡数据一个数没改**，改的是引擎怎么读这份时间表。
2. **手感跟着重配**：上色量 4 → 5、装填 0.46 → 0.42、吸附 24 → 44、6 颗糖换一罐，
   小怪血量折扣 0.85 → 0.78（大怪那道 0.46 不动）。这一组是拿 188 关全跑扫出来的：
   0 关失守、总共还是会丢 13 罐左右，既不是白送也不在悬崖边上。
3. **机器人改成盯「最快摸到家门口的那只」**，不再按「离家最近」排。第 166 关就是被这条坑的：
   慢吞吞的胶片大怪把机器人钉在原地，它召出来的小跟班排着队溜进家门。
4. 计划里说 `levels.ts` 一个字不改，实际改了**八个章节的简介文案**（`desc`）——
   那几句还在讲「摆颜料罐、架炮台」，跟 1.2 对不上。波次 / 怪表 / 预算一个数没动。

## 六、四种模式都能打到结算

| 模式 | 胜负条件 | 怎么验的 |
| --- | --- | --- |
| `campaign` | 清完本关全部波次即胜；元气罐被抱光即负，星级按剩几罐算 | `arena.test.ts` 188 关全跑机器人都守得住；干等一定输 |
| `endless` | 没有终点，元气被抱光为止，成绩 = 挡下的波数 | 同上 + 冒烟里真打到第 6 波再撒手收工 |
| `coop` | 两人共守，挡满 6 波即胜 | 无头跑通 + 冒烟里键盘双人打到「一起守住啦」 |
| `versus` | 两人各守一半，先被抱光元气的那边输，打满 6 波按剩下的元气分胜负 | 无头跑通（含「一边摆烂就一定输」）+ 冒烟真打到「星星这边守住啦」 |

四种都真能结算，所以 `meta.modes` 四种全留。
