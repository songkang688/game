# 1.2 第 14 步 · B 档 · `sky-squad`「飞机小队」升级计划

窗口 3 · 格号 14-B。规格原文见 `docs/plan-1.2-step14-B-sky-squad.md`。
工作基线 `origin/game-1.2-window3`,只往这条线推。只改 `src/games/sky-squad/**`。

本款是**纸飞机 / 棉花糖弹的卡通空中冒险**,不是战争:
没有军机写实、没有爆炸伤害、没有坠毁死亡。被碰到是打转 + 短无敌 + 掉一级火力。

## 一、现状审查(规格第三节逐条)

| # | 问题 | 1.1 的事实 |
| --- | --- | --- |
| 1 | `bullets.ts` 是不是数据驱动?能不能用一段 JSON 描述一个图案? | 半是。`PatternSpec` 已经是纯数据(弹型 / 速度 / 半径 / 间隔 / 张角 / 旋转 / 缺口 / 预警 / 延迟),`buildVolley` 是纯函数。但字段名是内部口径(`kind` / `spread` / `interval`),**没有**规格第四节要求的 `{ pattern, count, speed, delay, arc }` 那层声明式外壳,也没有 `aimed`,更没有「一段 JSON 直接喂进去」的入口 —— 现在必须先手写 `makeSpec("fan", {...})`。 |
| 2 | 判定盒是不是比飞机图形小?多大? | 是。`PLAYER_HIT_R = 9`,机身画出来是 72×64(翅膀椭圆 ±22、机身圆角矩形 22×42、尾焰再往下 12),判定圆直径 18 只有可见宽度的 **25%**、面积不到 **6%**。判定点画了,但只是一个 `r=4.5` 的半透明白点,弹幕一密就看不见。 |
| 3 | 敌机 / boss 是脚本化时间线还是硬编码在渲染里? | 脚本化。`PhaseSpec[]` 挂在 `BOSSES` 数据表上,`stepBoss` 只按 `nextVolley` 时刻表发弹,渲染不参与决策。缺的是**阶段切换的预告动作**:现在只有 1.2 秒静默 + 一句话,没有看得见的蓄力动作。 |
| 4 | `coop` / `twoPlayer` 是不是真能两人同时飞? | **一半是假的**。`createSortie({ players: 2 })` 确实同屏两机、两套键位互不串,`coop` 有入口;但 `meta.modes` 里的 `twoPlayer` **首页点不进去** —— 模式条上只有「无尽波次」和「双人合作」两个按钮。而且 `coop` 只是「两个人各打各的」,没有任何**配合价值**。 |
| 5 | 无尽是随机拼段还是纯加速? | 纯加速。`waveSpec(w)` 就是 `foes = 3 + 0.8w`、`speed = 1 + 0.05w`、`fireGap = 2.2 - 0.06w` 三条线性曲线加一个 8 元素道具循环,没有段落概念,飞到第 20 波和第 3 波长得一模一样。 |
| 6 | 弹幕多会不会掉帧?有没有对象池? | 没有池。`enemyBullets = enemyBullets.concat(...)`、`stepBullets` 每帧 `{...b}` 重建整个数组、`myShots` / `puffs` / `gliders` 全靠 `filter` 重建。一帧下来分配上百个对象,全交给 GC。 |

## 二、这一版要做的事

1. **弹幕语法**:新增 `PatternDecl = { pattern, count, speed, delay, arc, ... }` 声明层 + `compileDecl` / `expandDecl` 纯函数,能直接吃 `JSON.parse` 出来的对象;基础图案从 6 种加到 **8 种**(补 `aimed` 锁定弹与 `cross` 十字弹),boss 每阶段用 2~3 套组合。
2. **判定盒可视化**:判定核心画成「白环 + 亮心」,默认显示、可关;新增擦弹判定(`GRAZE_R`),擦过给「好险!」+ 擦弹计数。
3. **火力成长**:四条升级线(散射 / 追踪 / 穿透 / 僚机)各自有上限,关内拾取升级;被碰到掉一级,不是直接结束。
4. **boss 时间线**:三阶段保留,阶段切换加**预告动作**(蓄力 + 倒数 + 停火);「每一帧都存在可行走位」的模拟断言覆盖全部 24 个阶段。
5. **无尽「云海远征」**:段落表 + 拼接器 + 难度曲线,`expeditionPlan(seed, n)` 可复现;成绩仍走 `save.recordEndlessBest("sky-squad", n)`。
6. **对象池**:子弹 / 弹壳粒子 / 拾取物全部走池,「1000 次生成回收后池不膨胀」写成用例。
7. **模式矩阵**:`coop` 补真正的配合价值(两机靠近合体成「彩虹合流波」),`twoPlayer` 补真入口(同屏两机各记各的分,友好比拼)。四种模式全保留。
8. **手机 360px**:拖动时飞机在手指上方 40px(默认开、可关);HUD 一行显示,字号 ≥ 14px。
9. **平台接线**:`openCampaignLevel(n)` / `initialLevel` / `?level=`;Skip 继续走 188 框架的 `requestSkip`。
10. **收尾**:CSS 类名统一 `sks-` 前缀、局部 `<style>`;`destroy` 清 rAF / 定时器 / 监听 / 朗读 / 状态;新增 ≥ 20 个用例;前 99 关数据不改。

## 三、不做的事

- 不做真 3D,保持 2D 纵版(弹幕必须精确可读),只加云层视差。
- 不引入任何依赖,不自建 `AudioContext` / `setInterval`,音效只走 `api.play`。
- 不改 `src/styles.css`,不碰窗口 1 的平台文件,不碰 `shoot-range` / `tank-battle`。
- 前 99 关的编队 / 弹幕 / 道具数据一个字节都不动。
