## 二、要做的事

1. **六档 AI**（`ai.ts`）：`novice | easy | normal | smart | master | hell`。菜鸟 0 层随机 + 30% 挡冲四；地狱 = 迭代加深 + Zobrist 置换表 + 禁手抓杀，限时 350ms、至少 4 层，思考延时 ≥ 200ms。中间四档沿用现有实现与中文名。
2. **规则纯函数**（新 `rules.ts`）：棋谱字符串解析、活三 / 眠三 / 活四 / 冲四 / 三三 / 四四 / 长连 / 五连优先判定、白方「指出禁手」8 秒申告状态机。
3. **解局求解器**（新 `solve.ts`）：与 1.1 测试同语义的强制胜搜索 + **首手解集枚举** + 主变着法，带置换表。
4. **第 100–188 题换成真解局**（`puzzles.ts`）：89 道全新、互不对称的残局，每题带 `solutionKind`（唯一胜点 / 四手杀 / 五手杀 / 抓禁 / 弃子引杀）与完整 `solutions` 解集。**前 99 题一个字节都不动**（1.1 的坐标指纹测试盯着）。
5. **对局状态机**（新 `session.ts`）：落子确认、提示限次与「只给区域」、连胜阶梯、`level → AI 档`映射、`initialLevel` 解析、旧 key 迁移。
6. **UI 重排**（`view.ts` + `index.ts`）：接入 `mountLevelGame`（188 关号 / 星级 / 攻略 / 跳关全走框架），自由对战 6 档 + 双人同屏，连胜挑战写 `save.recordEndlessBest`。保持 2D。
7. **测试 ≥ 40 个新用例**，只增不减。

## 三、真·无尽为什么不做

五子棋一局的长度由棋盘决定，15×15 下满就是 225 手，没有「同一盘越来越快」的维度；硬加计时或缩盘会改掉五子棋本身的规则。用**连胜挑战**替代：从菜鸟起，赢一盘升一档，输一盘结束，最高连胜写进平台的 `endlessBest`。

## 四、存档与兼容

- 星级：旧 key `yiduo.gomoku.campaign.v2`（长度 99/188 的数组）**读一次**，逐关取最大值并进 `yiduo-yixing.l99.gomoku`，随后删掉旧 key；老玩家一颗星都不会丢。
- 跳关：`yiduo-yixing.l99skip.gomoku`（0 基），由框架写。
- 连胜：`save.recordEndlessBest("gomoku", n)`，不新增任何 localStorage key。
