## 一、现状审查(逐条交底,读代码读出来的,不是猜的)

### 1. 两位角色能力有区别吗?还是换皮?

**半个换皮。** 有区别,但都不是「专属能力」,只是同一套动作的两组数值:

- 王子:起跳 `PRINCE_JUMP_V = 660`,近战 `MELEE_*`(伤害 3、够 54px、CD 0.32s);
- 公主:起跳 `PRINCESS_JUMP_V = 610` + 空中再蹬一下 `PRINCESS_DOUBLE_V = 520`,远程 `SHOT_*`(伤害 2、飞 430、自动瞄准 520px)。

克制关系(`canDamage`)确实做了:铠甲怪弹开星星、幽灵穿透剑。但这是**怪的属性**,不是角色能力。
两个人谁都不会做另一个人做不到的**地形动作**——`levels.ts` 的注释写得很明白:
「主路上任何断口和台阶都按王子的跳跃极限来卡」,所以公主的二段跳**从来不是必需的**,
188 关里一处「只有公主过得去」的地方都没有。**没有推重物,没有滑翔,没有任何一关必须交替。**

### 2. 关卡阅读性:孩子第一次看这一屏,能看懂「往哪走、哪里危险、哪里是奖励」吗?三个反例

**看不懂。** 三个实打实的反例:

1. **奖励和危险共用同一个符号。** 宝石是 `💎`,公主的星星弹是 `⭐`,首领护甲提示也是 `⭐`,
   炮台的弹是 `🔴`。屏幕上同时飘着「捡了加分的」和「碰到掉心的」,靠的都是小小的发光图标,
   形状没有一点区别——第一次玩的孩子只能靠挨一下才知道哪个不能碰。
2. **「可踩」和「地面」几乎同色。** 平台是 `#FBEAD5`(实心)/ `#F3D9E6`(浮动),
   地面上表面 `pal.ground` 在樱花城堡是 `#F0A9C2`——同一片粉。而且**平台没有描边**,
   只有 3.5px 的 `pal.deco` 顶条,一旦背景也偏粉(第一章、第五章)就糊成一片。
3. **危险按章节调色板走,同一含义每章长得不一样。** 尖刺写死 `#B85C55`,断口是「背景色的缺口」,
   火球是 `🔴`,飞行怪是 `🦇/👻` 原色 emoji——四种「碰到掉心」的东西四个样子。
   反过来,熔岩章的地面 `#EE9E6E` 比尖刺的暗红还扎眼,**安全的地方比危险的地方更像危险**。

另外出口只有一颗 `🔒 / 🚪`,门开了靠一行 toast 提示,画面上没有任何指向性。

### 3. 有没有引导性视觉语言?

**没有。** 全款没有一处「危险统一 X 色、可踩统一 Y 边、奖励统一发光」的约定,
`PALETTES` 是**按章节**分的七套粉彩,同一个含义在不同章里是不同颜色。
`guide.ts` 里只有文字攻略,没有任何图例。

### 4. `endless` 现在是什么?

`buildEndless(round)`:和战役共用同一个 `walk()` 随机撒点器,换个种子、把长度和密度按 `round` 拉一拉,
每第 5 段(`r % 5 === 4`)塞一场弱化首领。**没有模板、没有必过窗口校验**,
可过性完全靠 `MIN_GAP / MAX_GAP / MAX_PLATFORM_RISE` 这几条几何红线兜底 + 事后 `trimSpikes / trimEnemies` 擦屁股。
成绩记的是 `endlessScore(kills, gems, meters)` 折出来的**分数**,不是层数。

### 5. 检查点密度?失败重来挫败感?

**一个检查点都没有。** 掉进断口的处理是 `safeGroundX(h.x - 30)`:就地往回找一块站得稳的地面放回去,扣一颗心。
心掉光 → `status = "lost"` → 188 框架给「再试本关」→ **整关从头**。
一关最长 3300px、限时 2.6 倍标准用时,倒在最后一段就得从起跑区重跑,收集的宝石也全没了。挫败感是实打实的。

### 6. 双人时摄像机与掉队?

`camX = clamp(两人 x 的平均值 - 半屏)`。**不缩放、不夹人、不拉回**:一个人往前冲、另一个人卡在后面,
落后那位直接被挤出屏幕左边,玩家看不见自己的人。掉队没有任何处理。
