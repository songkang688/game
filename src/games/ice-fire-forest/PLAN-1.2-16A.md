## 一、开工前的现状审查（规格第三节六问）

### 1. 两个角色的属性差异有没有纯函数判定？

**有。** `logic.ts` 的 `canEnter(level, pos, hero, power, light, partnerOnPad)` 返回
`ENTER_OK / ENTER_SOLID / ENTER_HURT` 三态：

- `TILE.ICE_WATER`（冰水潭）→ 凛凛 `OK`、焰焰 `HURT`；
- `TILE.LAVA`（岩浆池）→ 焰焰 `OK`、凛凛 `HURT`；
- `TILE.SLIME`（绿黏液）→ 两个人都 `HURT`；
- 两扇门也各认各的主人（`DOOR_ICE` 对焰焰是 `SOLID`，不是 `HURT`）。

`logic.test.ts` 的「冰水与岩浆」一组用例已经把这四条钉住了。

### 2. 平台手感常量与单测？

**基本没有，而且这一款根本不是侧视平台跳跃。**
世界是一张**俯视字符网格**，两人按格子走（`moveHero` 一次一格），所以：

- 重力 / 跳跃初速 / 土狼时间 / 跳跃缓冲 —— **四个都不存在**；
- 现有的「手感」只有四个埋在 `index.ts` 里、没有任何单测的裸数字：
  `MOVE_MS = 145`（按住方向键的走格间隔）、`BUMP_MS = 220`（撞墙硬直）、
  `HURT_MS = 520`（碰危险格硬直）、`HIGH_FIVE_MS = 2600`（击掌冷却）；
- `logic.ts` 里另有 `MOVE_SECONDS = 0.14`，但它只用来折算评星线，和实时手感不是一回事；
- 位移推进在 `advanceView(hero, dt)` 里按 `dt` 线性插值，**帧率无关性从来没测过**。

### 3. 合作点有几种？后段是不是只是变长？

屏障共 10 种（`BarrierType`）：`open / split / plateIce / plateFire / lever / seesaw /
belt / lift / beamPlate / beamMirror`。其中真正要两人配合的只有四类：

1. **踏板**：有人压着才通电，人一走开闸门立刻关；
2. **拉杆 / 跷跷门**：此开彼关，得商量谁先过；
3. **托举高坎**：同伴踩住托举点才上得去；
4. **光路**：人站在光路上会把光挡断。

**没有**双人按钮、顶举（主动把同伴举过去）、绳索、可推箱、传送门、双人电梯。
后段不是「只是变长」——第 5 章起会混编机关、加绿黏液、段数 3 → 4，
但**机关种类到第 6 章就见底了**，第 7、8 章是排列组合而不是新东西。

### 4. 单人怎么玩？

**已经能玩**：`index.ts` 有 `solo` 开关、`Tab` 换人、HUD 上一颗「🔁 换人」按钮，
另一角色原地待命（`held.clear()` 防止留下按住不放的幽灵）。
`smoke.test.ts` 拿 24 关样本证明过「一个人靠 Tab 也能通关」。

不足两处：换人按钮混在 HUD 那一排里、**不在中间上方**；
窄屏（≤ 420px）两套虚拟方向键被压到 **36px，够不到 44px 热区红线**。

### 5. 摄像机怎么处理两人分散？

**没有摄像机。** `layout()` 把格子边长压到「整张图一次放得下」为止，
所以两人再怎么分散都在屏幕里。代价是 17×11 的图在 360px 上格子只剩 ~14px，看不清。

### 6. 掉池后是整关重来还是回检查点？

**两者都不是，因为现在压根掉不进去**：`moveHero` 对危险格返回 `hurt`，
人被弹回原地、掉一颗心；三颗心掉完 `settleLose("hearts")` —— 那才是**整关重来**。
**没有检查点。**

## 二、这一版要做什么（以及为什么这么做）

### 硬约束先摆出来

- **前 99 关关卡数据不许改**；
- `solve.test.ts` 会对全部 188 关逐关跑 BFS，要求**首次种子就拼得出来、无兜底、宝石全可达、
  整局模拟不超时**。任何会改变既有网格的东西都可能让这一串证明塌掉。

结论：**新机关一律做成「运行时叠加的增量能力」，一个字符都不写进关卡网格。**
这不是取巧，是这个仓库既有的做法 —— `useElementPower`（凛凛冻岩浆、焰焰烤冰水）
本来就是「只把关卡变简单、不进 BFS」的增量能力。
只要每一件新机关都**只增不减**（不拿走任何原本走得通的选择），
「188 关全部可解」的旧证明就自动继续成立，一行都不用重跑。

### 1. 手感常量化（新文件 `feel.ts`）

把四个裸数字抽成带单位、带注释、带单测的常量表 `FEEL`，并补上格子游戏里
**真正说得通**的那套「平台手感」：

| 项 | 值 | 在这一款里是什么意思 |
| --- | --- | --- |
| `GRAVITY` | 2000 px/s² | 顶举把同伴抛出去的抛物线、小云朵飘回检查点的落势 |
| `JUMP_VELOCITY` | 600 px/s | 同上，`跳跃时长 = 2v/g`、`跳跃高度 = v²/2g` |
| `COYOTE_MS` | 90 | **同伴从托举点上走开之后，还有 90ms 能把这一步爬完** |
| `JUMP_BUFFER_MS` | 120 | 上一步还没走完就按下的方向，记住 120ms，一到点立刻兑现 |
| `EDGE_SNAP_CELLS` | 0.22 | 插值走到离目标格 0.22 格以内直接吸附，不留亚像素残差 |
| `STEP_MS` | 145 | 按住方向键的走格间隔（原 `MOVE_MS`） |

帧率无关：位移改成**定步长累加器**（`FIXED_STEP_MS = 1000/240`），
用例证明 30fps 与 60fps 走同样时长的位移差 **< 2%**。

### 2. 六种合作机关（新文件 `coop.ts`）

每一种都是纯函数，每一种都「只增不减」：

| 机关 | 规则 | 为什么只增不减 |
| --- | --- | --- |
| **双人按钮** | 两人各踩一个同组按钮 → 那一组**记忆门**永久闩开 | 记忆门原本是石墙，闩开只是多一条路 |
| **顶举** | 相邻时把同伴举过 1 格障碍，落到 2 格外 | 多一种过法，原来的路一条没少 |
| **绳索拉伸** | 相距 2–4 格且中间隔着危险格时，把同伴拉到身边 | 同上 |
| **可推箱** | 水潭 / 岩浆上的浮桥木箱，两人都踩得住，也推得动 | 木箱本身可走，占的又是原本危险的格子 |
| **传送门配对** | 两人分别站上一对传送门、按同行键 → 交换位置 | 要显式按键才生效，站上去不会被硬拽走 |
| **双人电梯** | 两人同时站上升降台的两格，电梯才沿竖井升降 | 竖井原本是石墙，电梯是凭空多出来的通道 |

机关套件由 `buildCoopKit(level, parsed)` 纯函数确定性地摆放，
**只在第 100 关及以后出现**（第 1–99 关连运行时都不叠加，前 99 关一个字都没动）。

### 3. 检查点（新文件 `checkpoint.ts`）

- 每关 **2–3 个**检查点，按横向分段均匀摆在保底通路上；
- 掉池不再是「弹回来掉一颗心」，而是**真的踩进去 → 变成小云朵飘回最近检查点**；
- 飘回**只挪人，不重置机关**：拉杆开关、闩开的记忆门、捡过的宝石、推过的箱子全保留；
- 心只影响星数，**掉完也不再判负、更不会整关重来**（超时才结束）。

### 4. 摄像机（新文件 `camera.ts`）

两人分散先拉远，缩放有下限 `MIN_SCALE`；超出下限不硬拽，改在屏幕边缘给
「另一位在这边」的箭头。纯函数 `computeCamera`。

### 5. 单人模式（新文件 `solo.ts`）

把原来散在 `index.ts` 里的 `solo` / `active` 抽成纯状态机：
`Tab` 或触屏按钮换人、两套键位在单人模式下都开当前这位、另一角色原地不动、
换人时两套 held 全清。触屏换人按钮**固定在中间上方**，热区 ≥ 44px。

### 6. 其余

- 虚拟按键热区拉到 **44px**（原来窄屏 36px）；
- 冰池 / 火池 **形状 + 纹理**区分（冰是圆角池 + 横波纹 + 六角雪花；火是尖角池 + 气泡）；
- 机关联动画**光路提示**（哪个开关连哪扇门）；
- `prefers-reduced-motion` 关抖动与闪烁；
- `openCampaignLevel(n)` / `initialLevel` / `?level=` 直达；Skip 走 188 框架自带的 `requestSkip`；
- **无尽不做**：本款过关条件是「两人同时站上各自的门」，
  关卡是一次性解开的机关谜题，拼成无限长只会变成同一道题重复出现，
  既没有成长曲线也没有终点，不适合无限拼接。`modes` 保持 `campaign / coop / twoPlayer`。

### 3.2 和计划的出入

计划里写的都做到了，另外有五处是施工时才补上或改掉的：

1. **可推箱的规则被推翻重写过一次。**
   计划写的是「推得动就推」。真写出来才发现要分三件事算：木箱滑到哪、
   **骑在木箱上的同伴**跟不跟着走、**推的人**自己站不站得住木箱腾出来的那一格。
   最后落成 `planCratePush`，返回三个落点。由此长出这一款最像样的一次合作 ——
   **摆渡**：焰焰坐在木箱上，凛凛趟在冰水里推，两个人一起过河。
   推的人站不住就留在岸上（木箱照样漂走），推不动就干脆爬上去。

2. **心掉光不再判负。**
   计划只说「不许整关重来」，没说心怎么办。实现时把 `settleLose` 收窄成只认超时：
   踩空 → 小云朵飘回检查点，心只影响星数。一个卡在半路的孩子不会被打回起点。

3. **补了 `Esc` 暂停。**
   规格第二节的键位约定里有 `Esc`，1.1 的这一款没接。现在按一下停住（两套 held
   与缓冲一起清空，恢复时不会突然兑现暂停前按住的那一下），再按一下接着玩。

4. **补了背景视差。**
   规格第六节「可加背景视差」。三层远景按 0.18 / 0.34 / 0.55 跟着镜头挪，
   纯装饰不碰判定 —— 没有它，拉远的时候画面看着像卡住了。

5. **`solo.ts` 里的 `clearedHolds()` 被删掉了。**
   计划阶段留的一个空壳（永远返回 `[]`），运行时改成直接 `held.clear()`，
   一处都没用上，留着只会误导人。
