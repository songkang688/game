# 找不同 `find-diff` · 1.2 升级计划（C 档 · 第 25 步）

规格原文：`docs/plan-1.2-step25-C-find-diff.md`。本文件是动代码前的现状审查与施工计划，
落地后再回填结果。只改 `src/games/find-diff/**`，`level99.ts` / `save.ts` 只读只调用。

## 一、开工基线（认下来的硬约束）

- `category: "edu"`、`levels: 188`、10 章（前 6 章 99 关 + 1.1 追加 4 章 89 关）。
- `LEGACY_CHAPTER_COUNT = 6`：**前 99 关的章节切分、seed、生成参数逐字不动**。
  证明方式：把 `LEVELS[0..98]` 与 `buildBoards(0..98)` 的完整 JSON 串成一条文本做 SHA-256，
  升级前后必须是同一串（升级前实测 `2c368b63559805942e31d6884f8a9a3a4600d927baf665f18cf00cbf7bbfa621`）。
- 只用 emoji 拼场景，不引入任何图片资源或外部素材；保持 2D。
- CSS 类名一律 `fdf-` 前缀。

## 二、现状审查（逐条）

1. **差异点怎么生成、有几种类型**
   真正的生成器在 `levels.ts`，不在 `scene.ts`：`buildBoard()`（经典 / 旋转）、
   `buildTripleBoard()`（三图）、`buildMirrorBoard()`（镜像）、`buildRushBoards()`（连环）。
   四条路子都是「先按主题池铺一张 base，再挑 diffs 个格子换掉图案」。
   **差异类型只有一种：换 emoji**（`lookalike` 时优先换成 `LOOKALIKE` 表里的双胞胎）。
   挪位置 / 变大小 / 变朝向 / 加减一个 / 变底色一个都没有。
   `scene.ts` 是 1.0 时代手画的 5 幅 SVG 场景（每幅 5 个圆形热区），**现在的玩法代码根本没引用它**，
   属于遗留文件；它的单测保留不动，1.2 的新场景层另起一份。

2. **公平性**
   差异点是格子下标，天然落在棋盘内，不会跑到重叠区外；`Set` / `shuffled().slice()` 保证
   两个差异点不会挤在同一格。但没有任何一处代码把「答案唯一」当成断言跑过全量 188 关，
   目前只有抽样测试。三图关的格子被压到 30px（`fd-grid-mini`），字号最低会 clamp 到 14px，
   低于「双胞胎在小屏上仍可辨、字号 ≥ 22px」和「热区 ≥ 44px」的红线。

3. **点击容差与惩罚**
   容差 = 0：格子按钮多大热区就多大，格与格之间 4px 的缝隙点下去什么都不算。
   惩罚很重：`misses > cfg.maxMiss` 直接 `ctx.lose()` —— **点错就失败**，
   而后段章节 `maxMiss` 低到 3。这条 1.2 明令禁止。

4. **三图关（第 7 章）**
   判定确实是「跟上面两张都不同」：答案格 `changed ≠ base = second`，
   干扰格 `second ≠ base` 而 `changed = base`，两个集合由 `shuffled` 切片保证不相交，
   所以不存在「两张都变了导致答案不唯一」。

5. **镜像关（第 9 章）**
   `changed[j] = base[mirrorIndex(j, cols)]`，点击用的就是下图自己的下标 `j`，
   `mirrorIndex` 是对合（照两次回到原位），换算与命中都是对的。

6. **连环挑战（第 10 章）**
   `timeLeft` 是关卡闭包里的一个数，退出关卡 `destroy()` 后全部清零；
   再进来是从第 1 轮、满倒计时重新开始，**没有中途续计时**。

7. **提示 / 放大镜 / 大棋盘**
   有一个「🔎 放大镜提示」按钮，但它既不放大也不分级，直接把答案格闪三下——一步泄题；
   次数 = 轮数（绝大多数关只有 1 次）。没有任何缩放 / 平移能力，
   5×5 棋盘在 360px 上每格 44px、三图关 30px，双胞胎图案很难分辨。

8. **`guide.ts` 泄题？**
   没有泄题：全篇只讲扫描路线与检查顺序，一个坐标都没写。
   但第 1 章那句「点错会扣次数」在 1.2 之后就是错的，要一起改。

## 三、1.2 施工清单

| 项 | 做法 |
| --- | --- |
| 场景层 `scene12.ts` | 新增 `CellView`（emoji / 缩放 / 左右翻 / 底色 / 个数 / 位移）与 `buildScene(level, round)`。前 99 关只是把 `buildBoards()` 的 emoji 原样包一层默认外观，逐字不变；第 100 关起在既有差异格上分派新的差异类型。 |
| `validateScene()` | 纯函数，五条硬规则：①数量 ②可视区内 ③任意两点格距 ≥ 1 ④答案唯一（逐格比对 `CellView`，不存在未标记却不同的格）⑤镜像/旋转换算可逆。测试里跑遍 188 关全量 + 无尽前 40 轮。 |
| 命中容差 | `hitRadius(cellW) = max(cellW * 0.55, 22)`；`pickNearest()` 在半径内取最近的格子，相邻两点同时命中取更近的那个。 |
| 温和惩罚 | 删掉 `maxMiss` 判负这条路。点错只进 0.6 秒冷却 + 涟漪；1 秒内 ≥ 5 次错点判为乱扫，冷却翻倍到 1.2 秒。**任何情况下都不会因为点错而失败。** |
| 缩放 | 1×–2.5×，双指捏合 / 滚轮 / 滑块三条路，两图共用一个 `transform`（联动缩放），可拖动平移且被夹在边界内。 |
| 提示经济 | 两级：第一下圈出 3×3 区域，第二下才精确指出；每关次数按章节递减（`hintBudget`），用完不阻塞过关。 |
| 差异类型 | 换 emoji / 挪位置 / 变大小 / 变朝向 / 加减一个 / 变底色，按章节配菜单，后段混合，写分布断言。 |
| 进度可视 | 找到的点在上下两图同时打圈，计数「3/5」；未找到的绝不提前显形。 |
| 无尽 | 「找不同马拉松」每轮 3 个差异点，网格、双胞胎比例、可用时间随轮次单调变难；成绩走 `save.recordEndlessBest("find-diff", n)`。 |
| 平台接线 | `initialLevel` / `?level=` 直开第 N 关：`level99.ts` 没开口子且只读，所以照 `pinyin-train` 的老办法——在自己的 `runtime.ts` 里替玩家点一下地图上的格子，点不到就安静停在地图。 |
| 文案 | `meta.blurb` 改成与事实一致（十大主题 188 关 + 无尽），删掉「归 B 改」注释，`meta.modes` 加 `"endless"`；`guide.ts` 里「点错会扣次数」改掉，补无尽与缩放的方法论（仍不泄题）。 |
