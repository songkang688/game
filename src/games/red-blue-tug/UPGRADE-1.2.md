# 1.2 第 23 步 · C 档 —— `red-blue-tug`「红蓝拔河」升级计划

对着 `docs/plan-1.2-step23-C-red-blue-tug.md` 写。只动 `src/games/red-blue-tug/**`,
不碰 `red-blue-race` / `red-blue-tap`,CSS 一律 `rbg-` 前缀,不引入任何依赖,保持 2D。

## 一、现状审查(1.1 的事实,逐条回答提示词第三节)

1. **绳子位置模型**:`pos` 是 -100..100 的连续量,但驱动它的是离散事件 ——
   玩家每点一次 `pull()` 加一个固定量 `pullPower`(再乘体力 / 号子 / 补给系数),
   小电脑每帧按 `aiRate * dt` 匀速拉。没有力量条,也没有蓄力与突然发力。
2. **体力**:1.1 加过,但只在第 100 关之后的「沙丘角力」「巅峰绳王」两章
   (`cfg.stamina`)。规则是「点一下 -1、见底力气 ×0.5、按 `staminaRegen` 回气」。
   **前 99 关没有体力,狂点就是最优解。**
3. **campaign 188 关**:全部是打小电脑。AI 只有一条线性拉力 `aiRate`,
   外加末章的读招系数 `aiAdapt`(领先时它拉得更凶)。**没有档位这回事。**
4. **节奏点**:只有「号子」`chantMs` —— 判的是**两次点击的间隔**(±150ms),
   跟绳子上的位置无关;加油星是随机位置的 DOM 按钮,点掉就 +12,和时机无关。
5. **胜负**:位置到底,`pos` 先到 ±100 的一方赢,不限时。
6. **触屏两侧**:普通关只有中间一个按钮(72px,窄屏降到 64px),
   节奏关才是左右两个(左手 / 右手,还是同一个人的)。对手是电脑,
   谈不上「两侧对称」。

## 二、1.2 要落地的东西

| 项 | 做法 |
| --- | --- |
| **力量模型** | 新建 `tuning.ts` + `force.ts`:体力**按住消耗、松开恢复**;体力见底进「脱力」状态,力量骤降到三成,要回到 30% 才缓得过来;松手 ≥ `CHARGE_MS` 再按下有一段「突然发力」加成。纯函数 `stepSide` 定长子步(≤1/120 秒)推进,帧率无关。 |
| **狂按不是最优** | `duel.ts` 里三种可对比的操作策略:一直按住 / 高频狂按 / 有节奏发力。固定时长的产出与正面对局都由用例断言:**有节奏 > 狂按 > 一直按住**。 |
| **节奏点** | 绳子上随机冒「加油点」,**双方共用同一串时刻表**(对称);它经过中线时按下(判定窗口 ±120ms)给一次额外拉力。为了不让狂按白捡,要求这一下是**松手 ≥ 250ms 之后的发力**。 |
| **反拉** | 落后一方被拉到 ≥80% 位置时开一个 2 秒「拼一把」窗口,拉力 +15%;有冷却、不叠加、可开关,默认开。 |
| **AI 四档** | `ai.ts`:轻松 / 稳扎 / 高手 / 绳王,四档差在**体力管理**(什么时候松手换气)与**节奏点命中率**,外加一点基础力量。固定 seed 跑对局,用例断言四档强度单调。 |
| **无尽「拉不完的绳」** | 一局接一局,AI 档位与力量随连胜上涨;成绩 `save.recordEndlessBest("red-blue-tug", streak)`。 |
| **versus 本命** | 同屏双人:左右两侧各一个 ≥72px 大按钮 + 两套键位(朵朵 F/A,星星 J/→);也可以选四档小电脑。 |

## 三、188 关怎么接新模型

- **前 99 关的关卡数据一个字不改**(`levels.ts` 只加可选字段的读法,不改 `buildLevel`)。
- 老字段在新模型里换一种读法,不改数值:`aiRate` → 对手基础力量,
  `pullPower` → 自己的基础力量,`star` → 加油点更密,`chantMs` → 加油点节拍更急,
  `stamina/staminaRegen` → 体力上限与回气速度,`supply` → 补给,
  `aiAdapt` → 读招(领先时对手更凶),`redlight` → 红灯期间拉绳打滑。
- `rhythm` 关保留左右手交替:换手才有满力,连按同一只手只有半力。
- 新增 `campaign12` 抽样用例:188 关按新模型跑,有节奏发力全过,狂按拿不下后段。

## 四、视觉 · 手感 · 平台

- 绳子按当前拉力做张力形变与抖动,`prefers-reduced-motion` 关抖动、只留形变;
  体力条颜色 + 条纹双通道,见底时角色喘气(可爱,不难受)。
- 胜负是「另一边坐到软垫上,大家一起笑」,无伤害、失败只给方法。
- `runtime.ts`:`createDisposer`(rAF / 定时器 / 监听统一登记,`destroy` 归零)、
  `sideLayout`(360px 下两侧按钮 ≥72px、中间留隔离带、字号 ≥14px)、
  `keySideOf`(两套键位)、`resolveInitialLevel`(`?level=` 直开第 N 关)。

## 五、实测结论(1.2 收尾时补记)

- `mountLevelGame` 这个共用框架**没有 `initialLevel` 这个入口**,也没有对外的
  「直接开第 N 关」方法;要接就得改 `src/games/level99.ts`,那不是本档能碰的文件。
  所以 `runtime.ts` 里把 `resolveInitialLevel` / `parseLevelParam` 按契约写好并写了用例,
  等框架开口子就能接上;**跳关**是框架自带的(壳层注册 `requestSkip` 才显示),本档一个字没动。
- 手感与接线在 jsdom 里逐条走过一遍:两侧按钮 160×76(360px 视口)、按住掉体力、
  松手回体力、一直按住会脱力、按「拉 0.9 秒 / 歇 0.56 秒」的节奏 11 秒拉赢第 1 关、
  节奏关连用同一只手会被提示、补给关掉 🧤 能抢、同屏双人 F/J 各拉各的、
  无尽赢一局再输会把连胜写进 `save.recordEndlessBest`、`destroy` 之后 window 上的监听归零。

## 六、测试
