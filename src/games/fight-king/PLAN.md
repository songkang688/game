# 窗口 2 · 10C —— 朵星格斗王 `fight-king` 精细化计划

对应规格：1.2 第 10 步 · C 档。只动 `src/games/fight-king/**`，CSS 一律 `fk-` 前缀。
**这一步是精细化，不是重做**：1.1 的八位角色、11 个招式槽、188 层格斗塔、五个模式全部续写，
不搬「连招对决」那一款的系统，也不建它的目录。

## 一、现状审查（读完 frames / rules / engine / ai / controls / levels / index 与 191 个既有用例后的实测结论）

| # | 规格点名的地方 | 实测结论 |
| --- | --- | --- |
| 1 | AI 几档？高档会不会吃投无限、会不会跳 | **3 档**（轻松 / 普通 / 高手），差别是反应延迟 26/15/7 帧 + 格挡概率 + 反击概率。**不会吃投无限**：`THROW_IMMUNE_PHASES` 给了硬直投技保护，投技又带 `knockdown`，起身有 6 帧无敌，实测贴身连按轻+重 1800 帧最多只摔中 2–3 次。**轻松档完全不会跳**：`planFor` 的起跳分支写着 `brain.level >= 1`，实测 lv0 在 12000 帧里 `up` 一次都没按过。 |
| 2 | 命中盒 / 受伤盒是固定矩形还是按帧给 | **都是固定矩形**。命中盒是 `Move.box` 一个框，整段 active 帧不变；受伤盒只有站 / 蹲两种高度（空中沿用站立），**出招时一点都不变**。后果：云云的云朵推伸出 150 单位打人，自己的受伤盒还是 25 半宽 —— 长手招是纯赚的，谁也不敢近身，这就是「隔空中」的手感来源。另有一处名实不符：追风踢 / 闪电步 / 糯米滚 / 墩墩撞的说明都写着「突进 / 撞过去」，**引擎里没有任何位移代码**，所以看着像原地挥空。 |
| 3 | 连段上限 6 与递减现在真生效吗 | 递减真生效（`COMBO_SCALES` + `scaledHitStun` 都接进了 `applyContact`）；**上限 6 是一句空话**。取消表 `light→[light,heavy,special,super] / heavy→[special,super] / special→[super]` 加上「同槽只用一次」，穷举八个角色的地面招，最长路径都只有 **5 段**：`5L > 2L > 5H > s1 > super`。`isComboCapped(6)` 这条闸这辈子没被触发过。 |
| 4 | 训练场存在吗？显示帧数与可取消吗 | 存在（`mode === "training"`），元气不掉、有一张全招式帧数表、有连段段数 / 能量 / 格挡槽 / 与对手距离。**缺三件事**：① 实时读数只写了「阶段名 + 第几帧」，没写当前招的 startup / active / recovery 三个数；② 完全没有「现在能取消成哪几招」；③ 陪练就是一个普通 AI，**没有站立 / 蹲防 / 随机反击这三种假人行为**。 |
| 5 | 188 层能打到吗？有 skip 与直开第 N 层吗 | 层数没问题：`CHAPTERS` 八章 24×4 + 23×4 = 188，`towerStage` 对越界做了 clamp，解锁走 `mountLevelGame` 框架。**skip 已经有了**（框架的 `attachSkip` 自己读 `getLevelExtras().requestSkip`）。**直开第 N 层完全没接**：`api.initialLevel`、`?level=`、对外的 `openCampaignLevel` 一个都没有。 |
| 6 | 窄屏摇杆会不会挡住元气条与连段计数 | 摇杆是画布**下方**的独立一行，不盖 HUD，这条没问题。但另外三件事不合格：① 触屏只有轻击 / 重击**两颗**按钮，没有必杀、没有防御；② 窄屏下 `.fk-padbtn` 高度约 40px，**不到 44px**；③ 连段计数画在画布 y=118，360px 宽时换算成 CSS 只有 47px，**正好被 60px 高的 HUD 压住**，手机上根本看不见连击数。倒计时 21px ≥ 16px、角色名有 ellipsis，这两条合格。 |
| 7 | meta 与实现一致吗 | `category: "party"`、`modes: ["campaign","versus","endless","twoPlayer"]`、`levels: 188` 都对得上实现。**blurb 落后**：只写了双人 / 人机 / 格斗塔，漏了无尽连胜和训练场；也没有 `platform` 字段（同期别的几款都填了 `"both"`）。 |

## 二、要做的事

1. **帧数据精细化**（`frames.ts`）
   - 新增 `advance`：突进招真的往前走（追风踢 / 闪电步 / 糯米滚 / 墩墩撞 / 展翅冲…），位移分摊在 startup 尾段与 active 帧上，说明与手感对齐。
   - 新增 `hurtExtend`：出招时受伤盒往前伸出去一截，长手招不再是白嫖 —— 谁伸手谁就得承担被戳到的风险。数值按 `box` 的实际长度给，长招伸得多、轻击几乎不伸。
   - 命中盒改成**按帧给**：`activeBoxAt(move, frame)` 让判定框在 active 段里随帧成长（第一帧最短、最后一帧最长），穿模与「擦过去也算中」同时变少。
2. **规矩精细化**（`rules.ts`）
   - 取消表补两条：`heavy → heavy`、`special → special`（仍旧单向、仍旧同槽只用一次），**让 6 段真的打得出来**，`5L > 2L > 5H > s1 > s2 > super` 就是可复现的那条；第 7 下必定撞上 `cappedOutcome`。
   - 受身与倒地无敌重做：受身窗口 8 帧不变，受身起身 18 帧、无受身 40 帧不变，但**起身无敌从 6 帧提到 12 帧**，并新增「被摔之后的投技保护帧」`THROW_PROTECT_FRAMES`，从根上封死投技循环。
   - 新增训练场用的纯函数：`frameReadout(move, frame)`（startup / active / recovery + 当前段 + 剩余帧）、`cancelTargets(char, move, used, hits)`（现在能取消成哪几招）。
3. **AI 加到 5 档**（`ai.ts`）：在现有三档之间插入两档，最终为
   `0 轻松 / 1 普通 / 2 会跳会投 / 3 会防反 / 4 高手`。
   - 2 档：跳跃与投技的权重明显抬起来（现在 lv0 根本不跳），中距离会跳进来压，贴身会找机会摔。
   - 3 档：多一套「确反」逻辑 —— 认准对方收招帧才动手，挡完立刻抓帧数差为正的招回敬。
   - 4 档：3 档的全部 + 最短反应延迟 + 会留能量放超必杀。**但不做地狱级深度**（那是新格斗那一款的定位）：保留 `AI_OPENING_MS` 反打窗口，每隔一段必定出现一个「什么都不做」的空档给孩子反打，格挡概率封顶 0.9 而不是 1。
   - 固定 seed 下高档对低档胜率显著更高，写成断言。
4. **训练场补全**（新 `training.ts` + `index.ts`）
   - 假人三选一：**站立 / 蹲防 / 随机反击**，纯函数产出 `InputFrame`，可单测。
   - 实时读数补上：当前招的 startup / active / recovery 三个数、正处在哪一段还剩几帧、**能不能取消 / 能取消成哪几招**、连段段数与本段累计削减、与陪练的净距离。
5. **平台接线**（新 `progress.ts` + `index.ts`）
   - `initialLevelOf(hint, search)`：`api.initialLevel` 优先，其次 `?level=`，1 基转 0 基、越界 clamp，给不出就返回 -1。
   - 导出 `openCampaignLevel(host, n)`：在已经挂好的 188 关地图上替玩家点开第 N 层，锁着就停在能玩的最远那一层。
   - 无尽成绩走 `save.recordEndlessBest("fight-king", n)`；老 key `yiduo-yixing.fight-king.endless` / `.streak` 若存在**只读一次**取最大值合并进去，不删（玩家自己导出的备份里还留着）。
6. **手感与画面**（`index.ts`，保持 2D 侧视，判定绝不改 3D）
   - 背景加一层视差（远山 / 近树各一层，跟着镜头平移）与前景轻粒子（花瓣飘落）；`prefers-reduced-motion` 下两者都停。
   - 命中顿帧收进 4–8 帧区间（减弱动效下为 0）；防御成功加金属亮边 + `api.play("tap")`；破防换 `oops` 并闪一层明显不同的颜色。
   - 眩晕 / 倒地 / 起身三种姿态各画各的，不共用。
   - 超必杀演出 ≤ 1.2 秒（72 帧），连点任意键可跳过。
7. **手机 360px**（`index.ts` + CSS 末尾）
   - 触屏四钮：轻 / 重 / 必杀 / 防御，热区 ≥ 44px 且互不重叠。
   - 连段计数从画布 y=118 挪到 HUD 下方的独立一行 DOM，永远不会被元气条压住。
   - 角色名过长自动缩写（保留前两个字 + 省略号），HUD 不会被顶出屏幕。
8. **测试 ≥ 18 个新用例**（新 `training.test.ts` `progress.test.ts` + 扩 `rules.test.ts` `ai.test.ts` `engine.test.ts`），只增不减。

## 三、明确不做的事

- **不改 3D**。判定继续是 2D 侧视的矩形重叠：帧数据的可预测性是这一款的立身之本，加一维就全毁了。
- **不做地狱级 AI**、不做取消路线树、不做输入指令（半圆下 + 拳那一套）。这些是「连招对决」那一款的活，本款最高档做到「稳定压制高手档、但留反打窗口」就收手。
- **不碰别人的目录**：新格斗那一款的目录不创建、不修改；角色名与招式名也不跟它撞。

## 四、分级红线

无血、无伤、无死亡描写；招式全是花瓣、星光、云朵、豆芽；条子写「元气」，掉光只是换人休息。
失败一律只鼓励（「元气用完啦，休息一下再来！」）。文案与注释不出现任何格斗商标、官方角色名与招牌招式名 ——
`copy.test.ts` 会把整个目录连注释一起扫一遍。
