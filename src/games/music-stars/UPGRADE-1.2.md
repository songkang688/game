## 一、现状审查（开工前逐条查证）

### 1. 音高怎么发声？频率表对不对？

用的是 `OscillatorNode`（`type = "sine"`），这一点没问题。**频率表是手打的常数**：

```ts
const NOTES = [261.63, 293.66, 329.63, 392.0, 440.0]; // 哆来咪索拉
```

对照十二平均律 `f = 440 × 2^((n−69)/12)`：

| 音 | MIDI | 十二平均律真值 | 代码里写的 | 误差 |
| --- | --- | --- | --- | --- |
| C4 哆 | 60 | 261.625565… | 261.63 | +0.0044 |
| D4 来 | 62 | 293.664768… | 293.66 | −0.0048 |
| E4 咪 | 64 | 329.627557… | 329.63 | +0.0024 |
| G4 索 | 67 | 391.995436… | 392.0 | +0.0046 |
| A4 拉 | 69 | 440 | 440.0 | 0 |

也就是：**近似正确，但不是算出来的**，误差在 0.005Hz 量级（听不出来，可它是手打的，改错了没人拦）。
`advanced.ts` 的节奏关另有两个裸常数 `174.61`（F3）与 `261.63`（C4），同样是手打。
**没有任何一条单测钉住频率。** → 1.2 必须换成公式算 + 精度断言。

### 2. 节奏关的判定窗口是多少毫秒？

**一毫秒都没有——根本没有时间判定。** `onDrum()` 只比对「短/长」的**序列**：

```ts
if (kind === want) { inputPos++; … } else onMiss(…);
```

孩子可以隔一分钟再敲，只要长短顺序对就过关。既没有 `AudioContext.currentTime`，
也没有 `Date.now()`，更没有 `outputLatency` 补偿。**「节奏跟打」目前练的是记忆，不是节奏。**

### 3. `intervalLabel` 与乐理一致吗？

不一致——它压根没说乐理，说的是**五声音阶上的格数**：

```ts
intervalLabel(0, 2) === "往上 2 格"
```

问题不在于「格」这个说法本身（对低年级是好懂的），而在于**同一句话对应不同的音程**：

| 说法 | 实际音程 |
| --- | --- |
| 哆→咪「往上 2 格」 | C4→E4 = 4 个半音 = **大三度** |
| 来→索「往上 2 格」 | D4→G4 = 5 个半音 = **纯四度** |
| 咪→拉「往上 2 格」 | E4→A4 = 5 个半音 = **纯四度** |

「2 格」在五声音阶上是三度也可能是四度。所以现状**不算教错名字**（它一个乐理名字都没教），
但**「音程听辨馆」这一章名不副实**：练完 22 关，孩子不知道什么叫大三度。
→ 1.2 补一张对照乐理写死的半音→音程名表，答对后把真名亮出来。

### 4. 双声部在触屏上能同时按两个键吗？

**不能，这是必修 bug。** 两处原因：

1. 按键只挂了 `click`（`btn.addEventListener("click", …)`）。触屏上一根手指按住 A 不放、
   另一根手指按 B，B 那一下经常出不来 `click`；就算出来了也是**先后两个事件**，
   没有任何「同时」的概念。
2. 判定逻辑 `chordDone` 明写成「先按一颗，再按另一颗」，还会提示
   「对了一颗，另一颗也按上～」——**设计上就是顺序按，不是同时按**。

`pointerdown` / `pointerId` 在整个目录里一次都没出现。→ 1.2 必须按 `pointerId` 独立记录。

### 5. 简谱记号对不对？

数字对（`SCORE_DIGITS = [1,2,3,5,6]`，五声音阶宫商角徵羽，写成 1 2 3 5 6 是对的），
**但只有数字**：

- **没有八度点**（高音点 / 低音点）——现在全部音符在同一个八度内，不标也不算错，
  可一旦沙盒或后续加高八度就没法表达；
- **没有时值横线**（四分音符不加线、八分音符加下划线、二分音符加增时线）——
  节奏信息在谱面上**完全缺失**，孩子照着「1 2 3 5 6」弹不出任何节奏。

字号 26px（≤420px 时 22px），满足「≥20px」。

### 6. 首次交互解锁 `AudioContext` 做了没有？

**没有。** `AudioContext` 是在 `tone()` 里懒创建的，而第一次 `tone()` 由
`later(…, 600)` 这个定时器触发——**不在用户手势的调用栈里**。
浏览器的自动播放策略会让它停在 `suspended`，**整段范奏是静音的**，
而且代码里没有任何 `resume()`。页面切后台也没有 `suspend()`。

### 7. 音量上限保护？静音开关？

- 峰值写死 0.28（`index.ts`）/ 0.24（`advanced.ts`），**没有常量、没有上限校验**。
- **没有主音量节点**：双声部一拍两个音直接并联，0.24 × 2 = 0.48；
  范奏与手动敲击重叠时还会更高。没人管过总和。
- **没有静音开关**，也没有音量设置，更没有存本地。

### 8. `guide.ts` 泄题吗？

**没有。** 10 条章节条目全在讲方法（听走向、切段记、用手比高低、先听高声部再听低声部、
视奏先扫一遍谱），一个具体旋律都没写。也能过 `src/games/copy.test.ts` 与
`ui/guide.ts` 的 `isAnswerLeak` 过滤。这一条 1.2 只做增量补充，不返工。

## 二、1.2 要做的事

### 1. 音准正确性（硬性）—— 新建 `tuning.ts`

- `midiToFreq(n) = 440 × 2^((n−69)/12)`，五声 / 七声音阶都从 MIDI 号算频率，**不再手打常数**；
- 单测断言 C4 ≈ 261.6256、A4 = 440、C5 ≈ 523.2511，**误差 < 0.01Hz**；
  另加八度倍频、半音比 = 2^(1/12) 两条第一性原理断言；
- `INTERVAL_NAMES` 按乐理写死 0–12 半音（纯一度 / 小二度 / 大二度 / 小三度 / 大三度 /
  纯四度 / 增四度 / 纯五度 / 小六度 / 大六度 / 小七度 / 大七度 / 纯八度），**全覆盖单测**；
- `intervalLabel`（「往上 2 格」）**原样保留**——它是 1.1 选项文案，快照与既有用例都钉着它；
  1.2 在 `IntervalRound` 上**加一个** `theory` 字段，答对后才亮出真名，
  顺带把「2 格可能是三度也可能是四度」这件事讲给孩子听。

### 2. 节奏判定分级 —— 新建 `timing.ts`

- 三档窗口常量化：`PERFECT_MS = 60` / `GOOD_MS = 120` / `OK_MS = 200`，超出算漏；
- **判定基准一律 `AudioContext.currentTime`**（秒，单调、与音频输出同一把尺），
  绝不用 `Date.now()`；
- 开局做一次输出延迟测量：`outputLatency`（没有就退 `baseLatency`，再没有退 0），
  夹到 0–400ms，判定时把玩家的敲击时刻**减去**这段延迟——声音晚到耳朵多久，
  孩子就自然晚敲多久，这一段不算他的错；
- `judgeTap()` 把一次敲击对到最近的、还没被占用的拍点上，返回档位与偏差毫秒；
- 边界值全写单测：60 / 60.1 / 120 / 120.1 / 200 / 200.1 六个点。

### 3. 多点触控（duet 硬性）—— 新建 `touch.ts`

- `ChordPad` 按 `pointerId` 独立记录按下 / 抬起，`heldKeys()` 给出当前同时按住的键；
- 松开后仍在 `CHORD_WINDOW_MS = 220ms` 窗口内的键仍然算进和弦，
  照顾「两根手指差一点点」的真实手感；
- 同一个键被两个 `pointerId` 按住只算一次；抬起一个 `pointerId` 不影响另一个（不串）；
- 单测模拟两个 pointerId 交叠的完整时序。

### 4. 示范与练习 —— 新建 `practice.ts`

- 范奏：每关开头可「听一遍范奏」，**视奏章除外**（那章本来就不给范奏）；
  播放中输入禁用并显示「听」；
- 慢速练习 `0.6× / 0.8× / 1.0×`：`scaleMs(ms, speed) = ms / speed`，慢速时音更长、间隔更宽；
- **慢速通关只给一星，全速才按失误数评 1–3 星**（`rateWithSpeed`），单测钉死。

### 5. 自由弹奏沙盒（新增）—— 新建 `sandbox.ts`

- 不计分的键盘：五声（5 键）可切七声（8 键，含高八度的哆）；
- 录音 **30 秒硬上限**，最多存 **6 段**，满了丢最老的；
- 存档 key `yiduo-yixing.music-stars.sandbox.v1`（只增不改，走 `yiduo-yixing.` 前缀）；
- **沙盒不产星、不写关卡进度、不碰 `yiduo-yixing.l99.*`**。

### 6. 三种音色 —— 新建 `synth.ts`

| 音色 | 波形 | A | D | S | R | 低通 |
| --- | --- | --- | --- | --- | --- | --- |
| 星铃 | triangle | 0.005 | 0.28 | 0.18 | 0.45 | — |
| 木琴 | sine | 0.002 | 0.14 | 0.00 | 0.16 | — |
| 软风琴 | sawtooth | 0.07 | 0.10 | 0.75 | 0.28 | 1600Hz |

- 全部现场合成；软风琴的锯齿波过一道低通，避免刺耳；
- 音色可在设置里切换，选择存本地。

### 7. 音量与静音（硬性）

- `VOLUME_DEFAULT = 0.35`、`VOLUME_MAX = 0.6`，主音量节点统一收口；
- 单个音的包络峰值 `voicePeak(volume, timbre, voices) = volume × timbre.gain ÷ voices`，
  **同时发几个音就分几份**，所以任何路径下同时发声的总增益 ≤ 0.6；
- 静音按钮，状态存本地；静音时主增益直接置 0。

### 8. 视觉化反馈

- **音高越高星星越靠上**：星星的 `bottom` 与 MIDI 号线性对应，
  让孩子看得见「高低」（`pitchOffsetPx` 纯函数，单测钉线性关系与单调性）；
- 星星按下发光 + 下沉 4px，松开回弹，发声与视觉同一帧（都在 `pointerdown` 里做）；
- 节奏关用**横向滚动的节拍条**，判定线固定在中间；
- 答对：星星连成星座（SVG 连线）+ `api.play("win")`；答错温和提示，不打叉；
- `prefers-reduced-motion`：关掉星座连线动画与节拍条滚动，节拍条改为**逐格跳动**。

### 9. 简谱记号补全 —— 新建 `notation.ts`

- 八度点：高八度上点、低八度下点；
- 时值横线：二分音符加增时线 `1 -`、八分音符加下划线；
- 单测覆盖「数字 + 八度点 + 时值」三件事的组合。

### 10. 平台接线 —— 新建 `runtime.ts`

- `level99.ts` 只读，`LevelGameOptions` 里**没有** `initialLevel` 这个口子。
  按红线不越界改平台，本目录自己提供 `parseLevelParam` / `resolveInitialLevel` /
  `openLevelOnMap`——挂载后照着地图替玩家点一下那一关；点不到就安静停在地图上。
  这一处折中写进回复。
- Skip 走框架自带的 `requestSkip`，不动。
- 首次用户交互 `resume()` 解锁；`visibilitychange` 隐藏时 `suspend()`；
  `destroy()` 断开所有节点并 `close()`。

### 11. 手机 360px

- 星星热区 ≥ 56px、间距 ≥ 8px，五颗星在 360px 下一行放得下（5×56 + 4×8 = 312 ≤ 360）；
- **双声部关同时按的两个键间距 ≥ 24px**（`duetGapPx`，单测钉死），一根手指盖不住两个；
- 简谱区字号 ≥ 20px，八度点清晰。

## 三、模式矩阵

- `campaign` 188 关保留，**前 99 关生成参数一个字不改**（逐关指纹钉死）。
- **自由弹奏沙盒**作为地图上的一个入口，不算 mode，不产星。
- **不做对战**：本款考的是听觉记忆与音准，同屏抢答会把它变成谁手快，
  而且一方弹出声音会直接干扰另一方听辨——机制上互斥。
- **不做无尽**：本款是听觉记忆游戏。无尽只能靠「越来越快」制造压力，
  练到后面比的是手速和反应，不是音乐性；而且旋律越来越长时人的短时记忆有硬上限
  （7±2 个音），越过之后就只剩瞎按。教学收益为负，所以不做。
  真要做也只有一条路：**不加速、只加长，并且每轮换调式**，靠调式辨识而不是手速支撑难度——
  但那本质上是第 11 章，不是无尽。

## 四、2.5D / 3D 决策

**保持 2D。** 音高的「高低」用纵坐标表达就够直观了，加透视只会让判定线和拍点更难对准。
不引 three.js、不引 WebGL。

### 与计划的四处出入

1. **`intervalLabel` 一个字没动**，1.2 的乐理名走 `IntervalRound.theory` 这个新字段，
   答对之后才亮出来。原因是 `levels188.test.ts` 用
   `expect(q.choices[q.correct]).toBe(intervalLabel(q.a, q.b))` 钉着选项文案，
   而「几格」对低年级本来就更好懂——教学上正确的做法是**先给好懂的说法，再补上真名**，
   不是把「格」换掉。
2. **`makeChords` 用可选参数而不是直接改行为**。双声部要求同拍两音隔 ≥2 格，
   但 `makeChords` 是 1.1 起就有的公开函数、老用例按默认行为断言，
   所以默认仍是 1，只有 `buildDuets` 传 2。
3. **简谱的八度点在关卡里看不到**。五声音阶键盘全在同一个八度内，
   按乐理就不该加点。八度点真正用得上的地方是自由弹奏台的七声音阶（高八度的哆），
   那里会显示；渲染器与单测两边都覆盖了高八度与低八度。
4. **加了一条计划里没写的兜底**：`StarSynth.now()` 在拿不到 `AudioContext` 时
   退回一把单调墙钟。写节奏关的时候才发现，如果浏览器压根不给 Web Audio，
   `currentTime` 会一直是 0，节奏关的每一次敲击都会被判成「没落在拍子上」——
   一路判负。有音频时仍然一律用 `AudioContext.currentTime`。

### 节奏判定与延迟补偿

- 拍点表 `beatTimes` 在范奏放完之后按 `synth.now() + 1.2 秒` 起排，
  单位是秒、尺子是 `AudioContext.currentTime`；
- 每次敲击 `judgeTap(beatTimes, synth.now(), beatTaken, synth.latencyMs)`，
  先把 `latencyMs` 从敲击时刻里减掉，再找最近的、还没被占用的拍点；
- `latencyMs` 在 `unlock()`（首次用户手势）里量一次：
  `outputLatency` → `baseLatency` → 0，夹进 0–400ms；
- 敲对拍点但长短敲反了，算一次失误并把那一拍标掉；一句结束时还没被敲到的拍点算漏。

这串数是在动第一行玩法代码之前、从 1.1 的输出上取下来的，

原有的两条聚合指纹（`levels188.test.ts` 里的 `de52474f` 与 `71ee0837`）**一条没删**，
