# 1.2 第 14 步 · A 档 —— `shoot-range`「康康射击场」升级计划

规格：`docs/plan-1.2-step14-A-shoot-range.md`。工作基线 `origin/game-1.2-window3`，只推这一条线。
只改 `src/games/shoot-range/**`，不碰 `sky-squad` / `tank-battle` 与任何平台文件。

分级基调（整份升级都守这一条）：这是**嘉年华打靶 / 打气球**，靶子是同心圆靶、气球、飞碟、铁皮机器人、
彩虹靶、护盾靶、分裂靶，以及两种「不许打」的靶（举旗子的好人靶、鸭梨的花朵靶）。
没有枪械写实建模，没有军事化十字准星（准星是一圈小花瓣 + 中心星点），没有伤害、没有血。
发射物叫「星星弹」，补给叫「装星星」。失败只鼓励。

## 一、现状审查（规格第三节，逐条）

**1. 瞄准是直接指向还是移动准星？后坐力怎么表达？**

两套并存：鼠标 / 手指按下即把准星放到指针处（直接指向），键盘 `WASD` / 方向键按住可以匀速微调
（`NUDGE_STEP = 26`，`aim += NUDGE_STEP * dt * 12`）。鼠标点一下 = 「瞄这里并且开火」，
拖动则只瞄不打。**后坐力完全没有**：开火只有 `cooldown = 0.16s` 的最短间隔和换弹，
没有前摇、没有准星位移、没有散布、没有命中顿感——按下去就是瞬时判定，手感是"点名式"的，
连发和单发的代价一模一样。

**2. 靶子种类、分值、节奏是数据驱动吗？有没有不公平靶？**

六种：`bull`（同心圆，环数 ×2，10/8/6/4 环）、`balloon` 14 分、`ufo` 18 分、`robot` 20 分、
`number` 16 分、`friend` 好人靶 −30 分。分值写死在 `scoreForHit` 的 switch 里（半数据驱动：
只有环数这一档是函数算的）。出现节奏是数据驱动的——`levels.ts` 的 `KIND_POOL[章节]` 加
`mulberry32(0x5ba7 + lv * 2654435761)` 确定性生成，同一关每次布局一模一样。
**没有「必须秒反应」的不公平靶**：气球飘出顶部会从底下重新升起而不是消失，飞碟机器人碰边界折返，
靶子不会逃跑；唯一的时间压力是第 8 章起的倒计时（最短 16 秒），而且 `levels.test.ts`
已经用「一个个瞄、每发 0.45 秒」的模拟证明了 188 关都能在弹药与时限内清完。

**3. 四种模式各自胜负条件？双人是两套准星还是轮流？**

- `campaign`：清完全部必打靶 = 赢；倒计时到 0 或弹药预算打光 = 输（`shotBudget = need + slack + max(4, need*0.9)`）。
- `endless`：波次制靶潮，清完一波续下一波，时间到就结算，成绩记 `recordEndlessBest`。
- `versus` 与 `twoPlayer`：**是同一个入口**。首页 `meta.modes` 声明了四种，实际只有三条代码路径，
  `versus` 和 `twoPlayer` 都指向那一个「双人分屏 60 秒比命中率」。
- 双人是**上下分屏**（`canvas` 被切成两块 `rect`，两人各一份完全相同的靶阵、各一套准星），
  不是同屏；不是轮流。键盘两套键位并行没问题，触屏是靠 `pickPane` 按 y 坐标分屏归属，
  同时按会互相顶（只维护一个 `dragId`，第二根手指进来会把第一根的拖动状态覆盖掉）。

**4. 无尽是加速度还是加靶数？成绩怎么记？**

两个都加，但是**阶跃**不是连续：`tideWave(w)` 给 `count 3→12 封顶`、`speed 1→2.4 封顶`、
`seconds 16→9`，好人靶第 5 波才混进来、比例封顶三成。关键问题是**必须清完当前波才会续下一波**，
所以它不是「打不完的靶场」，而是「一波一波的关卡」，卡住就只能等 timeup。
成绩 `tideScore(cleared, wave, acc) = (cleared*10 + (wave-1)*25) * (1 + acc*0.5)`，
已经在走 `save.recordEndlessBest("shoot-range", score)`。

**5. 188 关三星标准合理吗？**

只看命中率 + 犯规：干净且命中率 ≥ 90% → 3 星；命中率 ≥ 70% 且没碰好人靶 → 2 星；否则 1 星。
不看用时、不看连击。**偏紧且单一**：10 发里打空 1 发就掉出三星，而弹药预算比三星线宽得多，
所以整体是「过关很容易、三星很陡」，中间没有过渡；连击打得再漂亮也不加分，
1.2 要补的连击倍率因此在闯关里没有落点。

**6. 手机上手指遮挡靶子怎么处理？**

基本没处理。准星就画在手指按下的那一点上，手指必然压住靶子；只有「拖动只瞄不打」这半个措施，
代价是触屏要点两次（先拖着瞄，抬手不发射，再点一下才打）。
HUD 五个 chip 在 360px 会折成两行，`.sr-chip` 字号还被 `@media(max-width:420px)` 压到了 12px，
低于 1.2 的 ≥ 14px 底线。

### 真机视口实测（playwright，375×667 与 360×720，两档都跑同一套主链路）

跑通的链路：选关地图 →「开始冒险」→ 第 1 关按下预览 / 抬起发射三发清场 → 三星结算 →
`?level=125` 直达「忍住不打」章 → 无尽靶场看着靶子一个个冒出来、跑掉计数往上走 →
双人同屏两指同时按住（两套准星各自带名字）→ 键盘 F / L 各打一发 → 一起打的目标分。
全程零 console error、零横向溢出（`scrollWidth === innerWidth`）。

实测抓出来两个真问题，都已修：

1. **模式条离开地图不消失。** `.shr-modebar{display:flex}` 的优先级压过浏览器自带的
   `[hidden]{display:none}`，所以 `bar.hidden = true` 根本没生效，进了关卡那三颗大按钮
   还杵在顶上，360px 屏白占两百多像素。补了 `.shr-modebar[hidden]{display:none}`
   （连同其它几块 `display:flex` 的一起），并加了一条用例守着。
2. **暂停按钮会被横滑出屏幕。** HUD 是一行横滑，chip 一多，最右边的暂停就滑没了。
   顶栏拆成两块：左边 chip 横滑，右边「👆 预览 / ⏸️」固定不滚。chip 顺序也按
   「打的时候要看哪个」重排成 星星篮 → 剩几个靶 / 几秒 / 几发 → 分数与连击——
   分数排最后不亏，打中那一下画面上会飘一个 `+N`，比 HUD 显眼。

另外顺手修了两处：扣扳机当场刷 HUD（余弹不再等一帧才更新）、发射台底边不再被画布切掉。
