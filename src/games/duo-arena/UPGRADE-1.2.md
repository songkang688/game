# 11-B · `duo-arena`「梨康擂台」1.2 升级计划

窗口 3 · B 档。规格来源：`docs/plan-1.2-step11-B-duo-arena.md`、`docs/plan-1.2-supervisor.md` 第八 / 九节。
只改 `src/games/duo-arena/**`，不碰 `duo-rush` / `duo-vs-star` / 窗口 1 的平台文件，不改 `src/styles.css`。

## 一、1.1 现状审查（读 `logic.ts` + `index.ts` 得到的事实）

1. **玩法**：屏幕分成上下两个半场（上＝康康，下＝鸭梨），双方共用同一份出目标时间表（同种子），
   各自用手指点自己半场里冒出来的目标抢分。回合 25 秒，回合结束时分高者拿下该回合；
   先拿 2 个回合胜整场；三回合仍不分（含平局）进 15 秒决胜回合。
2. **人机**：完全没有。家里只有一个孩子就打不了，这是最大的坑。
3. **平衡**：两个半场共用一份时间表，位置、种类、存活时长完全一致，理论上没有左右 / 先手优势，
   但 1.1 没有任何断言看住这条。
4. **支配策略**：有——「无脑连点」。目标是 DOM 按钮，点中即得分，没有出手冷却，
   手指乱扫也能蹭到分，只有炸弹会惩罚。
5. **触屏**：只有指点（本来就是点击玩法），没有键盘，等于**违反双人键位约定**（鸭梨 WASD+F+G / 康康 方向键+L+K）。
6. **`meta.blurb`**：和事实一致，但没有人机、没有无尽，`modes` 缺 `endless`，也没有 `platform`。

## 二、1.2 要做成什么

| 项 | 落法 |
| --- | --- |
| 赛制 | 三局两胜赛制层独立成 `match.ts`：比分、赛点判定、赛点氛围（背景变色 + 提示语）、决胜回合。 |
| 人机四档 | `ai.ts`：菜鸟 / 普通 / 高手 / 地狱。低档反应慢、会失手；高档预判但**保留反打窗口**（反应时间恒 > 0，失手率 > 0）。固定 seed 强度单调断言。 |
| 技能 | `skills.ts`：加速 / 护盾泡 / 弹开波三个温和技能，纯状态机，前摇 → 生效 → 冷却；一个键轮转释放。另有「出手」三段（前摇 / 生效 / 后摇），破掉无脑连点。 |
| 场地 | `stages.ts`：4 张擂台数据表，平台数量 / 移动地块 / 边界形状（方台 / 圆台 / 沙漏）都不同，按局轮换。 |
| 让分 | 落后方温和助推，封顶 8%，默认关，HUD 常驻显示开关状态。 |
| 模式 | 双人同屏（本命）+ 单人 vs 人机四档（新增）+ 无尽守擂（新增，`save.recordEndlessBest("duo-arena", 连胜)`）。**不做 188 闯关**：纯对战硬凑 188 关是注水，理由写进 `meta.ts` 注释。 |
| 键位 | `keys.ts`：鸭梨 `WASD`+`F`(出手)+`G`(技能)，康康 `↑←↓→`+`L`+`K`，`Esc` 暂停；手机每个半场自带摇杆 + 两个动作钮，热区 ≥ 44px。 |
| 视觉 | 保持 2D，Canvas 矢量画原创小人；命中是弹开转圈，不是受伤；`prefers-reduced-motion` 关抖动。 |

## 五、与分支上另一份 11-B 的合并结论

收尾 rebase 时发现 `origin/game-1.2-window3` 上已经有另一份 11-B 提交（`arena12.ts` + `arena12.test.ts`，
外加对 `index.ts` / `meta.ts` / `guide.ts` 的改动）。两份的取舍如下，**没有删掉任何既有测试**：

- `arena12.ts` 与它的 37 个用例**原样保留**，并且在 `index.ts` 里真接上了：
  让分曲线 `arenaHandicap`（本回合实时按元气差补的那一层）、HUD 徽标 `arenaHandicapBadge`、
  赛点提示语 `matchPointLine`、连胜纪录 `bestStreak`。
- `index.ts` / `meta.ts` / `guide.ts` 取本档版本。原因是那一份的擂台仍然是**纯点击**玩法，
  全文件搜不到一个键盘监听：没有鸭梨 `WASD`+`F`+`G`、没有康康 `↑←↓→`+`L`+`K`、没有 `Esc` 暂停，
  而这是主管文档第九节第 5 条的硬约定。本档版本是走位对战，两套键位、`Esc`、以及每个半场自带的
  摇杆 + 两个动作钮都齐了，`meta.platform` 也按实测填了 `both`。
