# 1.2 第 22 步 · A 档 —— `landlord-cards`「朵朵抢地主」升级计划(窗口 5)

> 执行分支:`game-1.2-window5`。独占目录 `src/games/landlord-cards/**`,不碰 `fishing-star` / `poop-hero` / 任何其他游戏。
> 这是**纸牌策略**升级,不是赌博:全程无货币、无下注、无赔率、无筹码,「加倍」只用星星与气势值。

## 一、现状审查(动代码前先把基线读清楚)

| 问 | 现状 |
| --- | --- |
| `fan.ts` 支持哪些牌型 | `fan.ts` 其实是**扇形手牌几何**,牌型引擎在 `logic.ts`:单 / 对 / 三 / 三带一 / 三带一对 / 顺子 / 连对 / 飞机 / 飞机带单 / 飞机带对 / 四带二 / 四带两对 / 炸弹 / 王炸,14 种全在,没有漏 |
| 合法性判定是不是纯函数 | 是。`parsePlay` + `beats` 无副作用;`ai.ts` 的 `beatCandidates` 已能枚举「所有能压过上家的组合」 |
| `ai.ts` 有几档 | 三档 `easy` / `normal` / `hard`;困难档已有队友判断,但队友只剩几张时仍可能抢走出牌权 |
| 叫分规则 | `suggestBid` 按手牌强度叫 0–3 分,`runBidding` 一圈叫分;没有明牌加倍(也不打算加——加倍只走星星/气势值) |
| `sim.ts` 能跑多少局 | 已有 `simulateGame` / `winRate`,现有测试固定 seed 跑 200 局 |
| 188 关是不是关卡化牌局 | 已有固定 seed + 章节 + 档位 + 照顾力度,但**没有每关目标**,也没有「可赢性」证明 |

## 二、本步要落地的五件事

1. **牌力提示三档**:新增纯逻辑模块 `hint.ts`。
   - `off` 关(挑战)/ `groups` 高亮所有可出牌组 / `coach` 推荐一手 + 一句理由。
   - 推荐必须走**真实搜索**:枚举全部合法候选,用与困难档同一套局面分打分,理由里的数字(候选数、打完剩几手、是不是能一把走完)全部来自搜索结果,不许拍脑袋写死。
2. **AI 三档 + 农民配合**:保留现有三档,补一条「队友快走完就彻底让路」的困难档规则;固定 seed 下断言高档胜率显著更高。
3. **出牌动画**:新增纯状态机 `anim.ts`,飞牌 180–240ms + 轻微旋转,`prefers-reduced-motion` 改短淡入但走同一状态机;`index.ts` 照状态机实现飞牌与手牌重排滑动,禁止瞬变。
4. **关卡化牌局**:188 关每关加**目标**(赢 / 几手内赢 / 不出炸弹赢),用 `sim.ts` 新增的 `proveLevel` 证明每关都存在可赢线路。**前 99 关的 seed / 档位 / 底分 / 照顾力度 / 身份 / 星门一个字不改**,目标一律是「赢」。
5. **无尽连胜**:继续走 `save.recordEndlessBest("landlord-cards", streak)`,补上档位随连胜升级的断言。

## 三、模式矩阵

`campaign` / `versus` / `endless` / `twoPlayer` 四模式全保留。`twoPlayer` 是朵朵 + 星星 + 一个小牌灵的本地两人坐庄玩法,新增「两个真人 + 1 AI 打到结算」的脚本化对局测试。

## 四、2.5D / 3D 决策

**保持 2D**。扇形手牌只做轻微透视排布,不引入 three.js,不引入任何依赖。

## 五、手机 360px

牌宽 ≥ 44px(`cardWidthFor(360)` 已满足);「不出 / 提示 / 出牌」三钮固定底部一行,热区 ≥ 44px;手牌区可横滑。

## 六、测试(新增 ≥ 20 个用例)

牌型识别全覆盖(含四带二与飞机带翅膀边界)、可压牌组枚举、AI 三档固定 seed 各 20 局胜率、农民配合构造局面、关卡可赢性抽样 30 关(含 100 / 145 / 188)、牌力提示走真实搜索、飞牌时长区间、无尽连胜、`destroy` 归零。

## 七、红线

无货币 / 下注 / 赔率 / 筹码;无血无伤;输了只鼓励;角色只用朵朵 / 星星与原创的团团、圆圆;无广告内购账号联网;禁止 three.js。代码与注释里的商标词一并清掉。
