# 1.2 第 23 步 · B 档 —— `red-blue-tap`「红蓝点点」升级计划(窗口 5)

> 执行分支:`game-1.2-window5`。独占目录 `src/games/red-blue-tap/**`,一个字都不碰 `red-blue-race`(A 档)与 `red-blue-tug`(C 档)。
> CSS 前缀本款用 `rbt-`(拔河那款是 `rbg-`,不会撞);1.2 追加的样式只许贴在老样式后面,不改老规则。
> 一句话目标:**把「谁手快」改成「谁更准 + 更稳」**——大人靠手速碾压小孩的路子必须堵死。

## 一、现状审查(动代码前先把基线读清楚)

| 问 | 现状 |
| --- | --- |
| 判分是不是纯计数 | **是**。抢到一个点 +1(连击翻倍),先到 `targetPoints` 获胜;没有任何「点得准 / 点得克制」的加分项,手速就是全部 |
| 有没有「不能点」的目标 | 有一半:陷阱点(`trap`)碰到就把分让给对手,但**只有一种反义**,没有颜色指令、更没有「不要点红色」这类反向指令 |
| 有没有反应类回合 | **没有真正的反应回合**。点点用 `rbtIn` 动画直接闪现,冒出来就能点,既没有「预备—亮」的节奏,也没有「亮之前点」的抢点惩罚 |
| 两侧目标是否对称 | **谈不上对称:根本没有第二侧**。1.1 的对手是一个 `setTimeout` 定时器扮演的小电脑,场上只有一套点,不存在两个人各自的按钮 |
| `campaign` 188 关形态 | 单人 vs 小电脑抢分,先到 `targetPoints`;十章各带一种规则(陷阱 / 双子 / 连击 / 道具 / 序列 / 读招) |
| 有没有防连点作弊 | **没有**。`pointerdown` 直接记分,自动连点器和「一巴掌拍下去」都能白拿分 |
| 触屏两侧热区会不会重叠 | 会。`placeDot` 只做 `6%~78%` 的随机定位,不查间距,双子挑战时两个点可能贴在一起误触 |
| 无尽成绩记什么 | 记「分数」`recordEndlessBest(id, score)`,1.2 按主管口径改记「撑过的回合数」 |

## 二、本步要落地的六件事

1. **四种回合类型(新增纯逻辑 `rounds.ts`)**
   - ① `reaction` 反应:先「预备」再「亮」,亮灯后先点者得分;**亮之前点就是抢点,扣自己一分**。
   - ② `order` 顺序:1→2→3 按号码点,点错整轮作废。
   - ③ `color` 颜色指令:只点指定颜色,含 **「不要点红色」的反向指令**;颜色一律配形状(圆 / 方 / 三角 / 花),色弱也能玩。
   - ④ `count` 计数:限时内点满 N 个,**超过就作废**(这一条专门教克制,手快乱拍反而输)。
2. **公平性**:一轮只生成**一份** `RoundPlan`,两侧共用;左侧位序 `p`、右侧位序 `n-1-p` 指向同一个逻辑格子,`isMirrored` 写成断言进测试。抢点判定只认**同一个时钟源**传进来的 `t`,两侧时间戳来自同一个 `now()`。
3. **防乱拍**:`TAP_DEBOUNCE_MS = 60`,同一按钮 60ms 内的重复输入只算一次;`PALM_WINDOW_MS = 80`,同一侧在 80ms 内碰到 ≥2 个不同按钮判定为「手掌拍」,当次不给分**并把窗口内已经给出去的分收回**。
4. **AI 四档(单人挑战星星时)**:`600 / 420 / 300 / 220ms` + 失误率 `0.30 / 0.20 / 0.12 / 0.07`,反应时间带抖动但**永远 > 0**,写死下限常量;每一档都必须会失误,不许出现完美电脑。
5. **无尽「点到手软」**:回合类型随机、亮灯窗口一轮比一轮短(留人做得到的地板),**失误 3 次结束**,成绩走 `save.recordEndlessBest("red-blue-tap", rounds)` 记回合数。
6. **手感与无障碍**:预备时长 ≥ `READY_MIN_MS`,禁止无预警闪现;指令图形 + 文字双通道;抢点惩罚是「小云朵挡一下」,文案温和;`prefers-reduced-motion` 关闪烁改渐变。

## 三、模式矩阵

`campaign` / `versus` / `endless` 三模式全留,`levels: 188` 不变。

- **`campaign` 前 99 关数据一个字不改**,连 `LEVELS[0]` 的字段集合都不加——所以四种新回合不塞进前 99 关。前 99 关拿到的是「只让它更公平」的那一层:预备—亮节奏、60ms 去抖、手掌拍不给分、小电脑按四档失误率会失手。
- **`versus` 是本命**,这一步把它做成真正的**同屏两侧**:左朵朵、右星星,两侧目标镜像,四种回合轮着来;右侧可以切成「挑战星星(AI 四档)」给一个人玩。两套键位 `A S D F` / `J K L ;`,`destroy` 时两套一起卸。
- **`endless`** 换成「点到手软」:随机回合 + 加速 + 三次失误结束。

## 四、2.5D / 3D 决策

**保持 2D**。不引入 three.js,不引入任何依赖。

## 五、手机 360px

两侧热区中间留 **≥ 24px 隔离带**(`--rbt-gutter`),按钮 **≥ 72px**;比分与回合提示在中间一行,字号 ≥ 16px。

## 六、测试(新增 ≥ 16 个用例)

四种回合规则各自的判分、镜像序列断言、同一时钟源抢点、60ms 去抖、手掌拍收回分数、抢点扣分、AI 四档反应时间与失误率、无尽三次失误结束与回合数成绩、188 抽样可达标不回归、`destroy` 归零与样式只追加的源码巡检。
