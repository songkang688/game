# 1.2 第 24 步 · A 档 —— `clock-house`「时钟小屋」升级计划(窗口 5)

> 执行分支:`game-1.2-window5`。独占目录 `src/games/clock-house/**`,一个字都不碰 `math-farm`(B 档)与 `pinyin-train`(C 档),也不碰窗口 5 其它游戏。
> `quiz99.ts` / `speech.ts` / `level99.ts` 是公共资产,**只读**。CSS 前缀本款用 `clk-`,只许追加,不改别人的规则。
> 一句话目标:**把「认钟面」补成一套完整的时间课**——八类题型、教学正确的时针联动、权重表驱动的难度曲线、每关的错题回顾。

## 一、现状审查(动代码前先把基线读清楚)

| 问 | 现状 |
| --- | --- |
| 题型有几类 | 15 个 `kind`,归成 6 个家族:读钟面(`read`,只到刻)、拨指针(`set`,选钟面)、经过时间(`span`)、时刻加减(`arrive` / `depart` / `next`)、12↔24 与时区(`h24` / `h12` / `zone`)、日历(`weekday` / `monthdays` / `nthday`)、时刻表(`tableEarly` / `tableFast` / `tableWait`)。**缺:时间单位换算(时分秒)、作息表读取、跨中午的经过时间、分钟级读钟面** |
| 生成还是题库 | **全生成**。`buildQuestions(level)` 用 `mulberry32(8500 + level * 7919)` 定种子,重试不换题;干扰项都过 `Set` 去重并有 guard 兜底,`makeTrips` 会重摇直到「最早到 / 最快」唯一 —— 不会出重复题,也不会出无解题 |
| 难度怎么升 | 靠 `kindPool(level)` 的 if-else 阶梯 + `allowedQuarters(level)` + `questionCount(level)`,**没有一张能读的权重表**。第 188 关确实到了时刻表阅读 / 24 小时制 / 日历推理,但**分秒换算完全没有**,跨中午的经过时间也只是碰巧出现 |
| 拨指针联动吗 | **不联动,而且是错的**。`hourHandAngle(hour, quarter)` 只按刻(0.25 小时)偏移,分钟级时刻画不出来;更关键的是根本没有「拨」这个交互——`qSet` 只是三选一挑钟面 |
| 朗读走共用 `speech.ts` 吗 | 走。`quiz99.runQuiz` 里 `speak(q.ask)` 切题自动读、答对答错读评语、「🔈 再听一遍」按钮;没有中文语音包时 `speechReady()` 为 false,按钮保持隐藏、全程静默,**文字全在,体验完整** |
| `guide.ts` 泄题吗 | **不泄**。10 条章节条目全是方法与检查步骤,没有任何具体时刻;`copy.test.ts` 的 `ANSWER_WORDS` 与 `EQUATION_RE` 也已经在全局盯着 |

## 二、本步要落地的六件事

1. **题型补齐到 8 类(+ 1 类 1.1 遗留的日历,续写不推翻)**
   - ① 读钟面:`read`(刻,前 99 关原样)+ 新增 `readMin`(五分 / 一分)。
   - ② 拨指针:`set`(前 99 关原样)+ 新增 `setMin`,干扰钟面专挑「时针死死压在数字上」这个常见错误。
   - ③ 经过时间:`span` + 新增 `spanNoon`(跨中午,上午 → 下午)。
   - ④ 时刻加减:`arrive` / `depart` / `next`。
   - ⑤ 12↔24 换算:`h24` / `h12`。
   - ⑥ **新增** 时间单位换算 `unitHM` / `unitMS` / `unitMix`(时分秒互化)。
   - ⑦ **新增** 作息表读取 `routine`(起床—上课—午饭—放学的一张小表)。
   - ⑧ 简单时区:`zone` 改成「北京时间 + N」这种直观题。
2. **联动时针(纯函数 + 单测)**:钟面时刻统一用「12 小时制的总分钟数 0..719」表示,`hourHandAngleAt(t) = t * 0.5°`、`minuteHandAngleAt(t) = (t % 60) * 6°`;拖分针走最短路径 `dragMinuteTo`,跨 12 自动进位 / 退位。这是教学正确性,必须写死在测试里。
3. **难度曲线用一张表**:`DIFFICULTY_TABLE` 八段(1–30 / 31–60 / 61–99 / 100–122 / 123–144 / 145–166 / 167–177 / 178–188),每段给一组「题型 → 权重」。断言:区间连续铺满 1–188、每段权重和为 1、高段(161–188)必含经过时间与 24 小时制。**前 99 关仍走 1.0/1.1 的老生成路径**,权重表在那三段里只是老题型池的如实描述,用摘要哈希把 99 关的题目逐字钉死。
4. **错题回顾**:本关答完,把答错过的题按「同类换数字」重出一轮(新种子、不给原答案),回顾轮不改星级也不判失败;错题的**题型**计数写本地 `yiduo-yixing.clock-house.mistakes`。
5. **悄悄提示升级成方法提示**:连错 2 次时,`quiz99` 照旧让正确项一闪一闪,本款在同一时刻把提示语换成按题型给的**方法**(「先看时针在哪两个数字之间」),并朗读同一句。提示文案里一个数字都不许出现,用测试扫 188 关全部答案兜底。
6. **拨一拨的手感**:题面里嵌一个可拖的钟面,分针拖到哪儿时针按比例跟着走;默认磁性吸附到最近整分,「🎯 精确」开关关掉吸附;`prefers-reduced-motion` 关掉指针弹跳。

## 三、模式矩阵

`campaign` 188 关保留,`levels: 188` 不变。**对战 / 无尽不做**——理由:这是一款学习游戏,时间计算要的是「想清楚再答」,给它套上计时对战会把孩子逼成抢答,和教学目标反着来;188 关的章节推进 + 错题回顾已经是这类内容合适的节奏。

**前 99 关题型参数一个字不改**:`allowedQuarters` / `kindPool` / `questionCount` 在 0–98 上的返回值、以及 `buildQuestions(0..98)` 的完整输出摘要,全部写进回归测试。

## 四、2.5D / 3D 决策

**保持 2D**。钟面要的是刻度准、数字清楚、指针长短分明,任何伪 3D 都只会挡住读数。不引入 three.js,不引入任何依赖。

## 五、视觉 · 建模 · 手感

- 时针短粗、分针长细、秒针细红,长度比例写成常量并进测试;12 个数字 + 60 根刻度(整点刻度加粗)。
- 拨动磁性吸附到最近整分,可切精确模式。
- 答对:星星 + `api.play("win")`(走 `quiz99` 既有链路);答错只温和鼓励,不打叉。
- `prefers-reduced-motion`:关掉指针弹跳与提示闪烁的缩放。

## 六、手机 360px

钟面直径 `min(62vw, 可用高度)` 且 **≥ 200px**;选项按钮 ≥ 44px,和钟面之间留 ≥ 12px,绝不重叠;题干字号 ≥ 16px,`word-break` 允许换行不溢出。

## 七、平台接线

- `mountLevelGame` / `runQuiz` 的既有链路不动;`ctx.skipped`(跳过后重玩的温柔提示)与 `initialLevel`(框架的「继续第 N 关」「地图直接点第 N 关」)实测。
- `quiz99` 没有开放「按题型给提示」「关末回顾」的接口,公共文件只读,所以这两件事在本款目录里用 `ctx` 代理 + 只读 DOM 观察实现,折中点写在代码注释与回复里。
- `meta.platform` 补 `"both"`,`blurb` 与事实对齐(补上分秒换算与作息表)。

## 八、测试(新增 ≥ 18 个用例)

八类题型的生成与判分、时针联动比例与跨 12 进位、磁性吸附、经过时间跨小时 / 跨中午、12↔24 换算、单位换算、作息表唯一解、难度权重表(区间连续 / 和为 1 / 高段必含经过时间与 24 小时制)、错题回顾生成同类题且不重复原题、方法提示不含任何答案字符串、前 99 关摘要哈希回归、`destroy` 归零与样式只追加的源码巡检。

## 九、红线

学习内容必须正确(时间换算错一处就是教错人);失败只鼓励;攻略只讲方法不给答案;无商标;角色只用朵朵 / 星星;无血无死亡;无广告 / 内购 / 账号 / 联网;禁止 three.js;`destroy` 拆干净监听 / timer / rAF。
