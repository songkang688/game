# 一朵一星 1.3 · 视觉宪法（全 29 步适用，违反即打回）

> 1.3 只做一件事：**把 76 款游戏的前端视觉从「能玩」升级到「精美」**。玩法、关卡数值、胜负规则一律不动。
> 本文件是全部视觉步的最高裁量标准，与 [`plan-1.3-supervisor.md`](./plan-1.3-supervisor.md) 一起读；
> 每一份 `plan-1.3-step*` 提示词都必须链接本文件，执行子代理动笔前必须通读。
> 配套方法论（vendored skills）见 [`plan-1.3-skills.md`](./plan-1.3-skills.md)。

---

## 一、为什么要有这部宪法

1.2 收官后，76 款游戏玩法完整、测试全绿，但**建模粗糙**是普遍病：

| 病例（`origin/game-1.2` 实况） | 病症 |
| --- | --- |
| `gold-hook` 黄金矿工 | 矿工是「圆脑袋 + 几段圆弧」的准火柴人；金块是描边圆 |
| `poop-hero` 便便超人 | 主角与道具是纯色几何块，无体积、无表情层次 |
| `sling-birds` 弹弹小鸟 | 小鸟是一个圆 + 两个点，弹弓是两条线 |
| `rainbow-run` 彩虹跑跑 | 2.5D 数学在（`view3d.ts`），但跑者与障碍是平涂色块，没有纵深观感应有的体积与光影 |
| `garden-guard` 花园守卫 | 塔与敌人是色块 + 描边，波次再精彩也像草稿 |

病根不是「没人会画」，而是**没有共同的审美底线与共享素材**：76 个子代理各画各的，谁都不敢多花笔墨。
1.3 用本宪法定底线，用第 1 步的共享套件（[`step1-A` 素材包](./plan-1.3-step1-A-art-kit.md)、
[`step1-B` 布局动效](./plan-1.3-step1-B-layout-motion.md)、[`step1-C` 跑道套件](./plan-1.3-step1-C-3d-runner.md)）供弹药。

## 二、绝对禁止（负面清单，验收第一轮就查）

以下形态在 1.3 之后的任何画面里出现，直接打回：

1. **火柴人**：两个圆 + 直线四肢当角色。角色必须有体积（躯干是有宽度的形状）、有五官、有发型 / 帽子 / 配饰等剪影特征。
2. **纯色方块 / 纯色圆当金币**：一个 `fillRect` 或一个黄色 `arc` 就叫金币的，不行。金币必须有边缘厚度、高光、内圈细节（星星 / 花纹）与拾取反馈。
3. **1px 线稿障碍**：只有 `strokeRect` / 单线描边的障碍物。障碍必须有填充体积、顶面 / 侧面色差（明暗两阶以上）与落地阴影。
4. **无体积草稿角色**：没有阴影、没有描边层次、没有表情的「占位圆」。任何会动的实体至少要有 底色 + 暗部 + 高光 三阶。
5. **写实恐怖 / 尖锐惊吓**：不做写实血肉、骷髅、尖牙巨口特写。反派也要圆润 Q 版（皱眉、鼓腮，不狰狞）。
6. **商标与他人角色**：详见第八节。像不像「地铁跑酷 / 马里奥 / 蛋仔」只许在**观感质量**上像，剪影、配色标识、名字一个都不许像。

## 三、人物标准（Q 版宪章）

- **头身比**：约 **2–3 头身** Q 版。头大身小、四肢短圆，脸部至少眼 + 腮红 / 嘴两个特征层。
- **清晰剪影**：把角色涂成纯黑看轮廓，必须仍能认出是谁（发型 / 耳朵 / 帽子 / 尾巴等剪影特征至少一个）。
- **动画底线**：待机呼吸循环（缩放或上下浮动 ≤ 4%）+ **眨眼**；有移动的游戏要有左右朝向（翻转即可，但配饰方向要对）；
  有胜负的游戏要有**受伤表情**（眩晕圈 / 星星，不出血）与**胜利表情**（笑 + 跳或撒花）。
- **双人款 A/B 一眼可区分**：`ice-fire-forest` 冰冰火火、`puff-bros` 噗噗兄弟、`red-blue-*` 红蓝系、
  `gold-hook` 双钩手、`duo-*` 全家——A/B 角色必须在**剪影 + 主色 + 配饰**三层都不同，且**两个都精美**，不许 B 角是 A 角换色偷懒到只改 `fillStyle`。
- **共享角色**：朵朵（小花）、星星及其皮肤是全家 IP，由 [`step1-A` 素材包](./plan-1.3-step1-A-art-kit.md) 统一提供
  可 import 的绘制函数（目录 `src/art/kit/`）。各游戏可以有独占角色，但凡是画朵朵 / 星星，**必须 import kit，不许自己再画一套**。

## 四、金币 / 星星 / 障碍 / BOSS 标准

- **收集物**（金币 / 星星 / 宝石 / 花瓣）：边缘厚度（侧面色阶）、至少一处高光、内圈细节；被收集时要有反馈
  （放大消散 / 星屑粒子 / 计数器 +1 飞字，`prefers-reduced-motion` 时退化为淡出）。
- **障碍**：体积感（顶面 / 侧面明暗）、落地投影；会伤人的障碍要有可读的「危险语义」（尖刺、警示色带），但保持圆润。
- **BOSS 出场**：学 4399 同类的方法——出场要有**仪式感**（名字横幅 / 震屏一次 / 元气条展开），
  体型明显大于小兵，配色自成一组；击败时星星飞溅 + 摊手坐下，不做死亡描写。
- **道具复用**：金币、星星、爱心、盾牌等通用道具一律用 `src/art/kit/` 的共享绘制函数；某款独占的道具可以自画，但要达到同等三阶光影标准。

## 五、2D / 2.5D / 3D 分级口径（何时用哪种）

| 级别 | 技术 | 适用 | 例 |
| --- | --- | --- | --- |
| **精 2D** | Canvas 2D 矢量 + 三阶光影 + 粒子 | 棋牌、消除、答题、养成、俯视小品——纵深不带来玩法信息的 | `gomoku`、`mahjong-bloom`、`kitty-care`、`math-farm` |
| **2.5D**（默认升级方向） | `src/engine/view25d.ts` 透视投影 + 分层视差 + 深度缩放精灵 | 跑酷、赛道、球道、有前后纵深的动作 | `rainbow-run`、`duo-rush`、`bowling-lane`、`red-blue-race` |
| **伪 3D 观感** | 2.5D 全套 + 地面网格滚动 + 雾化 + 镜头微倾 / 抖动（reduced-motion 降级） | 「商业跑酷大作观感」目标款：三车道纵深跑酷 | `rainbow-run` 无尽、`duo-rush`、`poop-hero` 俯冲段 |
| **真 3D（three.js 等）** | **禁止** | — | 离线 PWA 底线：零外部运行时依赖，包体不膨胀 |

- 判据：**纵深会不会改变玩家的判断？** 会（躲障碍、变道、投掷落点）→ 至少 2.5D；不会 → 精 2D 即可，不硬上透视。
- 2.5D 一律走 [`step1-C` 跑道套件](./plan-1.3-step1-C-3d-runner.md) 与既有 `src/engine/view25d.ts`，禁止再造第二套透视数学。

## 六、向 4399 同类学什么（只学方法，禁止抄）

允许研究 4399 / 同类休闲游戏的**方法论**，且只落地为下面四种可检验的结构：

1. **画面密度**：主体之外要有中景装饰（云、树、观众星星）与近景反馈（粒子、尘土），但 HUD 信息 ≤ 3 组，不喧宾夺主。
2. **角色剪影**：一屏内每个可交互实体剪影互不混淆（收集物 / 障碍 / 敌人涂黑后可区分）。
3. **关卡节奏展示**：进关有「第 N 关 + 目标」入场卡，过关有节奏化结算（星级逐颗点亮、分数滚动）。
4. **BOSS 出场**：见第四节。

禁止：截图临摹、扒素材、复刻商标配色标识、使用原作角色名。研究结论只能以上述结构进代码。

## 七、手机与可访问性硬门槛（360 × 640 视口逐款验）

- 可点热区 **≥ 44 × 44 px**；相邻热区间距 ≥ 8px。
- 游戏内文字（HUD 数字、按钮字）**≥ 14px**，正文与攻略沿用 1.2 的 ≥ 16px 标准**不降**；对比度 ≥ 4.5:1。
- Q 版角色在 360px 宽的实机缩放下**不能糊成色块**：主体角色屏显 ≥ 32px 高，五官仍可辨；辨不清就简化细节层，不许缩没。
- **`prefers-reduced-motion` 必须尊重**：视差滚动、震屏、闪烁、粒子雨全部要有静态 / 淡出降级路径
  （engine 已有 `prefersReducedMotion` / `respectReducedMotion`，直接用）。
- 深色壳 / 浅色壳（若有）下都要检查一遍对比度。

## 八、法律红线（沿用 1.2 第八节全量，另加视觉项）

- 1.2 主管文档第八节黑名单**原样生效**（`地铁跑酷` `超级玛丽` `马里奥` `蛋仔` `宝可梦` 等，
  见 [`plan-1.2-supervisor.md`](./plan-1.2-supervisor.md)），扫描含代码注释。
- 1.3 追加**视觉侧红线**：不复刻任何商业游戏的角色剪影、标志性配色组合（例如某跑酷主角的具体套装配色）、UI 商标元素；
  「对标观感」只许对标**质量等级**（层次、光影、动效丰富度），不许对标**具体形象**。
- 商标扫描命令统一为：`rg -i "<黑名单>" src/ README.md --glob '!.cursor/skills/**'`。
  扫描对象是**代码、注释与孩子可见文案**；提示词文档（`docs/plan-1.3-*`）里引用黑名单本身不算命中；
  `.cursor/skills/` 是 vendored 第三方文档（保持原文，含上游示例文件名），**排除在扫描外**。
- 素材许可：1.3 不提交位图 / 字体 / 音频等二进制素材，全部矢量代码化（Canvas 2D 绘制函数），从源头杜绝素材侵权与包体膨胀。

## 九、素材契约测试（测试水位只升不降）

视觉步不许「改了就跑」，每步要加**素材契约测试**，且不许删旧测试、不许调低断言：

- 角色绘制函数存在且可调用：给一个 stub 的 2D context，调用后**有绘制调用发生**（fill/arc/path 计数 > 0），不抛异常。
- 关键常量契约：金币半径 > 0、高光偏移存在、调色板色值合法（`#rrggbb`）、动画帧数 ≥ 约定值。
- 双人款：A/B 角色主色不相等（直接断言色值不同）。
- reduced-motion：降级分支可达（传入 reduced=true 时不产生震屏 / 粒子调用）。
- 每个视觉步**新增 ≥ 8 例**；第 1 步三份基建各 ≥ 16 例。用例总数写回登记表作为下一格水位。

## 十、每款游戏的「深度审美评测 + 改进方案」

第 2–26 步每一格开工前，执行子代理必须先在自己那份回复（与 step 文档要求的报告）里交出：

1. **审美评测**（≥ 8 条）：对照本宪法二至七节逐条打分（现状哪里是火柴人 / 色块 / 无反馈 / 无纵深）。
2. **极高质量改进方案**：列出要重画的实体清单（角色 / 收集物 / 障碍 / BOSS / 背景层）、
   各自用共享 kit 还是独占绘制、2D/2.5D 定级、动效清单、reduced-motion 降级、素材契约测试清单。
3. 方案先行、代码在后；主管抽查方案与成品不符的打回。
