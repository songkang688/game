## 一、现状审美评测（基于 origin/game-1.2 真实代码，`src/games/fruit-stack/index.ts`）

打分制：草稿 / 能认 / 可爱 / 精美。

| 对象 | 现状代码 | 评分 | 问题点名 |
|---|---|---|---|
| 果子（核心资产） | `drawFruit()` 第 398–427 行：纯色圆（`kind.color`）+ 描边（`kind.edge`）+ 一个白高光 + 通用「一片叶子加一根短梗」（415–425 行） | **能认** | 11 级果子**只靠颜色和大小区分**：没有西瓜纹、橘子瓣、草莓籽，更没有脸；合成链的「进化感」全靠脑补 |

结论：物理与交互（吸合、影子、警戒线、aria）都在线，唯独果子本身是「彩色圆」。**给 11 级果子做出各自的脸和纹理是本步核心。**

## 二、极高质量改进方案（可执行绘制规格）

### 1. 果子 → 11 张有脸的果卡（核心资产）

- 每级果子专属纹理 + 统一的脸（闭眼微笑两弧 + 小腮红），全部在 `drawFruit` 内按 `level` 查表绘制，**预渲染 11 张 offscreen sprite**（按当前最大半径缓存，`drawImage` 缩放使用；合并动画的 `scaleK` 直接缩放贴图）：
  - 樱桃：双圆连梗；葡萄：3 圆簇 + 白霜点；橘子：橙圆 + 顶部蒂 + 4 条淡瓣线；柠檬：椭圆 + 两端尖 + 皮孔点；桃子：心形裂缝 + 渐变腮；苹果：红圆 + 高光条 + 叶；梨：上窄下宽双圆融合；哈密瓜：网纹（浅色随机短弧 8 条）；菠萝：菱形网格 + 顶叶 5 片；椰子：棕圆 + 3 个脸点；西瓜：深浅绿条纹 8 道 + 顶蒂——**必须一眼认出是什么果**；
  - 主体一律径向渐变（左上高光 → 边缘压暗 10%）+ 底部环境影；现有白高光和叶子规格保留。
- 脸的状态：正常＝微笑；堆到警戒线附近（`nearLine` 为真）＝全体果子睁眼担忧脸（两点眼+皱眉）——把警戒反馈做到角色身上。

### 2. 果盆 → 陶瓷果盆

- 三线盆壁改为：盆沿 6px 圆角厚边（顶面亮粉高光条）+ 内壁两侧 4px 渐变阴影 + 盆底内凹弧线；背景渐变保留但顶部加两朵淡云装饰；
- 警戒线保留现有闪烁逻辑，加左端小警示灯图标（红点+光晕，`reduced` 不闪）。

### 3. 合并 → 爆汁升级

- 吸合动画（494–501 行节奏不动）末帧叠加：接触点迸 4–6 滴果汁粒子（新果同色系，0.3s 抛物线下落淡出，对象池 ≤ 20）+ 新果出生时一圈白色扩散环（0.25s）；
- 合成前 3 大级（菠萝/椰子/西瓜）：额外金星 2 颗 + 「+分数」飘字放大版；
- 合成西瓜（顶级）：全盆轻震 1 次（translate 2px，`reduced` 关）+ 彩虹光环一圈。

### 4. 下一颗预览

- `refreshNext` 的预览区改为「果篮窗口」：木篮框 + 当前/下一颗两格（下一颗半透明），用同款 sprite。

### 5. 结算

- 结算面板：本局最大果 sprite 大图 + 合成树进度条（11 级点亮到第几级）+ 分数；双人模式两盆各自展示最大果对比。

## 三、2D / 2.5D / 3D 决策

**保持 2D 正视**（合成物理玩法规范）。立体感 = 果子径向渐变 + 盆沿厚度；物理帧率优先，sprite 预渲染是硬要求（11 种果 × 60fps 不许逐帧画纹理）。禁止 three.js。
