## 四、1.2 玩法升级

| 项 | 规格 |
| --- | --- |
| **`index.ts` 拆分（硬性）** | 630 行必须拆：把每种任务的判定逻辑抽到 `tasks.ts`（纯函数，输入状态 + 操作，输出新状态与是否完成），把猫的状态机抽到 `cat.ts`，`index.ts` 只留挂载与渲染。**拆完的纯函数全部补单测。** |
| **任务差异化** | 七种任务必须有七种手感，不许「点 N 下」换皮：喂饭 = 选对食物并拖到碗里（有猫不爱吃的食物）；逗猫 = 逗猫棒轨迹要让猫追上（追随 + 扑）；洗澡 = 画圈搓泡泡（覆盖率 ≥ 90%）；哄睡 = 按节奏点音符（节奏对了才睡）；打扮 = 拖拽配饰到吸附点；看病 = 按症状选检查再选处置（分步，选错可回退）；搭配 = 按给定主题词选三件，按规则表评分。 |
| **心情值改造** | 掉到 0 **不重来**，改为「猫躲进纸箱，安抚 3 次就出来」，本关最高星降一档但能继续。**不许出现「照顾失败」的挫败结局。** |
| **双猫目标锁定** | 双猫关点某只猫先「选中」（有明显高亮 + 名字），操作只作用于选中的猫；喂错猫不惩罚，只是猫摇头，重新来。 |
| **看病内容安全** | 症状只用「打喷嚏 / 没胃口 / 爪子上有小刺 / 毛打结」这类轻症；处置只有「喝水 / 保暖 / 拔小刺 / 梳毛 / 带去看医生」。**不许出现打针、吃药剂量、流血、手术、生病严重后果**；也不许暗示孩子可以自己给动物治病——每关结尾加一句「拿不准要找大人和兽医」。 |
| **搭配评分透明** | 评分规则写死成一张表（主题词 → 加分标签 / 减分标签），评分后**逐条列出为什么加分为什么减分**。规则表 + 评分函数纯函数化 + 单测。 |
| **长线养成（新增）** | 跨关卡的「小屋相册」：完成关卡随机解锁一张团团的照片/一件家具（共 24 件），可在小屋里摆放。**全部用星星解锁，不引入任何货币或抽卡**；进度存本地 key 走 `yiduo-yixing.` 前缀。若平台的 `collection.ts` 收藏册已合入 `game-1.2`，**优先动态 import 复用它并带 try/catch 降级**，没合入就本地实现，不要改共用文件。 |

## 五、模式矩阵

`campaign` 188 保留（**前 99 关生成参数不改**）。**新增 `endless`「照顾马拉松」**：任务连续出现，每完成一个进下一个，节奏（时限、同屏猫数、任务复杂度）随进度上升；**没有失败结局，超时只是本轮不计分**；成绩走 `save.recordEndlessBest("kitty-care", n)`。`meta.modes` 同步加 `"endless"`。对战不做。

## 六、2.5D / 3D 决策

**保持 2D**。小屋可用轻微的斜视角背景（伪纵深），但交互层必须是正交 2D，拖拽落点一眼可读。

## 七、视觉 · 建模 · 手感

- 猫要有表情状态（开心 / 好奇 / 困 / 委屈 / 躲），每个状态有呼吸起伏与尾巴摆动的循环动画。
- 摸猫会呼噜（低频轻音），洗澡泡泡有物理感的破裂。
- 完成任务：爱心飘出 + `api.play("win")`；做错**只让猫歪头**，不出现难过或哭泣的表情。
- **绝不出现动物受伤、瘦弱、被打、流血、死亡**；也不出现催促式的红色倒计时。
- `prefers-reduced-motion`：关呼吸、尾巴与飘心动画，保留状态切换。

## 八、手机 360px

- 拖拽物体与吸附点热区 ≥ 48px；双猫关两只猫的点击区不重叠。
- 洗澡的搓泡泡区域至少 240×240px；任务提示条固定顶部不遮猫。
- 相册与家具摆放界面在 360px 下用两列网格，缩略图 ≥ 100px。
