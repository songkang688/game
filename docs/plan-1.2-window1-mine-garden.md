# 窗口 1 · 5B `mine-garden`「扫雷花园」工作计划

规格：`docs/plan-1.2-step5-B-mine-garden.md`；红线：`docs/plan-1.2-supervisor.md` 第八、九节；
窗口所有权：`docs/plan-1.2-window1.md`（本款目录 `src/games/mine-garden/**` 归窗口 1 独占）。

## 一、题材口径（先定死，写代码时逐字照抄）

- 藏在土里的是**刺种**（带刺的种子），不是别的东西。
- 翻到刺种叫**踩到刺种**，表现是「这颗种子当场开出一朵花」，其余刺种温柔揭开，
  一朵一朵慢慢冒出来，**不做连环炸开式表现、不做红屏、不用惊吓音效**。
- 插小旗叫**插旗**，拔掉叫**收旗**；把整片地翻完叫**扫种完成**。
- 可见文案、按钮、提示、攻略、结算语一律只用「刺种 / 扫种 / 插旗 / 开花」，
  **不出现「地雷 / 爆炸 / 炸 / 战争 / 伤亡」任何一个字**；内部函数名允许叫 `mine`（不可见）。
- 不出现任何系统自带或商业扫雷软件的名字，注释里也不许。

## 二、无猜生成策略（本款最核心的一段，先讲清楚再写）

### 2.1 玩家模型求解器 `solveLogically`

求解器**只用玩家看得见的信息**推理，逐轮跑下面四级规则，能推出一格就继续，一轮全推不动才算卡住：

1. **平凡规则**：某个已翻开数字格，`数字 − 周围已知刺种数 == 0` → 周围未知格全安全；
   `数字 − 周围已知刺种数 == 周围未知格数` → 周围未知格全是刺种。
2. **子集规则**：两条约束 `A ⊆ B` 时，`B\A` 的刺种数 = `nB − nA`，再对差集套平凡规则。
   这一步只是加速，不加新推理能力。
3. **全局剩余数规则**：剩余刺种数为 0 → 场上未知格全安全；剩余刺种数 == 未知格数 → 全是刺种。
4. **约束求解器（完整枚举）**：前三级都推不动时启动。
   - 把「所有挨着已翻开数字格的未知格」按约束连通性切成若干**连通分量**；
   - 每个分量单独回溯枚举全部满足约束的布种方案（分量 ≤ `MAX_COMPONENT` 格，
     节点数超过 `NODE_BUDGET` 就放弃该分量，宁可判卡住也不瞎猜）；
   - 枚举时按「分量内刺种总数 k」分桶，给每格记两张位掩码：
     `mineMask`（存在 k 使得该格是刺种）与 `safeMask`（存在 k 使得该格安全）；
   - 再对「各分量的可行 k 集合 + 分量外未知格」做一次**子集和 DP**，
     算出全局真正可行的 k 掩码 `okMask`（这一步把经典残局「剩几颗刺种」的信息也算进去）；
   - `mineMask & okMask == 0` 的格判定为**一定安全**，`safeMask & okMask == 0` 的判定为**一定是刺种**；
   - 分量外未知格：全局 DP 说分量外刺种数只能是 0 → 全安全；只能是满额 → 全是刺种。

求解器**不做任何概率猜测**。一轮下来一格都推不出来，就返回 `solved:false` 并带上卡住的前沿格清单。
`isLogicallySolvable(board, firstClick)` 就是「跑完之后所有非刺种格都被翻开」。

### 2.2 生成器 `generateNoGuess`

首点位置是玩家点出来的，所以**刺种一律在第一次翻开之后才布**（这同时天然满足首点及 8 邻格必安全）：

1. `placeMines(w, h, n, safeIndex, seed)`：从「除首点及其 8 邻格以外」的候选格里做部分洗牌取 n 格。
2. 跑 `solveLogically`。全部翻开 → 直接采用。
3. 卡住 → **局部修补**：把卡住前沿附近的一颗刺种，和远处（安全区外、非前沿）的一颗空地对调，
   再解一次。修补比整盘重洗收敛快得多。
4. 连续修补 `REPAIR_RUN` 次仍不行 → 换派生 seed **整盘重洗**，回到第 2 步。
5. 总预算（重洗次数 / 修补次数 / 求解器节点数）全部写成常量并可传参。
   预算烧完还没成 → **降级**：返回最后一版棋盘并把 `noGuess` 标成 `false`，
   宁可这一盘偶尔要蒙一下，也绝不卡住界面（生成永远有限时间返回，绝不白屏）。

第 3 章起（第 49 关起）每一关都要 `noGuess`。测试对 **≥ 50 个 seed** 断言生成结果 `noGuess === true`
且 `isLogicallySolvable` 为真；另外对第 3–8 章抽样关卡断言同样的结论。

## 四、四种模式

| 模式 | 做法 |
| --- | --- |
| 闯关 188 | 走 `level99.ts` 的 `mountLevelGame`，尺寸密度递增，后期加限时 / 限旗 / 迷雾 |
| 竞速对战 | 同一张图、同一个 seed，朵朵和四档假人比谁先扫完 |
| 无尽清盘 | 连续清盘，每清一盘密度 +1，`save.recordEndlessBest` 记最高连清 |
| 双人同屏 | 两张同 seed 的图左右分屏，朵朵 `WASD+F+G`，星星 方向键 `+L+K` |

## 五、AI 四档与断言

| 档 | 行为 |
| --- | --- |
| 菜鸟 | 随机点未开格 |
| 普通 | 只点平凡规则能确定安全的格，没有就随机 |
| 高手 | 「数字 − 旗数」推导 + 会插旗，没有确定格才随机 |
| 地狱 | 会和弦、直接用 `solver.ts` 的约束求解，几乎不踩刺种，最快 |

固定 seed 下 `地狱档用时 < 菜鸟档用时`（而且差距明显）写成断言。

## 六、键位与手机

- 左键 / `F` 翻开，右键 / `G` 插旗，`WASD` 或方向键移光标，`Esc` 暂停。
- 双人同屏：星星用 方向键 + `L` 翻开 + `K` 插旗。
- 触屏：点一下翻开，长按插旗（阈值 `LONG_PRESS_MS` 写成常量、设置里可调），长按有进度环。
- 360px：格子 ≥ 28px，放不下就横向滚动 + 迷你地图；HUD 字号 ≥ 13px。
- `prefers-reduced-motion`：翻开动画缩到最短。
