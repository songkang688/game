## 四、1.2 玩法升级

| 项 | 规格 |
| --- | --- |
| **战斗数值透明化** | 把攻击 / 防御 / 幸运的结算写成一个纯函数 `resolveFight(attacker, defender)`，并在 UI 里给「打得过 / 有点悬 / 打不过」的三档预判提示（**不给具体数字**，保持探索感）。 |
| **成长三线** | 等级（关内）、装备（关内掉落）、收藏册加成（跨游戏、只读）三线各司其职；写断言：满级 + 满收藏的总增益不超过基础值 +35%（与 `collection.ts` 上限一致，不许自己突破）。 |
| **迷宫生成** | 若是生成的，必须有「起点到终点连通 + 钥匙在门前可达」的校验（随机 2000 张全部可解，写断言）；若是手工关，抽样验证并补 20 张新图。 |
| **无尽「无尽之路」** | 楼层递增、每 5 层一个休息点（三选一补给）；成绩 `save.recordEndlessBest("brave-path", floor)`。 |
| **对战** | `versus` 做成「同一张迷宫，谁先到终点」的异步竞速（和对手幽灵跑），做不了就从 `modes` 删掉并写明理由。 |

## 五、模式矩阵

三模式保留（前提是都能玩到结算）；闯关 **前 99 关数据不改**。

## 六、2.5D / 3D 决策

**保持 2D 俯视**。可加地面高低差描边与轻投影，**不做真 3D**。

## 七、视觉 · 建模 · 手感

- 战斗是「撞一下 + 星星火花 + 数字浮动」，**无血无伤**；敌人退场是「变成小云朵」。
- 拾取装备要有换装即时反馈（角色外观真的变）。
- 迷宫探索有已走路径淡色标记（防止孩子迷路）。
- `prefers-reduced-motion`：关抖动。

## 八、手机 360px

- 摇杆或点触移动二选一（默认点触），热区 ≥ 44px；背包面板从底部弹出，可滚动。
- 状态栏（等级 / 装备 / 钥匙）一行显示，字号 ≥ 14px。
