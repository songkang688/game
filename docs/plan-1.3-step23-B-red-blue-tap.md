## 三、现状审美评测（先开代码再动笔）

打开 `src/games/red-blue-tap/index.ts` 与 `arena.ts`，渲染入口是 `paintPad` / `renderScore` / `renderTop`（arena.ts）与 `renderTop`（index.ts）。已核实的问题：

1. `paintPad` 的按垫预期就是纯色 DOM 按钮（自查 CSS 确认）：反应类游戏一屏就两块大色板，色板却没有任何质感——无渐变、无按下形变、无波纹，「点」的爽感为零；
2. `renderScore` / `renderTop` 预期是「emoji + 文本」裸排（对照 `red-blue-tug` 853–856 行同风格），比分没有对抗仪式感；
3. 出题提示（哪边该点 / 什么信号点）的视觉强度自查：反应游戏的信号必须一眼炸出来，把现状对比度与尺寸结论记进开工 commit；
4. 点对 / 点错 / 抢点的反馈差异自查（预期只有文本变化）；
5. 双人分区（上下或左右）的边界视觉自查。

## 四、极高质量改进方案（绘制规格）

| 项 | 规格 |
| --- | --- |
| **果冻按垫（核心）** | 两块按垫改果冻质感：径向渐变（中心亮 → 边缘深 12%）+ 顶部弧形高光带 + 2px 深色描边；按下时 squash（scale 0.94 + 底部压扁，60ms 回弹）+ 触点波纹圆扩散（240ms）；正确点击波纹是金色星环、错点是灰色淡纹（不刺眼不批评）。**按垫热区一个像素都不动。** |
| **信号灯剧场** | 出题信号区升级为中央大信号灯：待机灰 → 预备黄呼吸 → 出题瞬间对应色爆亮 + 外圈光环一闪（120ms）；干扰信号（若有）用形状差异（三角 vs 圆）双通道，不只靠颜色。**出题时机与判定窗口逻辑一律不动。** |
| **对抗氛围** | 场地中线画对抗分界（红蓝渐变相接 + 中央小闪电标）；领先方那一侧背景轻微亮 4%（读比分只做映射）；连对 3 次按垫边缘流光一圈。 |
| **比分仪式** | `renderScore` 升级为中央计分牌：翻页数字动画（120ms 翻转，reduced 瞬换）+ 红蓝双侧小旗；每回合结算时得分方按垫放星屑 5 颗。 |
| **反应时间可视化** | 每次点击后在按垫上方冒出反应耗时小气泡（读既有统计值），快于上次时气泡带小闪电——纯展示不改统计。 |
| **布局与 HUD** | `renderTop` 卡片化（回合 / 最佳反应 / 规则提示）；开局倒计时 3-2-1 做成大号弹跳数字（reduced 静止渐隐）。 |

- 色板走 `src/art/kit/palette.ts`；星屑走 `sparkle.ts` 的 CSS 等价。
- `prefers-reduced-motion`：squash、波纹、流光、翻页全停，保留静态层次与信号变色（反应信号本体不减弱）。
