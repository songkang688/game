# 1.2 多人多窗口派发登记表

> 用户可能同时开多个窗口派发云端子代理。**派之前先读本表，派的时候改本表，推完再改本表。**
> 权威步数与独占路径见 [`plan-1.2-supervisor.md`](./plan-1.2-supervisor.md)。人类目录见 [`plan-1.2-index.md`](./plan-1.2-index.md)。
>
> 旧目录 `docs/game-1.2/` 已作废，不要把旧 step-01 / step-10 / step-30 登记进本表。

---

## 使用说明

1. **先看再派。** 打开本文件，找到要派的 `stepN-X` 那一行。状态不是「空闲」或「失败重做」就**不要派**。
2. **同一 `stepN-X` 不能派第二次**，除非该行状态已改成「失败重做」，并在「备注」写清失败原因（测试红、越界改文件、推送被拒且无法 rebase、执行者中途消失等）。
3. **一步三人必须一起派。** 不要只派 A 就去派第 N+1 步。任何时刻执行线上应有 **3 个**子代理在跑（当前步的 A/B/C）。
4. **派的时候改四列：** 状态 → `已派`；谁在管 → 窗口名或人名占位（例如 `窗-北` / `alice`）；开始时间 → ISO 本地时间；分支 → 执行者即将使用的工作分支名（还没开就先写 `待开`）。
5. **子代理回报开工后：** 状态 → `进行中`，补上真实分支名。
6. **推上 `origin/game-1.2` 后：** 状态 → `已推`，在备注贴 SHA。三人全是 `已推` 且 `npm test` / `npm run build` 绿了，才允许把下一步三行从空闲改成已派。
7. **多窗口冲突。** 两个窗口同时把同一行改成「已派」= 重派。后改的窗口必须立刻停掉自己的子代理，把该行恢复成先到者的记录。
8. **不要用本表讨论玩法。** 玩法写在 `docs/plan-1.2-stepN-X-*.md`。本表只登记调度。
9. **本表可以和提示词一起改，但不要在执行步里让三个子代理同时编辑本文件。** 登记是派发窗口的事。若必须由执行者回报，只许改自己那一行。

状态枚举（只准这五个词，不要自创）：

| 状态 | 含义 |
| --- | --- |
| 空闲 | 还没人派 |
| 已派 | 提示词已发出，子代理可能还在拉分支 |
| 进行中 | 子代理已开工（已有计划 commit 或已在改文件） |
| 已推 | 已普通推送到 `origin/game-1.2`（禁止 force） |
| 失败重做 | 明确失败，允许同一 `stepN-X` 再派一次 |

```md

```

## 防重复规则（写给窗口）

- 主键是 `step + 档`，例如 `1-A`、`15-C`、`28-A`。第 28/29/30 步的 tester 是**三行不同的主键**（步号不同），不是同一行。
- 已推的行禁止改回空闲。若线上被 revert，把状态改成「失败重做」再派。
- 提示词文件还没落地（备注写着「B/C 尚未写提示词」）时，**禁止派执行子代理去写游戏代码**。先让 B/C 把对应 `docs/plan-1.2-stepN-*.md` 推上 `game-1.2`。
- 第 1 步三档提示词已由主管写完，可以派；但仍须先把 `origin/game-1.1` @ `8867138` 合入 `game-1.2`。
