## 一、现状审美评测（基于 origin/game-1.2 真实代码，`src/games/sudoku-petal/index.ts`）

打分制：草稿 / 能认 / 可爱 / 精美。

## 二、极高质量改进方案（可执行绘制规格）

### 1. 棋盘 → 花田畦

- 棋盘外框 8px 木篱笆边框（竖条纹渐变 + 顶部圆头桩，CSS border-image 或伪元素）；
- `REGION_TINTS` 保留色相但统一降饱和提亮（花田畦感：每宫是一块「花圃」），宫界 `regionEdgeShadow` 线色 `#8874BE` 改深木色并加 0.5px 高光伴线（田埂感）；
- 背景 wrap 加上下渐变（晨光米黄→淡绿）+ 角落两丛小花装饰（静态 SVG）。

### 2. 数字 → 花瓣数字（核心资产）

- **题面数字（given）**：深色衬线感排版 + 底部一小片叶子衬托（SVG 叶片，颜色随宫色），表示「原生长好的」；
- **玩家填的数字**：填入瞬间数字从花苞展开（0.25s：花苞 SVG → 数字浮现 + 2 片花瓣散开），数字色用主题紫 `#6B5AA0`；
- **正确完成一个数字的九宫身位**（`sp-key-done` 触发时）：对应数字键上开一朵小花；
- 铅笔小字保留纯文本（信息密度优先，不加装饰）。

### 3. 状态反馈升级（保留全部 7 态语义）

- `sp-peer`（同行列宫）：底色改极淡水纹；`sp-same`（同数字）：花瓣形高亮圈替代方块高亮；
- `sp-bad`（冲突）：红底之外加 0.3s 摇头动画（translateX ±2px×2，`reduced` 关）+ 枯叶小图标；
- `sp-hint`（技巧提示焦点）：金色呼吸描边（`reduced` 静态金边）；`hintBox` 加小灯泡 SVG 前缀；
- `sp-cur` 光标：圆角粗框 + 四角小三角（键盘玩家可视性）。

### 4. 完成仪式 → 花田盛开

- 完成一宫：该宫 9 格依次冒小花瓣（每格 30ms 错峰，0.4s 总长）；
- 完成整题（`bloom()`）：从中心向四周波纹开花（每圈延迟 50ms，格子短暂翻转成花朵再翻回数字），顶部飘 10 片花瓣（对象池，`reduced` 时只显示一朵大花）；
- 双人/对 AI 模式：对手完成时其棋盘缩略图上放小礼花（区分你/他配色）。

### 5. HUD 与结算

- 数字键 `sp-key` 改成小木牌造型（顶部挂绳），用完的数字木牌翻转背面显示小花；
- 结算面板：用时 + 提示次数 + 「花田收成」插画（几朵花 = 剩余提示次数）。

## 三、2D / 2.5D / 3D 决策

**严格保持 2D**（数独规范）。立体感只用于木篱笆边框与木牌按钮；数字区必须平整清晰（可读性 > 装饰）。禁止 three.js。DOM 架构保留（aria-label 逐格、键盘光标依赖）。
