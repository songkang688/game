## 一、要做成什么

双人合作解谜闯关，走 `src/games/level99.ts` 的 188 关通用框架。

- **冰灵·凛凛**：踩得了冰水潭，进不了岩浆池。
- **火灵·焰焰**：踏得了岩浆池，进不了冰水潭。
- **绿黏液**：两个人都过不去。
- **过关条件**：两人必须同时站在各自的门上（冰门 + 火门），少一个都不算。

## 二、为什么做成「回合式格子」而不是横版跳跃

第 8 步的硬性验收里有一条：**全部 188 关都要有自动可解性验证**。
连续物理的横版跳跃没法穷举验证；格子世界可以把整局游戏压成
「(凛凛格号, 焰焰格号, 拉杆状态)」这么一个整数状态，直接 BFS 穷举，
既能证明每一关都有解，又能顺手算出最优步数当三星标准。

所以：**俯视格子 + 实时逐格移动**。两人各自有移动冷却，可以同时走；
但求解器只按「一次动一个人」搜索——这样搜出来的解在实时里必然也能照着走，
是个偏保守的证明。

## 五、关卡生成怎么保证「一定有解」

1. 关卡骨架是「若干段 + 中间几道屏障」：两人都从最左段出发，出口都在最右段。
2. 每道屏障是一条竖墙，只留 2～3 个通口；通口的花样决定这一道的谜题类型
   （直通 / 冰火分道 / 踏板闸门 / 拉杆闸门 / 跷跷门 / 传送带 / 光门 / 托举高坎）。
3. 段内永远保留一条打通的「主脉」空地，宝石与机关摆在主脉旁边的口袋里。
4. 生成器是纯函数（`mulberry32(seed)` 确定性），生成完立刻跑 BFS 验证；
   不通过就换种子重来（有上限，最后兜底一张必然可解的简版）。

## 六、单人也能玩

`Tab` 切换当前操控的角色；单人模式下两套键位都控制当前这一位。

双人键位（与全局约定一致）：

- **朵朵位 → 凛凛**：`W A S D` 移动，`F` 元素之力，`G` 击掌。
- **星星位 → 焰焰**：`↑ ← ↓ →` 移动，`L` 元素之力，`K` 击掌。
- `Esc` 暂停；手机上左右半屏各一套虚拟方向键 + 动作键。

「元素之力」：凛凛把相邻一格岩浆冻成冰桥、焰焰把相邻一格冰水烤干，每关限量；
两人相邻时按击掌键回一次。它只会让关卡变简单，所以不影响可解性证明。
