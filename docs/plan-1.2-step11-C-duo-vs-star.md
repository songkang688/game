## 四、1.2 要做的事（平衡优先，量化说话）

| 项 | 规格 |
| --- | --- |
| **平衡表** | 用固定 seed 跑角色对角色的循环赛（每对 ≥ 20 局），把胜率矩阵写成测试固定值 + 报告表格；任何角色总胜率必须落在 **40%–60%**。超出就调数值，调完重跑。 |
| **击退曲线** | 抽成纯函数并画出「元气 → 击退距离」的分档表；封顶，避免一击出界。低元气时给 0.4 秒挣扎窗口。 |
| **道具公平** | 刷新点镜像对称或轮流靠近；强道具改成「需要蓄力才生效」。 |
| **合作模式** | `coop` 要有真正的配合点（一人顶举、一人接应），不是两个人各打各的。至少 3 关专门教配合。 |
| **战役 188** | 不改关卡数据结构，只修「后段靠加数值堆难度」的关：改成新行为（会绕后 / 会抢道具 / 会等你出招）。 |

## 五、模式矩阵

五种模式全部保留；本步不新增模式。无尽成绩统一 `save.recordEndlessBest("duo-vs-star", n)`；旧 key 若存在读一次迁移。

## 六、2.5D / 3D 决策

**保持 2D 平台视角**。击退与出界的判定必须一眼可读，透视会骗人。

## 七、视觉 · 建模 · 手感

- 出界演出：变成小星星飞走 + 回到场边（**不是死亡**）。
- 元气条颜色 + 数值双通道显示（色觉友好）；濒危时角色轻微发光而不是闪红。
- 命中顿帧 ≤ 6 帧，`prefers-reduced-motion` 下为 0。

## 八、手机 360px

- 左右半屏控件互不重叠、热区 ≥ 44px；四人 HUD（若有 AI 队友）在窄屏折成两行且不遮角色。
- 角色名过长要缩写，禁止横向溢出。

## 九、平台接线

- 战役 `openCampaignLevel(n)` / `initialLevel` / `?level=N` 直开第 N 关；Skip 走 `requestSkip`，本关 0 星并解锁下一关。
- `meta.platform` 按实测填；`blurb` 与事实对齐。

## 十、独占文件与冲突
