# 🍐 鸭梨康康 · 1.2-kk 说明

> 这是 `game-1.2` 的一个**换人物分叉**：游戏、关卡、数值、存档全都不动，只把两位小主角
> 从「朵朵 / 星星」换成「**鸭梨 / 康康**」，产品名从「一朵一星」换成「**鸭梨康康**」。
>
> - 基线分支：`game-1.2`
> - 本叉分支：`1.2-kk`（对外版本号 **1.2-kk**，`package.json` 里写 `1.2.0-kk`）
> - 老玩家的进度**不会丢**：存档 key 仍然是 `yiduo-yixing.*`，一个字没改。

## 一、改了什么

| 面 | 改动 | 谁负责 |
| --- | --- | --- |
| 品牌与头像 | 首页标题、logo、欢迎气泡、`src/ui/avatars.ts` 与头像 PNG 换成鸭梨 / 康康 | 档 A |
| 游戏内文案 | `src/games/**` 里出现的人物名、双人对战 P1/P2 的称呼、攻略与说明文字 | 档 B |

### ⚠️ 「星星」这个词有两种意思，只改其中一种

- **角色名的星星** → 改成康康。例：欢迎气泡、双人对战的选手名、剧情文案。
- **评分 / 货币的星星** → **不改**。三星评级、星星余额、小屋里用星星解锁人物宠物装备，
  这套体系跟角色无关，名字继续叫「星星」，图标继续是 ⭐。

所以下面这些游戏标题里的「星星」是**道具或分数**，保持原名：

`星星消消乐`、`星星合成`、`音乐星星`。

最后一条是**唯一一处需要解释的**：这个靶场原本按「星星」命名，档 B 落地时判定它指的是

装填提示、攻略文案、评分星星一个字没动，只有场子的主人换了名字。

README 的游戏清单与 `src/games/*/meta.ts` 的 `title` 已逐条对齐（76 对 76，不多不少）。
以后改名先跑这条核对：

```bash
rg -o 'title: "([^"]*)"' -r '$1' src/games/*/meta.ts | sort
```

## 三、存档与安装包身份：故意不改

改名只是**显示层**的事，凡是会让老玩家丢进度、或者让新包装不上旧版的标识一律保持原样：

| 项 | 值 | 为什么不改 |
| --- | --- | --- |
| localStorage 前缀 | `yiduo-yixing.` | 改了等于清空所有人的进度 |
| 总存档 key | `yiduo-yixing.save.v1` | 同上 |
| 关卡星级 key | `yiduo-yixing.l99.<游戏id>` | 同上，188 关的数组照旧 |
| 收藏册 key | `yiduo-yixing.collection.v1` | 同上 |
| Electron `appId` | `com.yiduoyixing.hub` | 改了 Windows / macOS 会当成另一个应用，装出两份 |
| 安卓 `package_name` | `com.yiduoyixing.hub` | 改了老 APK 无法覆盖升级 |
| npm 包名 `name` | `yiduo-yixing` | 私有包，只影响产物文件名前缀 |
| 安装包文件名前缀 | `yiduo-yixing-<版本>-…` | 与 README 下载表、发版工作流一致 |

一句话：**用户看到的名字变了，机器认的 id 没变。**

## 四、怎么构建

需要 Node.js ≥ 22（建议 22.14+）。

```bash
git fetch origin 1.2-kk
git checkout 1.2-kk
npm install
npm test          # vitest,CI 里用 npm test -- --testTimeout=30000
npm run build     # tsc --noEmit + vite build,产物在 dist/
npm run preview   # 本地预览构建产物
```

出各端安装包、PWA 部署步骤、以及本轮实际的测试 / 构建记录，见
[`docs/release-1.2-kk.md`](./release-1.2-kk.md)。

  不直接合进 `game-1.2`，更不碰 `main`。

  不要用一侧整体覆盖另一侧。
