### 2.4 命名与法律红线（全体适用，违反即打回）

- 面向孩子的任何可见文案（`title` / `blurb` / 章节名 / 角色名 / 提示语 / 攻略文案）**一律原创中文**，**禁止出现任何商业商标或官方角色名**（例如「愤怒的小鸟」「植物大战僵尸」「水果忍者」「地铁跑酷」「森林冰火人」「屁王兄弟」「拳皇」「超级玛丽」「割绳子」等等，一个都不许出现，注释里也不许）。
- 内部研究原作玩法是允许的（用户说明是自己玩、非商业发行），但**研究结论只许体现为玩法结构**，**不许把原作名字、角色、素材、配色标识带进代码或文案**。
- 角色统一用本作原创形象：**朵朵**（小花）、**星星**，以及既有的糯糯 / 云云 / 墩墩 / 闪闪 / 绿绿豆 / 啾啾。

### 2.5 年龄定位（全体适用）

- 目标读者从「一年级」上移到 **约小学六年级**：
  - 文案不要过于低幼（去掉「宝宝」「乖乖」「小笨蛋」这类词，也不要滥用叠词到肉麻），但**保持中文粉彩萌系**的整体调性，emoji 与配色不变。
  - 句子可以更长、更有信息量，允许出现「连击」「命中率」「回合」「资源」「策略」这类词。
  - 每款游戏都要能回答三个问题：**能闯关吗？能对战吗？能无尽吗？**（不适用的写明理由）。

### 2.6 第 1 步产出的公共契约文件（第 1 步三人都要用；后续各步只读）

第 1 步的 A / B / C 都需要这个文件。**三人都必须在自己的分支里创建这个文件，内容逐字一致**（内容完全相同的新增文件在 rebase 时会被自动跳过，不会冲突）：

`src/ui/level188Contract.ts`

```ts
/**
 * 1.1 新增：188 关框架 与「家长跳关」「攻略侧栏」之间的契约。
 * 只放类型与运行时注册表，不 import 任何 UI / 玩法代码,三方都能安全依赖。
 */
export interface GuideEntry {
  /** 覆盖的关卡区间(1 基,含两端) */
  from: number;
  to: number;
  title: string;
  tips: string[];
}

export interface GuideBook {
  gameId: string;
  title: string;
  /** 通用攻略:任何关都适用的几条 */
  general: string[];
  entries: GuideEntry[];
}

export interface LevelExtras {
  /** 在 host 里挂「攻略」按钮并接管面板,返回清理函数 */
  mountGuide?: (host: HTMLElement, book: GuideBook, getLevel: () => number) => () => void;
  /** 请求跳关授权(家长高权限门);resolve(true) 才允许跳关 */
  requestSkip?: (gameId: string, level: number) => Promise<boolean>;
}

let extras: LevelExtras = {};

/** 由壳层在启动时注册实现;未注册时框架自动隐藏攻略与跳关入口 */
export function registerLevelExtras(next: LevelExtras): void {
  extras = { ...extras, ...next };
}

export function getLevelExtras(): LevelExtras {
  return extras;
}

/** 仅供测试:清空注册 */
export function resetLevelExtras(): void {
  extras = {};
}
```
