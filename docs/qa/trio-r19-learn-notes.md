## 七、skills / 方法论摘记（收口轮沉淀）

- **可达性判据补进量法**：r4–r18 只报 top/bottom 会把「滚得到的初见出屏」和「滚不到」混在一个 🔧 桶里；本轮 34 个态里 outs 总数 153，其中**真滚不到的只有 N-108 一处 9 个元素**。收口教训：`scrollIntoView 后 reach` 应成为 r19+ 工装标配，能把号量压掉一个数量级。
- **`.l99-host` overflow:hidden 第 4 次复发**（N-75 → N-98 → N-101 → N-108）：凡内容高被动超 334 的款必炸。给 A 的守门建议已在 r18 补 D 提过，收口轮再点一次：**壳层加一条「`.l99-host` 直系内容 scrollHeight > clientHeight 时必须有可滚层或 fixed 底栏」的静态断言**，比逐游戏修省力。
- **root 走 UI 的验证价值**：脚本 `btn.click()` 不受视口裁切影响,所以 seed storage / JS 点击都会漏掉 N-109 这类「门自己出屏」的伤——**收口后的回归一律走 UI 门**（🔑 → `kangkang` → 打开），顺手把「storage 无密码残留」验一遍。
- `frontend-design`「唯一 CTA 第一屏」收口统计：本战役共开 7 号同病（N-87/88/94/98/101/107/108），全部是 CTA/唯一输入排在 412 线下——新款接入清单里应把「915×412 首屏含 CTA」提为合入前检查项，而不是合入后开号。
