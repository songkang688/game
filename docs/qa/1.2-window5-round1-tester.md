### A1 · 走查方法与口径

五款全部用 **真机浏览器手点**（Chrome + Playwright 驱动，`vite preview` 起的产物包，不是 dev server），不是只跑单测。每一步都读真实 DOM、真实点击、真实键盘事件。

三条要先讲清楚的口径：

1. **第 100 / 188 关默认全是锁的。** 选关地图上未解锁的格子渲染成 `🔒` 且 `disabled`，从 UI 一路点是**开不到**第 100 / 188 关的——记「未解锁，未能直开」。平台的「直达第 N 关」口子没合进本分支，本档**不越界改平台**。为了仍能把这两关走完，本轮改用**写存档种子**的测试手法：往 `yiduo-yixing.l99.<id>` 写一个前 N-1 位为 1 的 188 长数组（这正是 `level99.ts` `loadStars` / `migrateStars` 认的格式），解锁后再从地图正常点进去。这只动测试环境的 localStorage，**没有改任何代码**。下文凡写「需种子」的都是这条路径。
2. **失败结局按各款设计判定**，不是「必须有输」。`color-fun` 源码里一次 `ctx.lose` 都没有（其自带的 `upgrade12.test.ts` 就钉着这条），本轮另用实玩确认涂错色只是不计入进度、可以撤销重涂，**不判负**。
3. **教育两款的「题目对不对」用双通道验**：一路是浏览器里逐题点、看游戏认不认；另一路是把 `buildQuestions()` 在 Node 里跑遍 188 关，拿**独立重算**的答案去比。两路结论必须一致才算过。

**W5-A-01 · 一般 · `clock-house` 读钟题的钟面无障碍标签直接念出答案**

- 复现：进 `clock-house` 第 1 关（或任何读钟面题）→ 读题面那张钟面 SVG 的 `aria-label`。
- 期望：题面钟面的读屏标签只说「一个可以读的钟面」之类，不含时刻。
- 实际：`aria-label` 就是答案本身。实测第 1 关第 1 题题面钟面 `aria-label="4 点"`，而三个选项正是「6 点 / 4 点 / 2 点」；第 100 关的分钟级钟面同理（`faceSVG` 默认 `label = formatClockMinute(time)`）。屏幕阅读器用户、或任何看一眼 DOM 的人，**不用读钟就知道答案**。
- 佐证这是遗漏而非设计：同一份文件里 `qSetMin` 给**选项**钟面显式传了 `label: "钟面"` 把时刻遮掉，说明作者清楚这个风险，只是**题面**钟面漏了。
- 影响面：`read` 413 道 + `readMin` 33 道，共 **446 道**题。
- 建议责任文件：`src/games/clock-house/levels.ts` — `clockSVG()` 里写死的 `aria-label="${formatClock(hour, quarter)}"`（第 86 行）；`qReadMin()` 调 `faceSVG(time, 150, { className: "clk-face" })` 时没传 `label`（第 518 行）。两处都改成不含时刻的说明性标签即可，`faceSVG` 已经支持 `label` 入参，不用动 `clockface.ts`。
- 不判阻断的理由：游戏自身的朗读（`quiz99` 只 `speak(q.ask)`）不会把这个标签读出来，普通触屏 / 鼠标玩家看不到它。
