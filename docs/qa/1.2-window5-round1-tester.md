### C1 · 走查环境与手法

- 分支 `game-1.2-window5`，基线 `bf6a972`（对齐 `origin/game-1.2-window5`）。
- `npm test`：**194 个测试文件 / 5379 个用例全绿**，耗时 36.07s（vitest 4.1.11）。
- `npm run build`：绿，`tsc --noEmit` 通过，vite 构建 412ms，PWA 预缓存 139 项 / 3286.70 KiB；入口 chunk `index-*.js` 86.80 kB（gzip 30.51 kB）。本档五款各自的 chunk：`poop-hero` 59.93 kB / `kitty-care` 66.24 kB / `find-diff`、`red-blue-tug`、`pinyin-train` 均在 60 kB 以下。
- 冒烟：`vite preview`（127.0.0.1:4173）下 `/`、`/sw.js`、`/manifest.webmanifest` 均 200。
- 真机手点：Chrome + Puppeteer 驱动**真实浏览器**，全部从首页 `button.game-card` 点卡片进入（不是直接改 hash），键盘用 `keyboard.down/up` 按住 90–120ms（`press` 的瞬时按下抬起会被逐帧输入采样漏掉，这点在走查早期踩到过）。
- 监听泄漏计数只统计**挂在 window / document / body 上的持久监听**。首页卡片那种「重渲染后旧节点被丢弃」的 click 监听不算泄漏，早期按总数统计会得到每轮 +151 的假阳性。
- 关卡 100 / 188 默认锁着。先如实记录 UI 上的锁态，再用 `localStorage` 播种 `yiduo-yixing.l99.<id>` 进度数组把关卡打开后实玩——**只写存档 fixture，没有改任何平台代码**。
