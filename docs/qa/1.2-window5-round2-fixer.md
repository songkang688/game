### A1 · 复审手法：为什么不认 `el.click()`

一台 `google-chrome --headless=new`，Node 22 自带的全局 `WebSocket` 直连 CDP，**零新增依赖**。
点击一律走 `Input.dispatchMouseEvent`、滑动一律走 `Input.dispatchTouchEvent`，全程真实屏幕坐标。

判「点得着」这件事，本轮用的尺子比前两轮又紧了一格，**两条同时成立才算数**：

1. 键心必须落在「**所有裁切祖先 ∩ 视口**」围出来的那块真看得见的矩形里；
2. 在键心上问 `document.elementFromPoint`，拿回来的得是**它自己或它的后代**。

第 2 条里**去掉了 `hit.contains(el)`**（前几轮的写法带这一项）。这一项会放过一整类假绿：
舞台裁在 `y=554`、视口有 568，中间那 14px 的带子里 `elementFromPoint` 拿回来的是壳层大盒子，
而它**正好是这颗键的祖先**——按 `hit.contains(el)` 算就成了「点得着」，
可那一处画的根本不是这颗键，手指真按下去点到的是壳。
本轮就是靠去掉这一项才把 `color-fun` 调色台那几颗从「绿」里揪出来的（见 A2 · L-02）。

「滚一下够不够得着」分两步，**程序滚只算粗筛，不作数**：

- 粗筛：写 `scrollTop` / `scrollIntoView` 看理论上能不能进视区；
- **定案：真手指**。在滚动容器上派完整 `touchStart → touchMove ×14 → touchEnd`，
  落指点必须①在舞台看得见的那一段里、②在这层容器自己的矩形里、
  ③那一处不是 `touch-action:none`（涂色画布就是，按下去是画画不是滚）、
  ④不在写了 `overscroll-behavior:contain` 的小盒子里（那一下滚不出去，传不给外层）。
  滑到之后**再真按一次**，用文档级捕获监听确认游戏真收到了 `click`。

一次性量尺与探针全在 `/tmp/w5r2a/` 下，**0 字节进提交**（收尾前已 `rm`，`git status` 干净）。

### C1 · 复审手法：那把不认 `el.click()` 的尺子

**真机**：Chrome `--headless=new` + Node 22 自带 `WebSocket` 直连 CDP（`Runtime.evaluate` / `Input.dispatchTouchEvent` / `Emulation.setDeviceMetricsOverride`），**零新增依赖**，探针全部落在 `/tmp/w5r2fc/` 下、跑完即删、0 字节进提交。被测的是 `npm run build` 出来的 `dist/`（`vite preview :4173`），不是 dev server。

| 量什么 | 怎么量 | 为什么不这么量就会假绿 |
| --- | --- | --- |
| 够不着 | `document.elementFromPoint(中心点)` 拿回来的是不是它自己 / 它的后代 | `el.click()` 对被 `overflow:hidden` 裁掉的元素照样绿 |
