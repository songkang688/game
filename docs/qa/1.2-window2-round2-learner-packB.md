才是存档、配表、AI 分支认的东西，`TIER_LABELS` / `TIER_NAMES` 只是屏幕上的那几个字。
所以这次一个 id 都没碰，**存档零影响**，配表口径也没动。

### P2B-2 · `tap-tiles` 同谱对战：四档从第 1 局起就分得开

**先把问题量出来**（`aiRun(matchChart(r), tier, chart.seed + 5)`，和界面上的 `mountVersus` 用的是同一条调用）：

| 局 | 音符数 | 改前 新手 / 普通 / 高手 / 大师 | 改后 |
| --- | --- | --- | --- |
| 第 1 局 | 28 | 3425 / **4200 / 4200 / 4200** | 2950 / 3800 / 3975 / **4200** |
| 第 2 局 | 30 | 3575 / **4650 / 4650 / 4650** | 3000 / 4175 / 4400 / **4650** |
| 第 3 局 | 32 | 2575 / **5150 / 5150 / 5150** | 2200 / 4650 / 4925 / **5150** |
| 第 4 局 | 34 | 3475 / **5650 / 5650 / 5650** | 3050 / 5175 / 5400 / **5650** |
| 第 5 局 | 36 | 3125 / **6150 / 6150 / 6150** | 2750 / 5500 / 5800 / **6150** |
| 第 6 局 | 38 | 2550 / 3800 / 6400 / 6650 | 2125 / 3400 / 6050 / **6650** |
| 第 7 局 | 40 | 2925 / 5700 / **7200 / 7200** | 2750 / 5100 / 6850 / **7200** |
| 第 8 局 | 42 | 5300 / **7800 / 7800 / 7800** | 4550 / 7050 / 7425 / **7800** |

改前八局里有**六局**至少两档同分（测试员点名的第 1 局 4200、第 3 局 5150 都在里头，逐个数字对得上）；
改后**八局全部严格递增**。

根子不在「假人太强」，在两条噪声都不起作用：普通档 ±40ms 整个落在 ±45ms 的完美窗口里，
而对战头几局的谱只有二三十个音符，3.5% 的手滑期望还不到 1 个，多半一次都抽不到。

**修法**：给前三档加一层**确定性**的「良好」失手 —— 每 3 / 5 / 9 个音符往后偏 `LOOSE_OFFSET_MS = 70`ms，
落在完美窗口外、良好窗口内，所以**只掉分、不断连击、不漏音符**；最高档 `hell` 是 0，一次都不偏。
偏移量还会按同轨下一个块的余量收窄（`looseOffsetFor`），挤不出余量就老老实实打准，绝不会判到隔壁块上去。
`runBot` 的随机数取用顺序一个字节没动（先取噪声、再取手滑，最后才叠这一层），所以长谱上原有的手感与既有断言都不受影响。

- **B-2 的平局前提原样保住**：`hell` 仍旧零 miss、零良好、满分，满分玩家对最高档还是平局 ——
  `versus.test.ts` 那四条回归一条没改（只把按钮上的「地狱」换成「大师」）。
- 测试：新开 `tap-tiles/tiers.test.ts` **9 条** —— 八局逐局四档严格递增 / 第 1 局只有最高档满分 /
  最高档八局全零 miss 零良好 / 中间两档掉的是良好不是 miss（连击不断）/ 失手确定性（跑两遍一样）/
  间隔单调 / 偏移量落在两条窗口之间 / 挤不出余量就不偏 / 真谱面上每一次打偏都在良好窗口里。

### P2B-3 · `hue-hand` 无尽重开换一批牌，发牌前先确认玩家开局接得上

**先把问题量出来**：

- **重开原样重放**：无尽的牌堆只由「第几局」决定（`buildEndlessRound(n).seed = 640000 + n × 2711`，
  `roundDeck(cfg, 0)`），连胜断了从「🔁 从第 1 局再来」进去，发到的牌与上一次一模一样，连胜三次就把前几局背下来了。
- **牌堆从没验过**：对战的 36 个「局数 × 人数」组合里，**4 人第 4 / 9 / 11 局**这三副牌玩家开局一张都接不上
  （不致命，摸一张就能走，但开局先罚站一手很扫兴）。

**修法**：`levels.ts` 新增 `dealRoundDeck(cfg, sitting)`，`sim.ts` 新增 `hasOpeningPlay()`。

- `sitting` 是「这是第几次从头连胜」，输了重开 +1 换一批牌；同一次连胜之内完全确定，断线重挂发同一副。
- 发牌前先用 `hasOpeningPlay()` 试算一遍，不合格就换下一副，12 副之内挑不出来就用最后那一副（不至于卡住）。
- **`sitting = 0` 走的仍旧是原来那副牌**：24 局逐局比对牌堆 id 序列，一张不差 —— 第一次玩的手感没被动过。
- 对战与双人同屏没有「从头再来」这个入口（`round` 只增不减），所以只吃可解性这一层，不引 `sitting`，避免留下永远等于 0 的死参数。

| 口径 | 无尽 24 局 × 6 批 | 对战 12 局 × 3 种人数 × 6 批 |
| --- | --- | --- |
| 旧 | 开局接不上 0 / 144（但 6 批发的是同 24 副牌） | 开局接不上 3 / 36 个唯一组合 |
| 新 | 0 / 144，且每批都是新牌 | **0 / 216** |

- 测试：`levels.test.ts` **+6 条**（第一次玩发的还是原来那副 / 重开换牌 / 同批确定 / 仍是整副 108 张 /
  旧口径确实会发出接不上的牌 / 新口径无尽与对战每一局每一批都接得上），
  `index.test.ts` **+2 条**（真走「无尽连胜」入口，把屏幕上七张牌的 `aria-label` 和 `dealRoundDeck` 算出来的手牌逐张比对，
  证明接线用的确实是新函数；再断言第 2 批发的不是同一副）。

### P2B-4 · `hop-pads` 蓄满力给信号

`powerFromHold` 在 `MAX_HOLD = 1200ms` 之后封顶，可屏幕上一点变化都没有 —— 孩子按着不放，只能靠「飞过头」才知道按久了
（第 1 轮 L-11 记录时说「要动 canvas 绘制，验证得靠绘制流水」，而这一款的 canvas 桩是个把所有绘制都吞掉的 Proxy，
所以这次把「满没满」做成**可读状态**，不依赖绘制也测得到）。

- 跨过封顶线的那一帧闪一句 `💪 满力啦,松手就跳`（只闪一次，不重复弹字）；
- 蓄力条随后一直保持满力那一档配色（`FULL_BAR_COLOR`），「再按也不会更远」这件事一直看得见；
- 画布挂 `data-full`，`aria-label` 里念一句「力度已经满了」；`Stage` 多导出一个 `full()`；
- 第 1 关的说明行补一句「蓄力条变色就是满力了」。

**判定一行没动**：同样的力度，跳出来的座数、分数、状态一字不差（用例守住）。
`onDown` / `onUp` / 手指号账本 **diff 为空** —— 第 1 轮 B-6 修的那一段一个字节没碰。

- 测试：`index.test.ts` **+2 条**（满力信号从 0 翻到 1、收力之后翻回 0、`ready` 时恒为 0；
  「按到满力再多按一会儿」与「直接给满力」两条路径跳出来的结果完全一致）。

### P2B-5 · `dark-chess` 顶栏补一枚和棋倒数
