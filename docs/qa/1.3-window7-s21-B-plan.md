# 1.3 第 21 步 · B 档 · `puzzle-tiles` 视觉升级计划（工人 w7-s21-B-puzzle-tiles）

> 只改视觉，不动玩法：三种板式（推格子 / 旋转块 / 缺块补齐）的判定与解算、
> 拼块数据、正确性校验、存档 key、`meta.ts`、关卡图案数据一律不碰。

## 现状审美评测（第三节自查结论）

1. **拼图感先天缺失（核心问题）**：三种玩法的拼块全是 `pz-tile` 方格按钮换背景色 +
   emoji（`renderSlide` 换 `pic[v].bg`，`renderRotate` 换 `tile.bg` + 旋转 span，
   `renderFill` 换色 / 换「？」），没有任何凹凸齿边——「拼图乐园」的拼块是圆角方砖，
   不是拼图。
2. **拾起 / 放置物理感不足**：1.2 的拖拽浮块 `.pzt-drag` 有 scale(1.06) + 投影，底子在，
   但没有 80ms 抬升过渡；放对只有 `msgEl` 文案 + 音效，没有吸附回弹和接缝白光；
   放错（`bounce` reason=wrong）只弹回托盘，目标格没有任何视觉分支——放对与放错
   在画板上看是一样的。近位提示 `pzt-target` 是黄色描边，对「这块就该放这」没有虚影表达。
3. **`renderPreview` 无仪式感**：目标预览是白底圆角小格平铺（16px `<i>` 格），
   是功能件不是「画框里的成品」；整图底图 `pzt-ghost` 只是半透明平铺。
4. **完成庆祝较弱**：`celebrate()` 只有 `pzt-shine`（格缝合拢 + 全板发光）一招，
   无「装裱」语义、无彩纸，1.2 秒后直接跳结算。
5. **顶栏与三玩法统一性**：顶栏是散排白色胶囊徽章（步数 / 三星线 / 沙漏 / 横幅），
   无卡片容器；三种玩法在画板上没有任何板式身份标识（旋转块无把手、滑块空格是
   平的半透明格、缺块的洞是斜纹格），切玩法只能靠读文案分辨。

## 改造方案（对应规格四 / 四·补一 / 四·补二 / 四·补三）

- **新增 `src/art/kit/jigsaw.ts` + 单测**（kit 里没有齿形能力，按「谁先用到谁新增」落自己的
  文件，不改别人的 `fruit.ts` / `caterpillar.ts` / `juice.ts` / `sparkle.ts`）：
  输入 `(rows, cols, r, c, size)`（另带确定性 seed），输出 SVG path d 与
  `clip-path: path(...)` 字符串；内边凸凹由确定性哈希决定、相邻块互补、边缘平边；
  齿形半径 18%（块宽 < 40px 降 14%）、齿颈 = 半径 55%、三段贝塞尔蘑菇头。
- **新增 `src/games/puzzle-tiles/visual.ts`**：`--pt-` 配色 token（画室底 / 木框 / 内亮边 /
  虚影 / 凹槽 / 微光 / 接缝白）、动效时序表、z-index 图层序（画室底→凹槽→已放定→虚影→
  拾起浮块→星闪彩纸→顶栏→装裱浮层）、拼块皮肤 SVG 纯字符串生成（纸质渐变 + 1px 内亮边）、
  放对 / 放错类名映射、虚影只读映射、旋转视角累计角、FX 计时包（destroy 一把清）。
- **`index.ts` 只动渲染**：三种 render 接皮肤层（按钮热区一个像素不动，皮肤是
  `pointer-events:none` 的绝对定位 SVG）→ 拾起 / 吸附 / 摇头反馈 → 旋转把手 + 120ms
  过渡 + 转正星闪 → 滑块凹槽 + 90ms 位移 + 可滑微光 → 画框化预览 + 完成装裱 + 彩纸 +
  画廊语义 → 顶栏卡片化 + 三枚玩法图标签 → reduced 全接线 → destroy 清 FX 计时。
- **新增 `visual21b.test.ts` ≥ 12 个视觉用例**；既有玩法测试文件零改动。
