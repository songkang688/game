## 六、走查工具本轮纠出的三处偏差（关系到前两轮结论的可信度）

测试员的取证工具本身也会骗人。本轮抓到三处，都已修并重跑：

1. **自带地图的两款点不开关卡（影响 `candy-swing`）。** `openCustomLevel` 用的是合成 `el.click()`，而 `candy-swing` 的关卡格子只吃真实 pointer 事件——**点了没反应，驱动却按「进去了」记账**。更糟的是走查流程会先点「🗺️ 闯关 188 关」，而这一款首屏本来就是关卡格子、那个按钮是「直接开打」，**先点它反而会跳进别的关**。也就是说**前两轮 `candy-swing` 的战役关号是不可信的**（进的不一定是目标关）。现改为真鼠标点击 + 这类款不再先点「闯关」，并加了「地图还看得见就不算进关」的兜底。修好后补测：第 188 关赢、第 1/60/133 关 15 秒随机输入没分胜负、360px 零溢出、最小热区 44px、console 零报错。
2. **`bowling-lane` 那条「360px 关卡页溢出 24px」是误判（S1 撤回，见 §7）。**
3. **`prince-princess` 摆烂扫描扫错了模式**（扫的是双人，漏了单人），因此第 2 轮把这一款判成「干净」。这一条直接导致漏掉了本轮的 B2。

工具改动都在 `scripts/qa-window3/` 下，`src/` 一行没碰。

## 八、第 3 轮结论：本窗口这一批**不能发布**

### 判据对照

| 发布判据 | 达成情况 |
| --- | --- |
| `npm test` 全绿 | ✅ 250 文件 / 6502 用例 / 失败 0 |
| `npm run build` 通过 | ✅ 526ms，precache 140 项 |
| 19 款进得去、玩得到真胜真负、模式都能进 | ✅ 浏览器 19/19、逻辑层 19/19 |
| 竞态无问题 | ✅ 四项 × 19 款零问题、console 零报错 |
| **阻断项 = 0** | ❌ **3 条阻断**（B1 仍在 + B2、B3 新增） |
| 严重项已修或有人接手 | ⚠️ S5 未修；S1 撤回；S2′ 降级为 O1 |

### 为什么这三条是阻断而不是严重

「一朵一星」的核心是**一关一颗星**——星星是孩子努力的凭证。现在这一窗有 **`sky-squad` 180 关 + `prince-princess` 110 关 + `duo-vs-star` 72 关 + `bumper-cars` 31 关，合计约 393 个关卡实例，把手机放桌上不管就能拿星，其中绝大多数还是三星**。`duo-vs-star` 第 157 关**开局 1 秒**就弹「★★★ 过关！一次都没被撞出去，太稳啦！」。这不是难度偏低，是**奖励与付出彻底脱钩**，产品最核心的那条承诺当场作废。四款里有三款的**第 1 关**就在名单上——新玩家第一次点进去，什么都不做就通关了。

四条的根因还各不相同，不能指望一处改动一起解决：

- `sky-squad`：判罚链路是死代码（`escaped` 恒为空）；
- `prince-princess`：AI 搭档强度盖过了玩家的存在感；
- `duo-vs-star`：`star-lift` / `night-hops` 两张场地的边界跟 AI 走位对不上，对手自己掉下去；
- `bumper-cars`：AI 对手自己冲下悬崖。

### 交接清单（按处理顺序）

1. **B1 `sky-squad`** — `stepFoes` 两行错位，改动量最小、收益最大，建议第一个修。
2. **B3 `duo-vs-star`** — 先看 `star-lift` / `night-hops` 两张台子的 `bounds` 与 AI 走位，19/19 和 16/19 这种集中度基本能定位到场地。
3. **B2 `prince-princess`** — 需要产品一起定：单人模式的 AI 搭档该多强？这条不是纯技术修复。
4. **S5 `bumper-cars`** — 顺带把「撞飞 1 台对手车」这句错误归因的结算文案一起改了。
5. **O1 `candy-swing`** — 请先回答「`sim.ts` 和真机是不是同一套物理」，再决定那 12 关要不要动。
6. **M1 / M2 / M4 / M5 / M6 / M7 / M8 / M9** — 轻微项，可与发布并行处理。

### 给下一轮（修完之后）的回归清单

修完 B1/B2/B3/S5 之后**必须重跑摆烂扫描**（`QA_ROUND=3 npx vitest run --config scripts/qa-window3/vitest.config.ts scripts/qa-window3/idle.qa.test.ts` + `scripts/qa-window3/round3.qa.test.ts`），四款的 `autoWin` 都要归零或落到「设计如此」的白名单内；并且**建议把这个扫描固化成 `src/games` 下的常驻用例**——这一轮的教训是，6502 条用例挡不住「不用玩也能通关」，因为没有一条在问这个问题。
