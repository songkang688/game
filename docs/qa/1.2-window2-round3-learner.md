### R3B-3 的根因（本轮新量，交给平衡专项）

四档两两互打各 120 局、**正反座位各跑一遍**（合计 240 局）：

| 对局 | 强的那一档拿下 |
|---|---|
| 新手 vs 普通 | 普通 123 / 240（51%） |
| 新手 vs 高手 / 大师 | 高手、大师各 **240 / 240**（100%） |
| 普通 vs 高手 | 高手 128 / 240（53%） |
| 普通 vs 大师 | 大师 132 / 240（55%） |
| 高手 vs 大师 | **大师 118 / 240（49%）—— 大师其实不比高手强** |

两条结论：① 真正的分水岭是 `aiCatchesOneCard`（rank ≥ 2 才会点破忘喊），
新手自己不喊「就一张」，一到 1 张就被罚抽，于是对高手 / 大师是 0 : 120 的碾压，
而 `rate()` 那套打分在相邻两档之间几乎不产生胜负差；
② 大师那层 `rank >= 3` 的加料是**负收益**，最可疑的是「加牌牌先攒着卡链」的 `-5`
与续链时 `pick = stacks[0]`（拿手上第一张能续的，而不是打分最高的那张）。

### P3C-1 / P3C-2 的共同根因（与同窗包 A 的 `R3-PA-DM-1` 同类）

三款游戏都为识字量有限的孩子做了 `speak()` 通道（`rainbow-run/logic.ts:1314` 的原注释：
「结算面板不走 level99 浮层，识字量有限的孩子靠听」）。但**纪录这件事只进了眼睛**：

| 通路 | rainbow-run | ocean-munch |
|---|---|---|
| 面板画出来 | ✅ `recordLine()`，破纪录还染成橙色 | ✅ 「🎉 破纪录!最深 N 米」 |
| 音效 | ✅ | ✅ `api.play(newRecord ? "win" : "oops")` |
| **朗读** | ❌ **不提** | ❌ **不提** |

也就是说：最该听见「你破纪录了」的那个孩子，听到的和上一趟一模一样。
同窗包 A 的 `R3-PA-DM-1`（dot-maze 第一次玩就是最好成绩、收场话却说「再来一次就能刷新它」）
是同一个洞的第三个实例。

既有用例断言 `lines.join("") === line`；新句子单出一个纯函数接在 `line` 后面朗读，
**面板一个像素没动**，那条约束在新用例里又断言了一遍。
