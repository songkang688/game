### F01（严重）Esc 暂停和游戏壳打架，5 款按两下 Esc 像卡死

- **现象**：`merge-2048` 第 1 关按 Esc，盘面停住并显示「⏸️ 暂停中，再按一次 Esc 继续」；
  **再按一次 Esc，画面上什么都没发生** —— 提示还是「暂停中」，盘面还是不动；按第三下才继续。
- **根因**：`gameShell.ts` 的 `onGlobalKeyDown` 也挂在 `window` 上，注释写得很清楚：
  自带暂停的游戏必须 `preventDefault()`，壳层推迟一个宏任务后看 `defaultPrevented` 决定让不让。
  这 5 款在 Esc 分支里只切了自己的 `paused` 就 `return`，**没有 `preventDefault`**，于是：
  第 1 下 → 游戏暂停 ＋ 壳弹出统一暂停面板；第 2 下 → 被面板在捕获阶段吃掉、只关面板，
  游戏还停着而面板已经不见了；第 3 下 → 游戏才继续，同时面板又弹了出来。
- **命中**：`orb-arena` `snake-royale` `block-drop` `combo-clash` `merge-2048`。
  另外 7 款（`mahjong-bloom` `star-estate` `hero-cards` `weiqi-garden` `flight-chess`
  `mine-garden` `sudoku-petal`）本来就调了，不用动。
- **复现测试（先红）**：新建 `src/games/__tests__/window1-esc-contract.test.ts`，
  逐款把 `index.ts` 里认 Esc 的 `if {...}` 块**按花括号配对切出来**（窗口开大一点就会把
  下面管方向键的那句 `preventDefault()` 误算成 Esc 分支自己调的，漏掉真毛病），
  断言块内或紧邻的前几行能找到 `preventDefault`。先跑：**恰好 5 红 8 绿**，与人工核对一致。
- **修复**：5 款各加一行 `e.preventDefault()`，附一句为什么。玩法数值一个没改。
- **回归**：真浏览器复测 `merge-2048`，Esc 四下的结果从
  `暂停中 / 暂停中 / 继续 / 继续`（且第 1、3 下会各弹一次面板）变成
  `暂停中 / 继续 / 暂停中 / 继续`，全程 `dialogs: 0`。
  `smoke-1.2-step5-a` 里原本失败的「再按一次 Esc 就接着玩」也从 21/22 变成 **22/22**。

### F03（严重）360px 上说明文字普遍小过正文下限

窗口自己的硬指标写在 `docs/plan-1.2-step1-B-platform-filter.md` 与 `src/ui/mobileText.ts`：
**正文 ≥ 16px，只有按钮文字和关卡格子数字可以放到 14px，说明文字不行**，行高 ≥ 1.4。
360×640 实测下来违反得很普遍，而且 `styles.css` 里的 `/* 1.2 mobile text */` 区块管不到 ——
`level99.ts` 和各款 `index.ts` 都是运行时注入 `<style>`，注入在后面，层叠上直接盖过 CSS 文件。

| `level99` `.l99-pagehint` | 12px | 16px | 同上 |
| `level99` `.l99-jump-note`（管理员权限还剩 XX 分钟） | 12px | 16px | root 门自己的提示 |
| `level99` `.l99-chip`（`🚩 0/188 关`、`⭐ 0/564`） | 14px | 16px | 同上；这是进度读数，不是按钮也不是格子数字 |
| 12 款的 `.xx-msg` 状态行 ＋ `.cc-note` / `.wq-note` / `.mg-note` | 13–14px | 16px | 12 款 |
| 8 款在 `@media (max-width:360px)` 里把 `.xx-msg` **再调小到 13px** | 13px | 删掉这条覆盖 | 8 款 |

| `home.ts` `.home-count`（找到 N 个游戏） | 14px | 16px | 首页 |

最后那一行值得单独说：**8 款在 360px 的媒体查询里把状态文字再调小**。360×640 正是验收视口，
越窄越小是反的 —— 这一条不是「忘了抬」，是「主动调低」，所以直接把那条覆盖删掉。

`.home-count` 还有一处层叠陷阱：`styles.css` 的 1.2 区块本来就给它写了 `max(var(--mt-body),16px)`，
但 `home.ts` 注入的 `<style>` 在后面，同样是单类选择器，14px 赢了。改的是 `home.ts` 那一份。

  写了个 `fontSizeOf(css, selector)` 帮手 —— 取**层叠后最后一条**（媒体查询写在后面，
  所以一条断言同时管住基准值和窄屏分支），`max(var(--mt-body), 16px)` 这种夹取写法取里面最大的 px。
  先跑 **12 红**，改完全绿。

### F04（严重）首页搜索框在 360px 上顶出屏幕，「清空」按钮被裁掉一半

- **现象**：360px 视口下 `.home-search` 实测宽 **370px**（容器只有 331px），
  「清空搜索」的 ✕ 落在 `331..375`，右边 15px 在屏幕外，点不着。
- **根因**：`.home-search` 是 flex item，`min-width` 缺省是 `auto`，自动最小尺寸把它撑住了不肯缩。
  逐项验过：`min-width:0` → 331（好）；`max-width:100%` → 331；把 ✕ 的负 margin 去掉 → 380（更糟）。
- **修复**：`.home-search` 显式 `min-width:0`；✕ 改成 `flex:0 0 auto`，
  去掉 `margin-right:-10px` 这个负 margin，靠容器右内边距从 16px 收到 12px 来补视觉位置。
- **复现测试**：断言 `home.ts` 的 `.home-search` 写了 `min-width:0`、`.home-search-clear` 不再靠负 margin。
