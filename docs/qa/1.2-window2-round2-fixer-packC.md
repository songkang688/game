### 1.1 `R2C-G1` / `R2C-G2` · gomoku 的三类按钮（`view.ts` CSS）

全局 `src/styles.css` 里有 `* { box-sizing: border-box }`，所以 `min-height` 把 padding
与边框都算了进去 —— 直接写 `min-height:44px` 量出来就是 44px，不用去猜行高。
`view.ts` 顺手立了一个 `MIN_HIT_PX = 44` 常量，CSS 用模板串插进去，
以后谁想调都得先改这个数（和 `xiangqi/session.ts` 里那个同名常量一个口径）。

```
.gmk-btns button   padding:10px 6px  font:14px          36.8–39.6px → min-height:44px
.gmk-seg button    padding:9px 8px   font:14px  边框 3px  40.8–43.6px → min-height:44px
.gmk-mode          padding:9px 16px  font:15px          36.0–39.0px → min-height:44px
.gmk-over-btn      padding:11px 24px font:16px          41.2–44.4px → min-height:44px
.gmk-start         padding:13px      font:18px          47.6–51.2px（本来就够，没动）
```

`.gmk-over-btn` 测试员标的是「⚠️ 临界」（行高取 1.2 时 41.2px、取 1.4 时才 44.4px），
也就是**换一台设备就可能不够** —— 这类不该留给下一轮去赌，一并兜住。

**测试**（`view.test.ts` +5 例）：新写了 `ruleBody()` / `hitHeight()` 两个小工具
（`min-height` / `height` 优先，没写就按「上下 padding + 上下边框 + 字号 × 1.2」估，
行高取最小那一档，**估出来是下限**，所以 ≥ 44 的结论只会更保守），
逐条量 `.gmk-btns button` / `.gmk-seg button` / `.gmk-mode` / `.gmk-over-btn`，
最后再加一条「能点的按钮一个都没漏」的清单式扫描（含 `.gmk-start`）。

### 1.3 `R2C-R1` / `R2C-O1` · 两款纯画布的热区（`index.ts`）

这两款没有 CSS 可以兜底 —— 热区就是 `inRect()` 拿去比的那个矩形。
测试员点名的 10 处里，**只有 `btnEndless` 能直接把画出来的按钮撑到 44px**，
其余 9 处都贴着标题或 HUD，撑大了会压字：

| 位置 | 撑大了会压到谁 |
| --- | --- |
| rainbow-run 选关屏 `◀ 世界`（y=7, h=30） | 章节标题在 y=28、地图节点从 y=96 起 |
| rainbow-run 局内 `◀ 回家`（y=6, h=28） | **HUD 第二行（赛道进度 + 任务条）从 y=40 起** |
| rainbow-run 首屏 `🎁`（y=8, 38×34） | 大标题横排到 x≈310，按钮已经在 x=314 |
| ocean-munch 四屏的 `◀` 与两处 `📖 图鉴` | 副标题都在 y=52 那一行 |

所以走另一条路：**画的还是原来那颗小按钮，能点的范围往外扩到 44px 见方**。
两款各加了一个 30 行的纯函数模块 `touch.ts`（不 import 任何东西，纯算术）：

```ts
export function touchArea(r: Rect): Rect {
  const w = Math.max(r.w, MIN_HIT_PX);
  const h = Math.max(r.h, MIN_HIT_PX);
  return { x: Math.max(0, r.x + (r.w - w) / 2), y: Math.max(0, r.y + (r.h - h) / 2), w, h };
}
```

`Math.max(0, …)` 那一下不是凑数：局内的「◀ 回家」画在 `y=6`、高 28，
居中往外扩会跑到 `y=-2`，画布外那 2px 手指根本够不着 ——
**看着是 44px，真能点的只有 42px**。推回 0 之后 `0..44` 才是真的 44px。
