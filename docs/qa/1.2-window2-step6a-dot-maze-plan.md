## 一、进场时的既有状态

`origin/game-1.2-window2` 上已经有一版 `dot-maze`（提交 `157f8bb`，11 个文件 / 52 个用例）。
这一版把格子逻辑、四种脾气、188 关生成器都写完了，跑下来是绿的。
本趟不推倒重来，而是**对着规格逐条验收，只补真正缺的那几块**。

对照规格逐条查下来，缺口是这些：

| # | 规格条目 | 现状 |
| --- | --- | --- |
| 1 | 第十三节「`destroy` 干净」 | 整个目录没有一个 DOM 用例，`mount` / `destroy` 完全没被测过 |
| 2 | 第九节 360px：格子 ≥ 14px、迷宫完整入屏 | 格子写死 `cell = 18`，靠 CSS 缩放，没有任何断言兜底 |
| 3 | 第七节 / 第八章第 7 章：星星操纵一只小幽灵 | `moveStarGhost()` 只在 keydown 里调一次，`stepRun` 每个 ghost tick 都会用 AI 把它覆盖掉——星星实际上操纵不了 |
| 4 | 第十节：地狱档会包抄，两只走对侧路线 | `flankTarget()` 写了但没有任何地方引用，是死代码 |
| 5 | 第六条：音效只用 `api.play(...)` | 局内一次都没响过，`mountStage` 根本拿不到 `api` |
| 6 | 第十四节分级红线 | 没有文案巡检用例（仓库里 `fight-king/copy.test.ts` 是现成的写法） |
| 7 | 小幽灵出生 | `makeGhost` 里 `maze.home.x + (slot % 2 === 0 ? 0 : 0)` 恒等于 0，四只叠在同一格出生 |

## 二、要动的文件（全在独占范围内）

- `src/games/dot-maze/ghosts.ts`：`flankTarget` 接进地狱档包抄；`makeGhost` 四只错开出生。
- `src/games/dot-maze/logic.ts`：加「玩家操纵的那只小幽灵」——`controlled` 下标 +
  `steerGhost()`，`stepRun` 对这一只跳过 AI，改用它自己的转向缓冲。
- `src/games/dot-maze/index.ts`：星星操纵接到新 API 上；接 `api.play`；
  格子尺寸按可用宽度算，保证 360px 下 ≥ 14px。
- `src/games/dot-maze/layout.ts`（新）：格子尺寸这点纯算术单独拆出来，好断言。
- `src/games/dot-maze/domStub.ts`（新）：测试用的极简 DOM 桩，只给 `*.test.ts` 用。

## 三、要加的用例（下限 22，只增不减）

- `index.test.ts`：四种模式各 mount 一次再 destroy，断言监听 / rAF / DOM 全部收干净；
  WASD 与方向键分别喂给谁；Esc 暂停；虚拟方向键热区；360px 布局。
- `layout.test.ts`：188 关 + 无尽圈的格子尺寸在 360px 下都 ≥ 14px，整张图不超宽。
- `copy.test.ts`：全目录（含注释）扫商标黑名单与死亡描写；攻略 8 章铺满 188 关；
  `meta.ts` 纯数据；音效白名单；`destroy` 源码巡检。
- 往 `ghosts.test.ts` / `logic.test.ts` 里追加：包抄目标、四只错开出生、
  星星操纵的小幽灵不被 AI 覆盖。
