## 二、逐条明细

### L-A-1 · dot-maze：巡游 ↔ 追击换段时全体掉头 ✅ 已落地

- **来源思路**：街机迷宫类的通用做法——节奏换段时怪物统一转身，
  既是给玩家的一个「看得见的信号」，也顺手打断「贴着屁股一路跟到底」的黏人劲儿。
  本仓 `PHASE_TABLES` 早就把两种节奏写好了，只差这个「转身」的表现。
- **现状**：`advanceGhost` 里 `next.mood = phase` 一句就把段换掉了，
  场面上没有任何提示；玩家只能靠数秒或者靠挨绕晕才知道进了追击段。
- **落地方式**：`ghosts.ts` 加 `reversePhaseFlip(ghosts, skip)`；`RunState` 多记一个
  `phase` 字段，`stepRun` 发现 `phase` 变了就整体掉一次头。
  回家的眼睛、正被吓到的、以及**第二个人操纵的那一只**都不掉头
  （双人追逃里方向必须留在人手里，不然就成了抢输入）。
- **收益**：追击段开始的那一刻四只同时转身，玩家有半秒判断「该收还是该冲」；
  同一段之内不会平白掉头，节奏读得出来。
- **风险与回滚**：改的是小幽灵朝向，不动碰撞与计分；
  `dummySurviveMs` 的「地狱档让假人活得更短」回归断言仍然成立。
  回滚 = 删掉 `stepRun` 里那三行 `if (phase !== state.phase)`。
- **测试**：`logic.test.ts` 3 例（换段那一步真的往回走 / 没换段照旧往前 / 被操纵的那只不跟着转）、
  `ghosts.test.ts` 3 例（眼睛与惊吓不动 / skip 生效 / 只换朝向不换格子）。

### L-A-2 · dot-maze：惊吓时四只散开逃 ✅ 已落地

- **来源思路**：吃到能量豆之后的反攻乐趣来自「追得到」，
  但四只如果都往同一个角落跑，就会连成一串，玩家顺着队伍一路吃到底，
  200 / 400 / 800 / 1600 的连击等于白送。
- **现状**：`fleeTarget` 只按「离玩家最远」挑角落，四只算出来的是同一个角落。
- **落地方式**：第二判据改成「各回各的角落」——
  `manhattan(角落, 玩家) * 4 - manhattan(角落, 自己的角落)`。
  距离玩家仍然是第一位的，只有一样远的时候才按自己的角落分开。
- **收益**：玩家站在中间吃能量豆时，四只往四个方向散，连击要真的绕路去凑。
- **风险与回滚**：`fleeTarget` 只被惊吓分支调用，影响面就是这一段；
  既有断言「逃向离玩家最远的角落」原样保留、仍然绿。回滚 = 把打分换回纯距离。
- **测试**：`ghosts.test.ts` 新增 1 例（玩家站正中间时四只的目标互不相同，且各是自己的角落）。

### L-A-3 · chess-garden：置换表按局面做键，杀分不当缓存值 ✅ 已落地

- **来源思路**：迭代加深 + 置换表的标准配法是「键只认局面，深度记在表项里」。
  本仓两样都写了，但键写成了 `zobrist|depth`——于是每加深一层，
  上一层辛辛苦苦算出来的分数与最好的一手全都查不到，`hit.depth >= depth` 那一行也就成了摆设。
- **现状**：`const key = \`${zobrist(p)}|${depth}\``。
- **落地方式**：键改成 `zobrist(p)`；查表沿用 `hit.depth >= depth`；
  存表改成深度优先覆盖（浅的不许冲掉深的）。
  另外两处顺手补严：① 杀分是相对层数算的，同一个局面在不同层上的杀分不一样，
  所以 `|score| >= MATE_SCORE - 1000` 的表项只借它记的那一手排序，不当缓存值返回；
  ② 50 手规则的判断挪到查表之前，免得不同 `halfmove` 的局面共用一条记录。
- **收益**（同一手、同一分，只是少算）：

  | 局面 | 深度 | 改前节点 | 改后节点 |
  |---|---|---|---|
  | 开局盘 | 5 | 45079 | 33036（−27%） |
  | 意大利开局 | 4 / 5 | 35500 / 146175 | 23224 / 86952（−35% / −41%） |
  | Kiwipete | 5 | 187116 | 146982（−21%） |

  地狱档是 200ms 固定预算，省下来的节点直接变成多算一层。
- **风险与回滚**：最大的风险是杀分串层，已用 `MATE_BOUND` 挡住并写了回归；
  既有的「一步杀 / 两步杀 / 升变 / 可复现 / 每档都在预算内落子」断言全绿。
  回滚 = 键改回 `zobrist|depth`。
- **测试**：`search.test.ts` 新增 2 例——
  ① 意大利开局 depth 5 仍是 `Nc3`、分数仍是 74，但节点数卡在 12 万以内
  （退回旧写法要 146175，这条会当场变红）；
  ② 同一道两步杀在 depth 3 / 4 / 5 上都报得出杀分，且挑的确实是杀法。

### L-A-4 · junqi-camp：高手 / 地狱档不再来回拉锯 ✅ 已落地

- **来源思路**：棋类 AI 的通病是「没事可做就原地蹭」。
  场面看着在动，其实一步没往前走，孩子会觉得电脑在发呆。
- **现状**：`scoreMove` 里没有任何「刚从那儿过来」的记忆，
  一枚子在两个格子之间来回挪的分数每一手都一样高。
- **落地方式**：`ai.ts` 加 `shufflePenalty(history, side, move, pieceId)`——
  走回上一手刚离开的那一格扣 22 分，同一对格子已经来回过一轮的翻倍。
  只在 `pro` / `hell` 两档生效（`normal` 保持「大子往前顶」的憨劲儿，
  `rookie` 本来就是随机挑）。分值刻意压得比吃子、进大本营都小，
  所以「实在没别的事可做」时它还是会走，不会因为躲罚分把子往嘴边送。
- **收益**（60 手之内同一枚子在同一对格子上最多来回几趟）：
  地狱档 1337 号局 **6 趟 → 1 趟**；高手档 5044 号局 3 → 1、8077 号局 3 → 1。
  既有的「地狱档 20 局对菜鸟档 ≥15 胜」「地狱档不落后于高手档」两条胜率断言仍然全绿。
- **风险与回滚**：只加了一项罚分，不改合法走法与胜负判定；
  回滚 = 删掉 `scoreMove` 里那一行 `score -= shufflePenalty(...)`。
- **测试**：`ai.test.ts` 新增 2 例——罚分函数本身的六种情形（换子 / 换方向 / 空历史 / 对手历史 / 翻倍），
  以及三个「改前真的会蹭」的种子局跑 60 手，最多只蹭 2 趟。

### L-A-5 · pool-stars：库边球先算清楚碰哪儿 ✅ 已落地

- **来源思路**：一库反弹的正确做法是「镜像求瞄准点 + 验证真实碰库点」。
  只做前一半就会打出一堆物理上根本不成立的线。
- **现状**：`bankPlans` 对每颗目标球 × 每个袋 × 四条库边无条件生成候选，
  既不检查母球到库边这一段通不通，也不检查这条线到底碰不碰得到那条库
  （镜像点可能在同一侧，那这一杆压根不碰库），打分里也没有库边那一段的路程。
- **落地方式**：新增 `cushionHit(from, mirror, side)` 求真实碰库点——
  方向不对、碰点落在库外、碰点压在袋口上（球会直接掉进去）三种情况一律不生成候选；
  再要求「母球 → 碰库点」与「碰库点 → 假想球点」两段都 `pathClear`，
  而且都不许从袋口边上蹭过去（新增 `clearOfPockets`，母球顺路掉袋等于白打）。
  打分与力度改按真实总路程算，力度上限压到 0.78——库边球不用打满，
  打满只会让母球满台乱窜。
- **收益**：己组球贴着上库、直线被三颗对手球挡死的局面里，
  高手档从「先撞上对手的球（犯规）」改成先碰到自己那一组；地狱档照旧打进。
- **风险与回滚**：候选变少可能让高手档更常退回「软软碰一下」的保守杆，
  既有的「高手档明显打得过普通档」「地狱档 20 局压制菜鸟档」都还是绿的。
  回滚 = 把 `bankPlans` 里那三行 `continue` 去掉。
- **测试**：`ai.test.ts` 新增 3 例——`cushionHit` 的四种边界、`clearOfPockets` 的两种线、
  以及「高手档在只能打库边球的局面里先碰到自己那一组」。

### L-A-6 · fruit-stack：普通档不往顶到警戒线的那一摞上压 ✅ 已落地

- **来源思路**：合成类的核心风险是「越线」，而最容易越线的动作就是
  「哪儿有同级的就往哪儿丢」——同级果子往往正在最高的那一摞顶上。
- **现状**：普通档 `bestMatchX` 挑的就是「场上最靠上的那颗同级果子」，
  完全不看那一列离警戒线还剩多少。
- **落地方式**：新增 `columnCrowded(w, x, level)`——用既有的 `heightMap`
  量那一列的堆顶，离警戒线不足一颗直径就算「压不得」，改投最低洼的那一段。
- **收益**（八个种子、每局最多 90 投）：总分 11013 → 11716（+6.4%），
  总投放 340 → 364（多撑 7% 的球），越线局数不变。
  普通档还是「对准同级」的憨打法，只是不再自己把自己顶出去。
- **风险与回滚**：只改普通档这一支，高手 / 地狱的推演一行没动；
  既有的「普通档会对准同级的那颗」断言仍然绿（那一摞不高就照旧对准）。
  回滚 = 把 `skill === 2` 那一支改回 `match ?? 随手一丢`。
- **测试**：`ai.test.ts` 新增 2 例（高柱上的同级不去压、低处的同级照旧对准）。

### L-A-7 · dot-maze：小幽灵错峰出巢 ❌ 本轮不落地

- **来源思路**：街机迷宫类的经典节奏是「一只先出、其余按豆数 / 时间陆续出」，
  开局那几秒玩家有喘息，越到后面压力越大。
- **现状**：`createRun` 把 `ghostCount` 只全摆在巢门口，第一帧起全员在场。
- **落地方式**（给下一轮）：`Ghost` 加 `releaseMs`，`RunState` 里按「已吃豆数 + 已用时」放人，
  掉命重置时重新计时；档位表里给四档不同的放人节奏。
- **不落地的原因**：这一改会整体拉低前几关的难度曲线，
  `dummySurviveMs` 那条「地狱档让假人活得更短」的回归断言与 188 关的三星门槛
  都要跟着重标一遍——属于「难度重标定」，不该塞进验收轮里顺手做。
- **收益 / 风险**：收益是开局手感明显变友好；风险是难度曲线要重跑一遍。

### L-A-8 · dot-maze：能量豆按「路口 / 角落」布点 ❌ 本轮不落地

- **现状**：能量豆位置由 `buildMaze` 的生成器按 seed 撒，
  有时候四颗挤在同一片区域，「绕圈反攻」的路线不成立。
- **落地方式**（给下一轮）：生成器在撒能量豆时优先挑「离其它能量豆最远的路口格」。
- **不落地的原因**：动 `maze.ts` 会改变全部 188 关的地图输出，
  可清性、豆子总数、三星门槛与既有关卡手感都要重验，改动面超出本轮。

### L-A-9 · pool-stars：高手档加一次「母球会不会掉袋」的轻预演 ❌ 本轮不落地

- **现状**：高手档完全不预演（`previewShot` 只有地狱档用），
  所以偶尔会打出「球进了、母球也跟着进了」的一杆。
- **落地方式**（给下一轮）：给高手档加一次只看母球去向的预演，
  不看走位（走位仍是地狱档独有），介于普通与地狱之间。
- **不落地的原因**：这会直接抬高高手档的实力，
  `aiWinRate([3,2])` 与 `aiWinRate([4,1])` 两条胜率断言的门槛要重新标定，
  同样属于难度重标定。

### L-A-10 · junqi-camp：把踩出来的地雷记进 `Knowledge` ❌ 本轮不落地

- **现状**：`knownInfo` 记得住对方暴露过的子，但「哪一格踩出过地雷」这件事
  只体现在 `combat` 事件里，`scoreMove` 没有专门绕开已知雷位的项。
- **落地方式**（给下一轮）：`Knowledge` 加一个 `mines: Set<Pos>`，
  高手 / 地狱档对已知雷位除工兵外一律重罚。
- **不落地的原因**：要改 `rules.ts` 里被界面、AI、测试三处共用的 `Knowledge` 结构，
  本轮刻意把改动面压在「一个纯函数模块之内」。

### L-A-11 · chess-garden：静态搜索加 SEE / delta 剪枝 ❌ 本轮不落地

- **现状**：`quiesce` 把所有吃子与升变一律往下延伸，没有 SEE 过滤，
  明显亏的吃子也会被算一遍。
- **落地方式**（给下一轮）：写一个 SEE（静态交换评估），
  在静态搜索里丢掉净亏的吃子，并加 delta 剪枝。
- **不落地的原因**：SEE 本身是一块需要单独写测试的新逻辑，
  而且要连着 L-A-3 一起做棋力回归；本轮先把置换表这一处结构性浪费收掉。

### L-A-12 · fruit-stack：地狱档「第二眼」的撒点按下一颗的半径来 ❌ 本轮不落地

- **现状**：`scoreCandidate` 里预演下一颗时固定撒 5 个点、间距按盆宽均分，
  下一颗要是「籽」（r=9）这 5 个点就太稀，要是「玉瓜」（r=76）又几乎重叠。
