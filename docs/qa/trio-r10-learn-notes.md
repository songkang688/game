## 四、系统性模式提炼（r4 A/B/C、r5 D/E/F、r6 G/H、r8 I/J、r9 K 仍有效，本轮补一条）

### 模式 L · 共享容器的验收要拿「内容最长的实例」当样本（N-40 机理）

- **机理**：`.dialog` 家族「max-height + 内滚」的病,伤面 = 内容高 − 可视高。用短内容实例（结算弹窗 511px）量,只暴露矮横屏档（N-33）；换长内容实例（家长面板 ≈800px）,连 1024×768 桌面档都中（N-40）。同一容器规则,**短实例干净 ≠ 家族干净**。
- **配方**：grep `showDialog` 调用点列出实例清单（结算 / 暂停 / 家长门 / 家长面板 / rootGate / 跳关确认…）,按内容高排序,**取 top2 进验收矩阵**——最长的定伤面上限,次长的防单点侥幸。
- 与 K（机制看接线）呼应：K 管「调用路径」维度,L 管「内容装载」维度——共享件验收两个维度都要铺,行为参数矩阵 × 内容极值矩阵。

### 合流纪律提炼（写给 r10 的 A/B,本轮最大的非代码风险）

- 并行修复轮次里,**同职能双分支（①②这类双 A 并行）是纯浪费 + 纯冲突**,比漏修更伤——下轮开工前先 `git fetch` 列全在途分支,同账目只留一路,另一路只挑独有增量。
- 陈旧基点是定时炸弹：⑤ 落后主干四轮（r5 时代基点）,冲突文件从 r9 预警的 4 个涨到 8 个。**在途分支每轮至少 rebase 一次**,别攒到合流日一次爆。
