## 1. 调研：11 条候选（≥8），标明哪几条打算落地

### `gomoku`（全程避开 `ai.ts`）

**C3 · 落子确认的预览点会过期** —— **落地**（口径已修正，见下）
第 1 轮转交时的说法是「预览点被对手占了，`pending` 还指着那一格」。
本轮**逐路径复核后发现现状不可达**：`play()` 与 `undo()` 都会无条件 `confirmState = emptyConfirm()`，
而 `humansTurn()` 在 `thinking` / `claim` 期间为 false，对手根本没有机会在预览点还活着的时候落子。
但这条**不是白跑**：`view.ts` 画预览点前**自己**查了一次 `cells[...] === 0`
（`view.ts:359`），也就是说「预览点可能落空」这件事视图层是防了的、状态层没防，
两边靠 `index.ts` 每一处都记得清一次来兜住。这是典型的**靠调用方守纪律**的约束。
→ 把这条约束放回纯函数里：新增 `pruneConfirm()`，视图与状态用同一把尺。

**C4 · 连胜开局播报没有「这一档什么脾气」** —— **落地**
`DIFFICULTY_BLURB` 六档各有一句话，自由对战的开局播报里有
（`index.ts:786`），连胜挑战的开局播报里**没有**（`opening: streakOpening(streak)`）。
下一档的脾气只在上一盘的结算浮层里出现一次，点掉「继续挑战」就再也看不见了；
而第 1 盘（`wins === 0`）压根没有任何一档说明。
→ `streakOpening(s, blurb)` 收一个可选的档位说明，和自由对战一个口径。

**G13 · 键盘光标一路走下来，读屏器一个字都不播** —— **落地**（本轮新发现）

→ 新增纯函数 `cursorLabel()`，方向键与落子后同步刷 `aria-label`。

## 3. 落地细节（计划的 6 条全部落地）

每条一个独立 commit，改完就跑该款自带用例 + `tsc --noEmit`。

### C3 · `gomoku` 落空的预览点（`session.ts` + `index.ts`）

先说复核结论，因为它改变了这一条的写法：**第 1 轮描述的那条路径在现有代码里走不通。**
逐路径查过：

| 会不会留下一个指着「已经有子」那一格的 `pending` | 结论 |
| --- | --- |
| 人落子 → `play()` | 无条件 `confirmState = emptyConfirm()`，清了 |
| AI 落子 → `scheduleAi()` → `play()` | 同上，清了 |
| 悔棋 → `undo()` | 无条件清了 |
| 开 / 关确认按钮 | 无条件清了 |
| 对手趁我有预览点时抢先落子 | `humansTurn()` 在 `thinking` / `claim` 期间为 `false`，人根本预览不上 |

所以这不是一条能复现的缺陷，但**也不是白跑的一条**：`view.ts:359` 画粉圈之前
**自己**查了一次「这一格还空着吗」，状态层却没有同一道闸 —— 同一条约束写在两个地方，
其中一处靠 `index.ts` 每一个落子 / 悔棋路径都记得手动清一次来维持。

```diff
+export function pruneConfirm(state: ConfirmState, isEmpty: (cell: Cell) => boolean): ConfirmState {
+  const p = state.pending;
+  if (!p) return state;
+  return isEmpty(p) ? state : emptyConfirm();
+}
```

`refresh()` 里过一道，视图与状态从此用同一把尺。
没有预览点、或预览点还有效时**连对象都不换**（用例用 `toBe` 钉死了这一点），不制造多余的重渲染。

### G13 · `gomoku` 键盘光标的读屏播报（`session.ts` + `view.ts`）

棋盘是 `<canvas role="application" tabindex="0">`，`aria-label` 原先是建好就再也不变的
一句「五子棋棋盘，方向键移动、回车落子」。方向键把 `cursor` 挪遍全盘、
`state.ghost` 跟着画十字准星 —— 屏幕上什么都对，accessibility tree 上**一个字都没变**。

新增 `cursorLabel(cell, size, info)`，方向键与 `update()`（换手 / 换预览点 / 换盘）时同步刷：

```
棋盘第 8 行第 8 列，正中间天元。这里是空点。按回车先出预览，再按一次才落子；方向键换位置。
棋盘第 5 行第 6 列。这里是白棋。这一格有子了，换个空点；方向键换位置。
棋盘第 8 行第 8 列，正中间天元。这里是等着确认的预览点。再按一次回车就落子；方向键换位置。
棋盘第 3 行第 3 列。这里是空点。现在轮不到你，先等一等；方向键换位置。
```

位置放最前、操作说明垫最后：读屏器随时可以打断，先听到的永远是「我在哪儿」。
`ViewState` 多收一个 `confirm` 字段，只为了播报「按回车是预览还是落子」，不参与任何绘制。

**这里报行列号不违反「提示不报坐标」那条口径** —— 报的是光标自己的位置（用户按出来的），
不是答案在哪儿。用例里专门放了一条把两者摆在一起看：
`hintArea().text` 仍旧一个数字都没有，`cursorLabel()` 才报「第 8 行」。

### C5+M16 · `match-stars` 卡壳指路（`board.ts` + `index.ts`）

`board.ts` 加三个纯函数：

| 函数 | 干什么 |
| --- | --- |
| `bestHintSwap(s)` | 遍历 `legalSwapsOn(s)`，挑收成最大的一步。彩虹星按「全场那种图案」算，特殊块按引爆范围算，普通三连按盘面多出来的匹配格算 |

### C8 · `rainbow-run` 收场时的幽灵战报（`ghost.ts` + `index.ts`）

```diff
+export function ghostOutcome(meters: number, ghost: GhostRun | null): GhostGapState | null {
+  if (!ghost) return null;
+  return ghostGap(Math.floor(...), ghost.meters).state;
+}
-export function beatsGhost(meters, ghost) { return !!ghost && Math.floor(meters) > ghost.meters; }
+export function beatsGhost(meters, ghost) { return ghostOutcome(meters, ghost) === "ahead"; }
```

`beatsGhost()` 变成三态的薄封装，**对外行为一个字节没变**：
用例拿 `[299, 299.9, 300, 300.4, 300.6, 301, 9999]` 逐个米数比对了新旧两种算法。
名牌（`ghostGap`）与收场（`ghostOutcome`）从此是同一把尺 ——
以前名牌一路写着「并排跑着呢」，收场却按「没赢」处理，是两套口径。

`ghostResultLine()` 三句话：

```
👻 比上一趟的自己多跑了 20 米,幽灵换成这一趟啦!
👻 和上一趟的自己跑成平手,都是 300 米!
👻 上一趟跑到 300 米,这次差 20 米就追上了。
```

`index.ts`：`ghostRaced` 在开跑时记下这一趟同场跑的是哪一份快照，
