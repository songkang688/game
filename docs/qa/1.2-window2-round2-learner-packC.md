## 1. 调研：11 条候选（≥8），标明哪几条打算落地

### `gomoku`（全程避开 `ai.ts`）

**C3 · 落子确认的预览点会过期** —— **落地**（口径已修正，见下）
第 1 轮转交时的说法是「预览点被对手占了，`pending` 还指着那一格」。
本轮**逐路径复核后发现现状不可达**：`play()` 与 `undo()` 都会无条件 `confirmState = emptyConfirm()`，
而 `humansTurn()` 在 `thinking` / `claim` 期间为 false，对手根本没有机会在预览点还活着的时候落子。
但这条**不是白跑**：`view.ts` 画预览点前**自己**查了一次 `cells[...] === 0`
（`view.ts:359`），也就是说「预览点可能落空」这件事视图层是防了的、状态层没防，
两边靠 `index.ts` 每一处都记得清一次来兜住。这是典型的**靠调用方守纪律**的约束。
→ 把这条约束放回纯函数里：新增 `pruneConfirm()`，视图与状态用同一把尺。

**C4 · 连胜开局播报没有「这一档什么脾气」** —— **落地**
`DIFFICULTY_BLURB` 六档各有一句话，自由对战的开局播报里有
（`index.ts:786`），连胜挑战的开局播报里**没有**（`opening: streakOpening(streak)`）。
下一档的脾气只在上一盘的结算浮层里出现一次，点掉「继续挑战」就再也看不见了；
而第 1 盘（`wins === 0`）压根没有任何一档说明。
→ `streakOpening(s, blurb)` 收一个可选的档位说明，和自由对战一个口径。

**G13 · 键盘光标一路走下来，读屏器一个字都不播** —— **落地**（本轮新发现）
棋盘是 `<canvas role="application">`，`aria-label` 是**建好就再也不变**的一句
「五子棋棋盘，方向键移动、回车落子」（`view.ts:122`）。
方向键把 `cursor` 挪遍全盘、`state.ghost` 跟着画十字准星，
但 accessibility tree 上**没有任何变化** —— 看不清屏幕的孩子按了半天方向键，
不知道自己在哪、那一格有没有子、按回车是落子还是先出预览。
→ 新增纯函数 `cursorLabel()`，方向键与落子后同步刷 `aria-label`。

**G14 · 提示用完之后那句话实际播不出来** —— **列出，不落地**
`hintButtonHint()` 的 `left <= 0` 分支写得很好，但 `refresh()` 里
`hintBtn.disabled = hints.left <= 0 || ...`，禁用按钮多数读屏器直接跳过，
`title` / `aria-label` 都到不了用户耳朵里。
→ 想修得干净要动「禁用 vs 可点但给解释」的交互口径（可点会多一次音效与焦点跳转），
属于交互改动而不是文案改动，超出本轮「小而稳」，转交。

**G15 · 「能力单调」基本功电池从 `normal` 起就满分** —— **列出，不落地**
第 1 轮测试员第 7 节观察项 2。这把尺分不出上面四档。
→ 换考卷会直接动到 `tiers.test.ts` 的相邻档回归口径，**本轮红线明令不许碰**，转交。

### `match-stars`（时间线一段不拆）

**C5 · 死局直接洗牌，不给「先自己找一步」的机会** —— **落地**（缩到「小而稳」的一半）
第 1 轮的原方案是「卡住 N 秒闪一下」，要动 DOM 与计时，所以当时整条搁置。
本轮把它拆成两半，只落**不碰 DOM、不碰计时**的那一半：
`board.ts` 出纯函数 `bestHintSwap()`（挑消得最多的一步，稳定 tie-break）
与 `stuckHintLine()`（只说方位、不报行列号），
挂在**已经存在**的 `onRevert` 回调上 —— 连着换错 3 次才说一句，不新增任何定时器。
「闪一下」那一半仍旧转交。

**M16 · 换错时的三句解释里，「换了消不掉」那句没有任何下一步** —— 并入 C5 一起落地
`onRevert` 现在只有「这样换消不掉，不算步数～换个方向再试～」，
连着撞墙五六次说的还是同一句。C5 的指路正好补在这里。

### `rainbow-run`（`view3d.ts` / `controls.ts` 一个字节不动）

**C8 · `beatsGhost()` 只有两态，而且结算面板压根没提幽灵** —— **落地**
第 1 轮把三态口径落在**名牌**上（`ghostGap` / `ghostGapLine`），
但 `beatsGhost()` 本身还是 `Math.floor(meters) > ghost.meters` 的布尔值，
而且 `index.ts` 里**一次都没调用它** —— 一趟跑完，`drawRetryPanel()` 只报米数和糖果，
「跟上一趟的自己比赢了没有」这件事孩子只能自己拿两个数字相减，追平更是无从说起。
→ 补 `ghostOutcome()` / `ghostResultLine()` 三态，`beatsGhost()` 改成同一把尺的薄封装
（对外行为一个字节不变），结算面板补一行幽灵战报。

**R17 · 第 1 关摆烂也能通关** —— **列出，不落地**
第 1 轮测试员第 7 节观察项 1，1.1 逐字节继承的教学关设计。
要加失败分支就是改关卡参数，属于产品决策，转交。

### `ocean-munch`（`LEVELS` 与 `ENDLESS_TIERS` 一个数不动）

**O18 · 水压把你压小的时候，HUD 只报上限，不说「你正在被压小」** —— **落地**（本轮新发现）
第 5 层起 `pressureDrain()` 每帧把超过 `sizeCap` 的体型往回削，
但 HUD 那一行（`index.ts:2309`）**只有两种状态**：吃到精英鱼是
「💫 顶住水压 N 秒（上限 M）」，其余一律「🕳 水压上限 M」——
**不管你现在是安全的还是正在被压小，印的是同一句话**。
孩子看到的现象是「我明明一直在吃，鱼却越来越小」，屏幕上没有一个字解释。
整段还是内联在 canvas 绘制里现拼的，和 C10 修之前的饥饿预警一模一样，没有纯函数、没有用例。
→ 提成 `pressureState()` / `pressureLine()` 两个纯函数，分 `none` / `safe` / `squeezed` 三档，
被压小时明说原因和解法。**`PRESSURE_DRAIN`、`sizeCap`、`ELITE_BREAK` 一个数都不动**，
只改这一行字怎么写。

**O19 · 深层难度是双份的（越挤 + 越吃不饱）** —— **列出，不落地**
第 1 轮 C9 修掉了「深层长不出条纹鱼」的尺寸归一化，成长断档解决了，
但「越深越挤」和「越深上限越低」仍旧叠加。
→ 调这个要动 `ENDLESS_TIERS` 的档位数值，**红线明令不许碰前 99 关与既有参数口径**，转交。

### `xiangqi`（只升级既有目录）

**C12 · 电脑求和门槛写死 40 手，而且这条规则被抄了两份** —— **落地**
`session.ts:132` 有纯函数 `aiAgreesDraw(materialDiff, plies)`，有用例；
`index.ts:635` 却又把 `Math.abs(diff) <= 60 && entries.length >= 40` **原地抄了一遍** ——
纯函数改了 UI 不跟着改，这是一定会走散的两份。
门槛本身也有问题：`plies >= 40` 不看盘面稀不稀，两边只剩单车残棋、明摆着和了，
也得先凑满 40 手；而拒绝时只回一句「对手还想再下下去」，
**不说是子力差太大还是手数不够**，孩子不知道该继续兑子还是继续走。
→ ① `index.ts` 改成真的调 `aiAgreesDraw`（一把尺）；
② 门槛按**盘面还剩多少子**放宽（子越少门槛越低，满盘仍是 40 手，老口径一字不变）；
③ 补 `drawRefusalLine()` 说清差在哪儿。

**X20 · 上两对相邻档实战大量和棋** —— **列出，不落地**
第 1 轮测试员第 7 节观察项 3。强档一局没输，不构成倒挂。
→ 要拉开差距得放宽封手数或时间预算，直接动强度曲线，转交。
