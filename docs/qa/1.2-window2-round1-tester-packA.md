## 一、走查记录

走查方式：仓库没有 jsdom，五款各自带的 `domStub.ts` 就是这一轮的「手」——
它把 `document` / `window` / `requestAnimationFrame` / `performance` / `matchMedia` 全换成能数数的桩，
于是「点这个按钮」= `dispatch("click")`，「按这个键」= `fireWindow(dom,"keydown",…)`，
「过了一帧」= `flushFrames`。走的都是 `index.ts` 里那一份真代码，没有把结果硬塞进回调。
`installDom(360)` 就是铁则 4 要的窄屏。

结论一句话：**5 款全部可玩，没有阻断；3 条严重都集中在「窄屏热区」和「双人/暂停的输入归属」上。**

## 四、本轮没做到的，留给后面几轮

- 对战 / 无尽这两种「随机开局、上限 400 手」的玩法，没有在无头环境里跑完一整局到自然结算：
  junqi-camp 走的是同一条 `createTable` 代码路径、用可解的残局与手数上限把结算逻辑跑到了，
  但「随机整局打到底」这件事本轮只在 fruit-stack 的既有 `smoke.test.ts` 里有（八张对战盆分胜负）。
- 真机 / 真浏览器上的触屏手感与 360px 实际渲染没有验（本轮全部是 DOM 桩上的度量与 CSS 静态计算）。
- 商标扫描是词表匹配，不是图形 / 音效相似度审查。
