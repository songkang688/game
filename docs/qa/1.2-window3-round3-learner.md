## 〇、这一轮换什么样本

- 第 1 轮盯**手感输入**：`prince-princess` 的土狼时间 / 跳跃缓冲，
  外加两处「档位表里写了、没人读」（`bowling-lane` 补中策略、`tank-battle` 开火距离）。
- 第 2 轮盯**档位到底算不算数**：把带档位的几款两两拉出来真打一场看谁赢，
  量出 `bumper-cars` 四档打不过二档、`snow-fight`「风向大师」和初学者算的是同一阵风、
  躲球阈值把反应慢的档次算成躲得最早、`tank-battle` 的 `think` 全仓库无人读取。

第 3 轮换第三个角度，也是前两轮反复撞见同一类东西之后必须收的一条口：

> **同一件事在仓库里有几份定义？真正在跑的是哪一份？**
> 以及更要命的一步——**单测断言的，是不是真正在跑的那一份？**

前两轮抓到的都是「写了没人读」（死参数）。这一轮要抓的是它的孪生兄弟：
**写了两份、读的是另一份**。这一类比死参数更危险——死参数至少不骗人，
而两份定义会让「绿的单测」和「上场的代码」各说各话：
断言天天绿，孩子玩到的却是另一套数。

## 一、本轮清单（10 条，拟落地 3 条）

排序按「孩子当场能感觉到」的程度，不按实现难度。

### 1. `duo-arena` 一款游戏两张人机四档表，上场的是没被断言的那张 —— **拟落地**

- `ai.ts/AI_SPECS` 反应 0.85 / 0.48 / 0.30 / 0.18，`index.ts` 走 `createBrain` 用它，**这张真上场**。
- `arena12.ts` 另有一张手写表：反应 0.62 / 0.40 / 0.22 / 0.16、漏点 0.4 / 0.2 / 0.07 / 0.02，
  **只被单测读，一次都没上过场**。
- 最难看的是 `ARENA_AI_HINTS` 里写给孩子看的那句「它也要 0.22 秒才反应过来」——
  高手档真跑的是 0.30 秒。这句话的全部用处就是告诉孩子「抢那半拍」，数字错了就是骗人。
- 拟落地：`arena12.ts` 这一节**一个数都不再手写**，全部从 `AI_SPECS` 推。

### 2. `duo-arena`「地狱档也必须留反打窗口」这条硬规矩没兜在真跑的那条路上 —— **拟落地**

- `MIN_COUNTER_WINDOW_S = 0.15` 只在 `arena12.ts`（那张不上场的表）里有 `Math.max`。
- 真正在跑的 `thinkAi()` 直接读 `spec.reactionS`，**下限一次都没兜住过**：
  谁把规格表里那个数改成 0，地狱档当场变成 0 帧完美反应，**没有一条断言会红**。
- 拟落地：下限收进 `ai.ts` 的 `reactionOf()`，所有读反应时间的地方都走它。

### 3. `bomb-buddies` 单测跑的电脑，和上场的电脑不是同一个 —— **拟落地**

- `AI_TUNING.thinkMs`（260 / 150 / 70）**全仓库没有一处生产代码读它**，
  只有 `ai12.test.ts` 断言它单调。同一组数字在 `index.ts` 里被手抄了一份三元表达式。
- 更要命的是 `ai12.test.ts` 的胜率对局**每 20ms 就重想一次**，
  也就是把三档的思考节奏全抹平了——那条「固定 seed 的胜率」回归线量的是一个**不存在的电脑**。
- 拟落地：`thinkMs` 变成唯一真源，节奏逻辑挪进 `ai.ts` 让上场与单测共用一份；
  补一条按真节奏跑的阶梯对局。既有断言一条不动。

### 4. `snow-fight` `duckTime` 三档同值 —— **实测后决定不落地，写清原因**

- 第 3 轮真改过一版 0.55 / 0.45 / 0.35，量下来只有中间档动了，首尾一动没动。
- 原因是这个字段**够不着**：它只在「看见对面举球、主动蹲一下」那条路上生效，
  而初学者的 `dodge` 只有 0.05/秒。分一个它几乎摸不到的参数只会把中间档削薄。
- 收口动作：把这段实测结论写进 `brains.ts` 的注释，让下一个人不用再试一遍。
