#### C1-01　推箱小仓鼠：双鼠宽仓在 360px 上被切掉右边几列

- **根因**：格子边长是媒体查询写死的（`42 / 34 / 28`），跟棋盘有几列**毫无关系**。
  13 列的双鼠宽仓需要 `13 × 34 + 12 × 2 = 466px`，360px 手机上留给棋盘的只有 332px。
  偏偏 `.game-stage` 是 `overflow:hidden` —— 超出的 4 列不是能滑出来，是**直接看不见也点不到**。
- **修法**：
  1. `assist.ts` 新增纯函数 `fitCell(cols, avail)` / `boardWidth(cols, cell)` 与三个常量
     `CELL_GAP = 2` / `CELL_MAX = 42` / `CELL_MIN = 18`——按「还剩多宽」倒着算边长，夹在上下限之间取整；
  2. `index.ts` 新增 `fitBoard()`：量 `.bh-stagebox` 的内容宽度，写进 `--cell`。
     建棋盘时量一次、换关（`swap`）时量一次、`resize` / `orientationchange` 各量一次；
     挂载那一刻可能还没上屏量不出来，所以再补一帧 `requestAnimationFrame`。
     量不到宽度就**什么都不写**，留着 CSS 里原来那一档兜底，绝不会写出比原来更差的值。
- **为什么 `CELL_MIN` 敢取 18**：棋盘格子只负责「看」，走位靠键盘方向键和触屏方向盘，
  没有任何一个格子是点得动的，所以不受 44px 触摸下限管。实测 360px 上最宽的 13 列只需要 **23px 一格**，
  离下限还远。
- **宽屏没有被连累**：768px 上 7~9 列仍然是满格 42px，和改之前一模一样。
- **验证**：从 320px 到 1024px 共 9 档屏宽 × 188 关 + 24 个无尽仓，**逐个**算宽度，一处不溢出。
  高度也顺带体检：360×640 老机器上最高的一关也没吃掉 HUD 和方向盘的位置。

### 三、`destroy` 泄漏体检

| `box-hamster` | 3 挂 / 3 摘（本轮新增的 `resize`、`orientationchange` 一并摘） | 有 / 有 cancel | — | 1 / 1 | 干净 |
| `bubble-aim` | 3 挂 / 3 摘 | 有 / 有 cancel | — | — | 干净 |
| `snake-snack` | 3 挂 / 3 摘 | 有 / 有 cancel | — | 1 / 1 | 干净 |
| `memory-cards` | 0 | — | 2 / 2 clear | 用 `timeouts` 集合统管，回调里自己 `delete`，`destroy` 里整批 clear | 干净 |

另外三条闸门：**不许**给全局监听塞匿名函数（塞了就再也摘不掉）；每一款都得有 `destroy`

本轮新加的 `resize` / `orientationchange` / `requestAnimationFrame` 是这一轮唯一新增的三个资源，

### 二、W4A-01（严重）· 礼物气球暗扣星

**现象。** 第 129–188 关里整整 28 关（129–144、172–173、175–176、178–179、181–182、184–185、187–188）会放礼物气球，但它们的目标类型是「戳够数量 / 只戳指定颜色 / 按顺序戳」，**不是**「护住礼物气球」。HUD 上写的是 `🎯 戳红色` 之类，从头到尾一个字都没提礼物。可 `index.ts` 里礼物飘走时无条件 `giftLost++`，结算 `starsFor(mistakes, escaped, giftLost)` 又按 `giftLost × 2` 计入扣分档。

于是孩子看到的是：一个该戳的没漏、一次没戳错，结算却只有一星。**扣分的理由从来没有露过面。** 这直接违反「规则必须先讲清楚」和「失败只鼓励」两条。

**修法。** 把 `giftLost` 的语义收紧成「**该护住却没护住**的礼物」，而不是「飘走的礼物」：

- `logic.ts` 新增 `giftGuarded(kind: GoalKind): boolean`，只有 `protect` 返回 `true`；
- `index.ts` 的逃逸分支改成 `if (giftGuarded(goal)) { giftLost++; msgEl.textContent = "🎁 礼物飘走啦……" }`——记账和那句鼓励绑在一起，以后不会再出现「扣了分却没说话」；
- `logic.ts` 的 `simulateLevel` 同步收紧，两边口径一致；
- `GoalState.giftLost` 与 `starsFor` 的注释写明这层含义。

**为什么不是「给非保护关也加一个礼物 HUD」。** 礼物在非保护关里戳不破（点一下只是摇一摇）、不是目标、不占爱心，它就是个不能戳的路人。给它加 HUD 等于凭空多一条要盯的规则；把不该记的账取消掉才是对的。真正的护礼物关（6 关）一个字没动：礼物飘走照样过不了关、照样拿不到三星。

**验证。** 28 关逐关模拟 `giftLost === 0`；6 关护礼物关照旧 `won === true` 且 `giftLost === 0`；188 关全量复跑没有一关因为礼物掉星。

### 四、`destroy` 无泄漏复核

五款各自的资源看管类都用可注入的假宿主跑了一遍：

| 款 | 看管类 | 管的东西 | 结论 |
| --- | --- | --- | --- |
| brave-path | `Cleanup`（`cleanup.ts`） | timeout / interval / rAF / 监听 | `destroy()` 后 `pending() === 0`，四类各清一次 |
| brick-break | `Janitor`（`logic.ts`） | timeout / rAF / 监听 | 同上；宿主没有 rAF 时 `frame()` 返回 0 也不崩 |
| balloon-pop | `Janitor` | timeout / interval / rAF / 监听 | 同上 |
| fruit-catch | `Janitor` | timeout / rAF / 监听 | 同上；双人同屏的两套键位监听都摘得干净 |
| lianliankan | `Janitor` | timeout / interval / 监听 | 同上；连线动画那三段接力 timeout 在 destroy 后一个都不回调 |

三条共性断言每一款都过了：

1. `destroy()` 之后 `pending()` 归零、`dead === true`，假宿主的 clear 计数与注册数一一对上；
2. `destroy()` 之后再手动触发挂起的回调，一个都不执行；
3. 摘监听时某一条抛错，剩下的照样摘干净、`pending()` 照样归零。

外加对 `index.ts` 的静态复核：每一款的每个入口（闯关 / 无尽 / 对战或双人 / 外层壳）都有自己的 `destroy()`，都会 `cancelAnimationFrame` 并收在 `jan.destroy()` / `cleanup.destroy()` 上，外层 `destroy` 会顺手带走子界面。
