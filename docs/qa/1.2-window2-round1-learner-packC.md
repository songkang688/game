## 1. 调研：八条可落地的改进（≥8）

### `gomoku`（全部避开 AI 相邻档主路径）

**C1 · 连胜挑战缺「破纪录」实时反馈**（落地）
`streakLine()` 只播报「已经连赢 N 盘，下一位是 X」，整轮里**从不提历史最高**；
`streakSummary()` 只在这一轮结束后才说纪录。孩子打到第 4 盘时并不知道自己离纪录还差几盘，
真的破纪录的那一盘也只弹「🎉 连赢 N 盘」，和平常一盘没有任何区别。
→ 补「还差几盘破纪录 / 已经破纪录」的进行时播报，并让结算面板认得出「刚刚破纪录」。

**C2 · 提示（hint）文案不分级**（落地）
`hintArea()` 每次都是同一句「好棋就在……」：
用掉最后一次提示时不说「这是最后一次」，解局模式用提示前也不提「用了就封顶 2 星」
（`puzzleStars()` 明明是这么算的，但玩家点下去之前看不到这个代价）。
→ 按「还剩几次 / 是不是解局」拼一句带后果的提示文案。

**C3 · 落子确认的预览点会过期**（列出，不落地）
`tapCell()` 只在「点到已有子」时清 `pending`。若预览点被对手（AI / 同屏另一人）先占了，
`ConfirmState.pending` 仍指着那一格，视图还画着粉圈，玩家再点一次会被判成 `move`。
→ 建议加一个 `pruneConfirm(state, board)`，换手时把落空的预览点摘掉。

**C4 · 连胜开局播报没有「这一档什么脾气」**（列出，不落地）
`DIFFICULTY_BLURB` 已经有六档的一句话说明，但连胜模式的 `opening` 只给 `streakLine()`。
→ 建议把档位脾气拼进开局播报，和自由对战口径一致。

### `match-stars`（时间线一段不拆）

**C5 · 死局直接洗牌，不给「先自己找一步」的机会**（列出，不落地）
`reshuffle` 一发现 `legalSwaps() === 0` 就洗牌。但真正卡住孩子的是
「还有一步能消、我找不着」的局面，这时游戏不提供任何指路。
→ 建议 `board.ts` 加纯函数 `bestHintSwap()`（挑消得最多的一步、稳定 tie-break），
留给视图层做「卡住 N 秒闪一下」。**这条要动 DOM 与计时，超出本轮「小而稳」的口径，先列不落。**

**C6 · 洗牌失败是静默的**（列出，不落地）
`shuffleOn()` 洗不出来时返回 `false`，`index.ts` 只在 `ok` 时写文案，失败分支一个字都没有。
→ 建议补一句「这一盘实在挪不开了」的兜底文案。

### `rainbow-run`（`view3d.ts` / `controls.ts` 一个字节不动）

**C7 · 幽灵竞速只画名牌，不播报领先 / 落后**（列出，不落地）
`ghostMetersAt()` 已经算得出「上一趟这一刻在第几米」，但没有配套文案，
玩家得自己拿两个数字相减。
→ 建议 `ghost.ts` 加 `ghostGapLine(meters, ghostMeters)` 纯函数。

**C8 · `beatsGhost()` 打平时归到「没赢」，却没有平局口径**（列出，不落地）
`Math.floor(meters) > ghost.meters` 严格大于才算赢，正好追平时和落后一样什么都不说。
→ 建议补一个三态返回（领先 / 追平 / 落后）供结算文案用。

### `ocean-munch`（`LEVELS` 一个字符不动）

**C9 · 深层小鱼尺寸归一化算错，第 7–9 层「条纹鱼」绝迹**（落地，本包最实的一条）
`spawnEndlessFish()` 里小鱼那一段：

```
const smallShare = Math.max(0.42, 0.7 - spec.bigFishBias);
if (roll < smallShare) {
  const t = (roll - spec.toxinRate - spec.eliteRate) / Math.max(1e-6, smallShare);   // ← 分母错了
```

毒藻鱼和精英鱼吃掉的是 `roll` 区间的**前一段**，所以小鱼段真实区间是
`[toxinRate + eliteRate, smallShare)`，分母应当是 `smallShare - (toxinRate + eliteRate)`。
现在拿整个 `smallShare` 当分母，`t` 永远到不了 1，而且层数越深压得越扁：

| 层 | 小鱼段区间 | 旧 `t` 上界 | 旧「最大小鱼」倍率 | 还出得了条纹鱼吗（≥0.5×） |
| --- | --- | --- | --- | --- |
| 1 | [0.02, 0.66) | 0.97 | 0.727 | ✅ |
| 3 | [0.13, 0.60) | 0.78 | 0.645 | ✅ |
| 6 | [0.27, 0.53) | 0.49 | 0.516 | ✅（只剩一条缝） |
| 7 | [0.31, 0.51) | 0.39 | 0.473 | **❌** |
| 8 | [0.34, 0.50) | 0.32 | 0.441 | **❌** |
| 9 | [0.38, 0.50) | 0.24 | 0.406 | **❌** |

后果有三层：① 第 7–9 层只剩 `minnow`，中号鱼这一档从画面上消失；
② `growEndless()` 的收益 ∝ `preyR / r`，深层每口都特别小，成长直接断档；
③ 越深越吃不饱，和「越深越挤越危险」叠在一起，深层难度是双份的。
→ 只改**尺寸归一化**，`toxin / elite / small / big` 四段的**出现概率一个都不动**
（所以现有的「层数越深毒藻鱼和大鱼越多」那条用例的口径完全不变）。

**C10 · 饥饿预警只有一档，而且是内联在画布里的**（落地）
`STARVE_WARN = 20` 这条线是接着的，但整段逻辑内联在 `index.ts` 的 canvas 绘制里
（`STARVE_SECONDS - sinceEat` 现算、文案现拼），**没有纯函数、没有一条用例**，
而且从剩 20 秒到剩 1 秒都是同一句话、同一个闪烁频率 —— 最后几秒不催人。
→ 提成 `starveLeft()` / `starveWarnLevel()` / `starveWarnLine()` 三个纯函数，
分「提醒」和「快没了」两档，最后 8 秒字更大、闪更快。

### `xiangqi`（只升级既有目录）

**C11 · 长将 / 重复局面只在判负那一刻才说话**（落地）
`judgeRecord()` 要等同一局面出现第 `REPEAT_LIMIT`（3）次才出声，出声就是终局。
孩子在第 2 次重复时完全不知道自己正在往长将判负上撞。
→ 补 `repeatWarning()`：局面第 2 次出现时先给一句预警，
并且分清「你在连将，再来一次判你负」和「双方来回走，再来一次判和」。

**C12 · 电脑求和门槛写死 40 手**（列出，不落地）
`aiAgreesDraw(materialDiff, plies)` 要求 `plies >= 40`，残局连胜那种十几手就能定型的局面里
永远点不了头。→ 建议按「是不是残局」放宽，属于口径调整，本轮不动。

## 3. 落地细节

### C9 · `ocean-munch` 深层小鱼尺寸归一化（`endless.ts`）

```diff
-    const t = (roll - spec.toxinRate - spec.eliteRate) / Math.max(1e-6, smallShare);
+    const lo = spec.toxinRate + spec.eliteRate;
+    const t = (roll - lo) / Math.max(1e-6, smallShare - lo);
```

**只改尺寸归一化，四段（毒藻 / 精英 / 小鱼 / 大鱼）的出现概率一个都没动** ——
新加的用例把这四段占比按档位表逐层核了一遍，就是为了把这一点钉死。

改后各层都长得回中号的条纹鱼：

```
tier1..9 每层抽 4000 条:minnow 与 stripey 都出得来,
最大的那条小鱼稳定摸到这一段的上界(0.74 × 体型),各层口径一致
```

### C10 · `ocean-munch` 饥饿预警（`endless.ts` + `index.ts`）

新增 `starveLeft()` / `starveWarnLevel()` / `starveWarnLine()`：
`none`（>20 秒）/ `soft`（≤20 秒）/ `hard`（≤8 秒）。
HUD 里 `hard` 档字号 15→17、闪烁 4Hz→7Hz，文案换成更急的一句。
`index.ts` 那段内联的现算现拼整段换成调这两个纯函数。

### C1 · `gomoku` 连胜破纪录反馈（`session.ts` + `index.ts`）

- `streakRecordLine(s)`：整轮都看得见「最高纪录 N 盘，还差 K 盘追平」，
  只差一盘时换成「再赢 1 盘就追平」，已经站在纪录上时换成「再赢一盘就再往上刷一格」；
  第一次玩（`best = 0`）一个字都不多说。
- `streakOpening(s)`：开局播报 = 原 `streakLine` + 纪录播报。
- `brokeRecord(prevBest, s)` / `streakWinTitle()`：**超过**旧纪录那一盘标题换成
  「🏆 新纪录 N 盘！」，追平不算、第一次玩不算。
  `index.ts` 在 `streakStep` 之前先存一份 `prevBest`（`streakStep` 会把 `best` 抬上去，事后就比不出来了）。

### C2 · `gomoku` 提示文案分级（`session.ts` + `index.ts`）

- `hintButtonHint(state, kind)`：挂在提示按钮的 `title` 与 `aria-label` 上。
  解局是「提示还有 1 次；用了这一题最多拿 2 星哦」——**代价在点下去之前就说清楚**；
  自由对战剩最后一次会单独提醒；用完了也有一句话，不只剩一个灰按钮。
- `hintSpentLine(area, spent, kind)`：真的用掉之后，在区域文案后面接「还剩 N 次 / 这是最后一次 / 最多 2 星」。
  新用例专门查了一条：补出来的这几句**仍旧一个坐标都不报**。

### C11 · `xiangqi` 长将预警（`rules.ts` + `index.ts`）

`judgeRecord()` 要等同一局面第 3 次才出声，而出声就是终局。
新增 `repeatWarning(startKey, entries)`：第 2 次重复时先提醒，并分清两种后果 ——
连将方是**判负**，双方来回走只是**判和**。
`perpetualCheckLoser()` 抽出 `perpetualCheckCount()`，**预警与判负数的是同一把尺**
（用例里专门验了「预警之后再走一轮一定判得出来」），`judgeRecord` 的判定口径一个字节没动。

### C7+C8 · `rainbow-run` 幽灵名牌（`ghost.ts` + `index.ts`）

`ghostGap()` / `ghostGapLine()` 三态：领先 / 并排 / 落后。
以前 `lead >= 0` 一律走「领先」，差 0 米时印的是「👻 领先 0 米」；
现在差不到一米就是「👻 并排跑着呢」，坏数字也不会印出 `NaN`。
**`view3d.ts` / `controls.ts` 一个字节没动，没有引入 three.js，`makeCamera` 的两个调用点也没碰。**

### C6 · `match-stars` 洗牌失败文案（`board.ts` + `index.ts`）

`shuffleOn()` 洗不出来时返回 `false`，闯关里以前只在 `ok` 时写文案 ——
一步都消不动、盘面也没变、屏幕上一个字都没有，孩子只能一直点到步数耗光。
补 `shuffleLine(ok)` 两条文案（失败那条明确「不算你的错」）。
**消除 → 下落 → 补位的时间线一段没拆：`anim.ts` / `engine.ts` 未改。**
