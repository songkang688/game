### `gomoku`（全程避开 `ai.ts`）

**P3C-3 · 满盘和棋只有干巴巴一句，而这一句孩子会反复听到** —— **落地**

测试员本轮量到 `smart` vs `normal` 和棋率 **47.2%**（三轮 25% / 36% / 47%，见 `R2C-G3`）。
也就是说自由对战里两档旗鼓相当时，**将近一半的对局是以和棋收场的**。
而 `index.ts:801` 给出的收场话术从头到尾只有一句：

```
api.onWin(1, "棋盘下满了，握手言和！");
```

不分棋盘大小、不分档位、不分人机还是双人 —— 孩子听完只知道「和了」，
**不知道为什么会和，更不知道下一次该改什么**。这正是 `R2C-G3` 从玩家一侧看到的样子：
`ai.ts` 那边的强弱关系其实没坏（72 局里 smart 只输 3 局），坏的是「和棋太多而且无从下手」。

→ 出纯函数 `boardFullLine(size, ai)`：说清 15 路为什么容易和，
并指一条**玩家真按得到**的路（设置面板里就摆着「9×9 入门」这个开关）。
**`ai.ts` 一个字节不动**，强度曲线不受影响。

**P3C-8 · `R2C-G3` 本身（和棋率高）** —— **记录，不落地**
要真把和棋率压下去只有两条路：动 `ai.ts` 的评分权重给 `smart` 加进攻倾向，

后者是产品默认值决策（还会牵动 `.gmk-seg` 的选项表与既有用例）。
**P3C-3 是这一条在「不动 AI」前提下能做的那一半。**

## 3. 落地细节

### 3.1 P3C-1 / P3C-2 · 无尽收尾把纪录念出来

两款各加一个同名同形的纯函数（各自放在自己的 `endless.ts` 里，**不共享模块、不跨目录 import**）：

```ts
export function endlessRecordSay(depth: number, best: number, newRecord: boolean): string {
  const m = Math.max(0, Math.floor(depth));
  const b = Math.max(0, Math.floor(best));
  if (newRecord) {
    return b > 0 ? `这是新纪录,比上次的 ${b} 米还深 ${m - b} 米!` : `这是你的第一条纪录:${m} 米!`;
  }
  if (b <= m) return `跟最好成绩打平,都是 ${b} 米!`;
  return `你最深潜到过 ${b} 米,再往下 ${b - m} 米就追平啦。`;
}
```

（`rainbow-run` 那份把「深 / 往下潜」换成「远 / 多跑」，其余一字不差。）

**三态各说各的，一句都不含糊：**

| 情形 | 说什么 |
| --- | --- |
| 破纪录、以前有纪录 | 「这是新纪录,比上次的 2000 米还远 928 米!」——**明说比上次好了多少** |
| 破纪录、第一趟 | 「这是你的第一条纪录:2928 米!」——**不硬扯「比上次的 0 米还远」** |
| 没破纪录 | 「你最远跑到过 2928 米,再多跑 928 米就追平啦。」——**给的是一个够得着的数字目标** |
| 追平 | 「跟最好成绩打平,都是 2928 米!」——**不说「还差 0 米」** |

接线各只动一行：

```ts
// rainbow-run/index.ts  endEndlessRun()
speak(failCopy(kind, dist).line + endlessRecordSay(meters, recordBefore.meters, brokeMeters));

// ocean-munch/index.ts  finishArena()
speak(endlessFailCopy(fail ?? "starved", scoreDepth).line
      + endlessRecordSay(scoreDepth, before, newRecord));
```

`meters` / `brokeMeters` / `before` / `newRecord` **四个量在改之前就都算好了**，
一个新状态都没引入，也没多读一次存档。

**面板一个像素没动**：两条落地都刻意**不碰** `failCopy` / `endlessFailCopy`。
那两个函数的 `lines` 是面板排版用的两行，既有用例断言 `lines.join("") === line` ——
这条约束在新用例里**又断言了一遍**，确认没有被这次改动带歪。

**实测（用第 3 轮的走查脚本抓 `speechSynthesis` 桩，seed 2718）：**


### 3.2 P3C-3 · gomoku 满盘和棋

```ts
export function boardFullLine(size: number, ai: Difficulty | null): string {
  const head = `${size} 路棋盘下满了，握手言和！`;
  if (!ai) return `${head}两边都守得很紧，谁都没让对方连成五颗。`;
  return head + (size >= 15
    ? "两边都会挡活四，15 路又特别宽，很容易下成和棋。想分个胜负，可以换 9×9 入门盘，格子少一点，五颗更快连得上。"
    : "两边都守住了对方的活三。下一盘先做双威胁：一手棋同时开两个活三，对手只挡得住一边。");
}
```

三条分支各有各的道理：

- **15 路人机**：把和棋的成因说给孩子听（「两边都会挡活四，15 路又特别宽」），
  再指**设置面板里真有的那个开关**——「9×9 入门」。这是玩家自己按一下就能改变结果的唯一一条路；
- **9 路人机**：小盘本来就不容易和，再劝换盘就没意义了，改教**双威胁**——
  这正是 9 路上打破僵局的正解，也和解局战役后半段教的东西对得上；
- **双人同屏**：没有档位可言，只讲「两边都守得很紧」，**不提换盘也不提档位**。

`ai.ts` **一个字节没动**，`tiers.test.ts` / `ai.test.ts` **一条没改、没放宽**。

**新增用例**：`gomoku/smoke.test.ts` +4，覆盖三条分支、六档 × 两种盘面全说得出话、
以及一句批评都没有（`笨 / 傻 / 菜 / 太差 / 不行 / 输了 / 血 / 死` 逐词扫）。
