## 二、落地明细

### L-1 · `dark-chess` 棋格热区 44px

`view.ts` 的 `.dc-cell` 从 `min-height:40px` 提到 `44px`，同时把 `@media (max-width:400px)` 里的 `.dc-board` 间距从 4px 收到 3px。
360px 视口下 8 列 `1fr`：`(360 - 3×7) / 8 = 42.4px` 宽 × 44px 高。宽度受"一行八格"这个玩法本身的约束，做不到 44，但比原来的 41.5px 宽回来将近 1px，高度这一维先补齐。

- 测试：`smoke.test.ts` 原来那条 360px 用例改断言 `min-height:44px` 并加 `not.toContain("min-height:40px")`；另加一条新用例算窄屏格宽。

### L-2 · `hue-hand` 键位提示写全

`keyHint()` 从 `A / D 挑牌` / `← / → 挑牌` 改成 `W A S D 挑牌` / `← → ↑ ↓ 挑牌`。
`KEYS_P1` 本来就有 `up: "w"` / `down: "s"`，`KEYS_P2` 本来就有 `ArrowUp` / `ArrowDown`，只是提示行漏写了一半。

- 测试：双人同屏下逐个断言提示行里 `W/A/S/D`、`← → ↑ ↓`、`F/G/L/K` 都在；另一条实测 `S` 与 `W` 挪的确实是同一个光标。

### L-3 · `hue-hand` 手牌横滚跟随光标

`renderHand()` 收好当帧的牌元素，末尾对光标那一张调 `scrollIntoView({ block: "nearest", inline: "nearest" })`。
`nearest` 的好处是：牌已经在视野里就一动不动，也不会把整页往上顶。

- 测试：`domStub` 的 `scrollIntoView` 加了个 `scrollCount` 记账；用例先证明 7 张 50px 的牌在 360px 上确实摆不下，再按 `A` 让光标绕到最后一张，断言只有光标那一张被滚进过视野，别的牌 `scrollCount` 全 0。

### L-4 · `hop-pads` 收力键

`createStage` 新增 `cancelKeys`（默认 `["g"]`，双人同屏里朵朵 `g`、星星 `k`）与 `cancelCharge()`：蓄力中按下就把力卸掉、回到 `ready`，屏上闪一句「收住啦，重新蓄力」，**不消耗这一跳、不断连击**。
`Stage` 接口同步导出 `cancel()`，三处说明行都补了这句提示。这一条动的只是 `onKeyDown` 的分支，`onDown` / `onUp` 一行没碰——B-6 的触屏串台仍旧原样留给修复员。

- 测试：三条。按住到快满力再按 `G` 回 `ready` 且座数不涨、收完还能重新蓄出一个完美；`cancel()` 在站定 / 飞行途中都返回 `false`；双人两块舞台各收各的（`K` 只收得掉星星的，`G` 只收得掉朵朵的）。

### L-5 · `hop-pads` 返回钮 44px

`.hp-back` 从 `min-height:40px` 提到 `44px`。同页 `.hp-open` 早就是 44px。

- 测试：新用例断言 `.hp-back` / `.hp-open` 都命中 44px，且整份 CSS 里不再有 `min-height:40px`。

### L-6 · `tap-tiles` 双人分轨键位别名

新增 `ALIAS_DUO = { d: 1, arrowleft: 2, arrowright: 3 }`，只在 `split` 时生效：朵朵的 `A / S` 里 `S` 可以改按 `D`（左右手就是 `A / D`），星星的 `K / L` 可以改按 `← / →`。**主键 `KEYS_DUO` 一个都没换**，单人四轨也不认这些别名。
一条轨对上两个键会带出一个新问题：按着 `S` 再按 `D` 会被当成又点了一次、抬起 `D` 会把长条按断。所以顺手加了 `laneHeldByKey()`——同一条轨上只要还有键按着，既不重复触发也不算抬手。

- 测试：两条。别名与主键落在同一条轨、单人模式不认别名；双人同屏里按谱面时间轴用别名键把开头一串打完，逐个音符断言「完美 + N 连」，长按条报「按住别松」。

### L-7 / L-8 · `fight-king` 格斗塔台阶错开 + 后段增益缓收

两件事一起改：

1. `roundsToWin` 的门槛从 `ci >= 5` 挪到 `ci >= 6`。第 6 章（第 119–141 关）现在只上 **AI 档**（灵巧 → 老练），第 7 章才上 **两回合制**，一章只上一级台阶。
2. `foeBuffOf` 的进度过一道 `buffProgress()`：`p ≤ 0.62` 照直走，之后斜率降到 0.55。最高档的对手是"更会打"，不该同时"更耐打"。
