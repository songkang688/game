### B-2 · `tap-tiles` 同谱对战：打平不再判输

**先红**：新开 `src/games/tap-tiles/versus.test.ts`，进「同谱对战 → 地狱 → 开始」，按 `matchChart(1)` 的时间轴把整张谱一路完美打完（长按条按住到尾，同一刻先按后松），再走到结算面板。
跑出来的红是**测试员那句话的原文复现**：

```
AssertionError: expected '<div class="tt-over-t">🤖 这局对手分高一点</div>
<div class="tt-over-s">你 4200 分 · 对手 4200 分。最高 28 连,再稳一点连击就追回来了。</div>'
not to contain '对手分高'
```

4200 比 4200，屏幕上却写着「对手分高一点」。

**修法**（`src/games/tap-tiles/index.ts` 的 `mountVersus`）：

- 判定从两态改成三态。**「赢」仍旧是严格大于**（`state.score > rivalScore`），`<` 才是对手赢，`===` 就是平局。
- 平局既不进 `wins[0]` 也不进 `wins[1]`，另记一个 `draws`；顶栏比分抽成 `scoreLine()`，有平局时写成 `你 0 : 0 地狱 · 平 1`，不再把平的那局悄悄算给对手。
- 结算面板补一档平局文案：标题 `🤝 打成平手!`，正文 `你 4200 分 · 对手 4200 分。最高 28 连,一分不差地追平了,再来一局看谁先多出一个连击。`——三个数字和结论现在是一回事。
- 平局也给一颗星：地狱档的假人一下不差，孩子打到满分只能追平，这不是「输」。

**回归**（4 条，`versus.test.ts`）：

| 用例 | 守住什么 |
| --- | --- |
| 地狱档假人在第 1 局这张谱上确实是满分 | 平局这件事真会发生，不是假设出来的场景 |
| 打平不算输 | 面板写「平」、不写「对手分高」，两个分数一样多；`再来一局` 之后顶栏仍是 `你 0 : 0` |
| 赢仍旧是严格大于 | 菜鸟档打满分 → `🏆 你赢下这一局!`、拿到星、顶栏 `你 1 : 0` |
| 一下不点就是真输 | 对手分高才写「对手分高」、顶栏 `你 0 : 1` |

### B-6 · `hop-pads` 双人同屏：按手指号分台

**先红**：新开 `src/games/hop-pads/duo.test.ts`，照双人同屏那两个座位造两块 stage，两边各按各的（`pointerId: 11` / `12`），只抬一根手指：

```
AssertionError: expected [ 'flying', 'flying' ] to deeply equal [ 'charging', 'flying' ]
```

真走「👫 双人同屏」入口读两块 `.hp-canvas` 的 `data-phase`，红的一模一样。

**修法**（`src/games/hop-pads/index.ts` 的 `createStage` 输入段）：

- `onDown` 时把这次按下的手指号记进**本台自己的**账本：pointer 事件取 `pointerId`（记作 `p<id>`），touch 事件取 `changedTouches[].identifier`（记作 `t<id>`）。真机上同一次按下两种事件常常都会来一遍，所以收到几个记几个，回来任意一个对得上就算这一台的手抬了。
- `onUp`（`pointerup` / `pointercancel` / `touchend` 共用）先对账：这一台压根没人按屏幕就直接不管（键盘那一路走 `onKeyUp`）；认得出手指号、又不在本台账本里，就是隔壁那个人在抬手，一样不管。
- 事件不带手指号（鼠标、老浏览器、现有单测里那种裸 `dispatch("pointerdown")`）按「同一根」处理，向后兼容，`index.test.ts` 原有用例一条没改。
- window 监听仍旧是那六个，`destroy()` 的摘除清单一行没动——**监听归零这条老账不受影响**。
- 键盘一侧本来就是好的（`onKeyUp` 有 `keys.includes(k)` 把关），一个字没碰；学习优化员加的收力键 `G` / `K` 也原样保留。

**回归**（9 条，`duo.test.ts`）：

| 用例 | 守住什么 |
| --- | --- |
| 两个人各按各的，只抬一根手指 | 星星抬手 → `['charging','flying']`；朵朵再抬手才 `['flying','flying']` |
| `touchend` 也按手指号分台 | `identifier: 0` 抬手 → `['flying','charging']` |
| 只有一个人按着屏幕时 | 隔壁的 `touchend` / `pointerup` 都不会把他强行送出去 |
| `pointercancel` 只取消自己那一台 | `['charging','flying']` |
| 蓄力时长真的各按各的 | 朵朵按到正好的力度站住一座还是完美，星星手一抖 60ms 就够不着 |
| 鼠标 / 不带手指号的老事件 | 照旧能松手起跳（向后兼容） |
| 键盘一侧仍旧各松各的 | 星星 `K` 收力不影响朵朵；朵朵松 `F` 只有朵朵飞 |
| 真的双人同屏模式里也是各跳各的 | 走 `mount()` → 「👫 双人同屏」，读两块 `.hp-canvas` 的 `data-phase` |
| `destroy` 之后 window 上一个监听都不剩 | 按着屏幕的时候直接 `destroy()` 也收得干净 |
