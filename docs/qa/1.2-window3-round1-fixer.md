## 四、`destroy` 泄漏审计

### 4.1 先查覆盖，发现 4 个盲区

19 款逐个数「测试里有没有真的断言过 `destroy`」，结果 15 款有、**4 款一条都没有**：

`duo-rush`、`duo-vs-star`、`bumper-cars`、`bowling-lane`。

这四款的 `destroy` 此前只有「打开文件读一遍」这一种保证。
考虑到红线写的是「`destroy` 必须拆掉监听 / timer / rAF / AudioContext」，
只靠阅读不算数——尤其 `duo-rush` 还额外用了 `ResizeObserver` 和两条 `window.setTimeout`，
是本窗最容易漏东西的形状。

### 4.2 补齐：四份 DOM 桩 + 四份 `destroy.test.ts`（17 条）

仓库的 vitest 跑在 node 环境、没有 jsdom 也不许为此引依赖，
所以照本仓库已有的做法（`gold-hook/domStub.ts`、`puff-bros/domStub.ts` 等 10 份先例）
给这四款各配一份桩，再各写一份 `destroy.test.ts`：

| 款 | 新增用例 | 真的验了什么 |
| --- | --- | --- |
| `duo-rush` | 5 | 模板解析、`ResizeObserver` 活跃数、rAF、`window.setTimeout`、节点数；开跑 → 换玩法 → 再开跑三轮不叠加 |
| `duo-vs-star` | 4 | 四个 `window` 监听、rAF、`timers` 集合；进出对局三轮不叠加 |
| `bumper-cars` | 4 | 五个 `window` 监听（keydown/keyup/blur/pointerup/resize）、rAF；双人 / 人机 / 无尽来回六次不叠加 |
| `bowling-lane` | 4 | keydown / resize / canvas pointerdown、rAF；三段式投一球后再 destroy |

`duo-rush` 的桩比别人多两样东西，都是被这一款逼出来的：

1. **`innerHTML` 会真的解析**。这一款整块界面是一条 HTML 模板铺出来的，
   之后全靠 `wrap.querySelector(".dr-start")` 取节点；桩要是只把标签剥掉留文字，
   `mount()` 第一行就取不到东西。桩里带了一个够用的迷你解析器（标签、属性、
   `class` / `type` / `data-*`、自闭合标签、文本节点）。
2. **`ResizeObserver` 是真桩**，会数还活着的观察者。这样
   `ro?.disconnect()` 有没有真的被调到，是断言出来的而不是读出来的。

四款用的断言口径一致，都是「挂载前的数 → 玩到中途（必须比挂载前多）→ `destroy()` → 回到挂载前」，
再加一条「退出后再按键、再放一帧、再跑一遍 timer，都不该有人接、不该冒出新的 rAF」。

### 4.3 审计结果

**四款的 `destroy` 都是干净的，一处泄漏都没有。补的是证据，不是修复。**

顺带对全窗做了一次 `ResizeObserver` 静态核对：本窗用到它的 5 款
（`duo-rush` `sling-birds` `monster-crisis` `ice-fire-forest` `puff-bros`）
在各自 `destroy` 里都调了 `disconnect()`，无遗漏。

## 五、本轮真正修掉的问题

### 5.1 【严重】玩家可见文案里还在说「血」——3 款，已修

**这是本轮唯一的严重级发现，此前没有人报过。**

本窗红线写着「无血、无死亡描写」。同窗已经有 4 款把这个字直接列进了 BANNED 常量
（`gold-hook/copy.ts`、`monster-crisis/copy.ts`、`sky-squad/copy.test.ts`、
`prince-princess/runtime12.test.ts`），`garden-guard/fx12.ts` 的注释更是写得清清楚楚
「头顶那条也不是血条，是元气条」。可是同一个窗口里，还有 3 款的**玩家能直接读到的字**在说血：

| 款 | 位置 | 原文 |
| --- | --- | --- |
| `garden-guard` | 第 121 / 165 / 188 关 BOSS 提示 | 「给随从奶血」「半血还会暴走」 |
| `garden-guard` | 克制表标签与波次预告 | 「会回血」「这一波有会回血的」 |
| `sprout-defense` | 攻略 3 条 | 「速度型血量通常不高」「首领血厚且带甲」「掉到一半血会狂暴」 |
| `sprout-defense` | 带盾特性的克制说明 | 「先把盾打碎才掉血」 |
| `sprout-defense` | 第 188 关提示、进化体波次提示 | 「血少一半会狂暴」「进化体半血会狂暴」 |
| `duo-rush` | 攻略第三章 | 「对手的血量就在他那一格的左上角」 |

不一致的是文案，不是红线。全部改成**元气**口径。
`duo-rush` 那句顺带改对了事实——那一格显示的根本不是血量，是**还剩几次机会**
（这一档比的是谁先撞满三次），原文既违红线又说错了。

另外把 `sky-squad/index.ts` 与 `prince-princess/index.ts` 里两处
`// 血条` 的代码注释也改成元气条，和 `garden-guard` 的口径对齐。

**没有动的部分，以及为什么：**

`garden-guard` 与 `sprout-defense` 的 `logic.test.ts` 各有一条
「前 99 关一字不动：关卡数据回归指纹保持不变」，用 `fnv1a(JSON.stringify(LEVELS.slice(0, 99)))`
把 1.1 的关卡数据整个冻住。我第一版把全部关卡提示都改了，这两条立刻变红：

```
garden-guard  expected '81fd8cf9' to be '7c76e1eb'
sprout-defense expected 'b4140574' to be '30106773'
```

落在冻结区里的是 `garden-guard` 第 **15 / 55 / 66 / 88** 关和 `sprout-defense` 第 **13** 关。
改它们就必须改既有断言的期望值，那是「调弱既有断言」，本轮规矩不允许。
**已全部回退，列为遗留项交主管定夺**（第六节 L1）。
