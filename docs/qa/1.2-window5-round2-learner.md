#### W5R2-L-01 · `clock-house` 12↔24 时制改用课本的七段时段词 —— ✅ 本轮落地（测试员 W5R2-A-03，**严重·点名必须落地**）

**来源思路**：测试员把 188 关的 `h12`（60 道）与 `h24`（62 道）按小学《24 时计时法》口径逐题核，**78 道对不上、落在 46 关**，其中 9 道是硬错（「上午 12:30」「下午 12:10」——中文里这两句根本不存在）。

**现状**：`levels.ts` 只有 `PERIODS = ["上午", "下午"]`，`to12Hour()` 走「0–11 → 上午 / 12–23 → 下午」的纯 AM/PM 二分。这套二分是英文 am/pm 的直译，跟中文口语和课本都对不上：0 点被说成「上午 12 点」，12 点被说成「下午 12 点」，孩子照着念在课堂上会被判错。

**落地方式**：
- `logic.ts` 把 `DayPeriod` 从二分改成课本的**七段**：夜里(0) / 凌晨(1–5) / 早上(6–8) / 上午(9–11) / 中午(12) / 下午(13–17) / 晚上(18–23)，抽出 `DAY_PERIODS`、`PERIOD_BANDS`、`dayPeriodOf()`、`hoursOfPeriod()`，`to12Hour()` / `to24Hour()` 一起改口径。
- `levels.ts` 的 `qH12` / `qH24` 跟着改：**干扰项一律由 `to12Hour()` 生成**，保证每一个都是真说得出口的说法，只是配错了时刻——不再出现「上午 12:40」这种语言上就不成立的选项。
- `hints.ts` / `guide.ts` 的方法提示与攻略同步改口径，并把「上午 12 点」「下午 12 点」这两个常见误区明写出来。
- 改动**全在第 100 关之后**，前 99 关摘要锁一个字没碰。

**量化**（独立复算题面 + 正确答案，不含干扰项）：

| | 改前 | 改后 |
| --- | --- | --- |
| 不合课本口径的说法 | **140 处 / 77 关** | **0** |
| 其中硬错（「上午 12:xx」「下午 12:xx」） | **58 处 / 45 关** | **0** |
| 与测试员手点的 9 道硬错逐个对上 | ✅ | — |

测试员手点到的 9 处硬错全在 `h12`+`h24` 里；本轮另外 49 处硬错在测试员没量过的**跨中午题（`spanNoon`）** 里，一并收掉。

**受益 id**：`clock-house`（第 100–188 关的 `h12` / `h24` / `spanNoon` 三种题型）。

**风险与回滚**：口径变了，`logic.test.ts` / `levels.test.ts` 里原来按二分写的断言同步改成七段（**只改断言不删用例**）。新增 `dayPeriod.test.ts` 9 条守门，含「任何一道题的题面与选项里都不许出现『上午 12 点』『下午 12 点』」这条全量扫描。单条 `git revert` 可回滚。

#### W5R2-L-05 · `landlord-cards` 无尽连胜输了重开不再永远发同一副牌 —— ✅ 本轮落地（测试员 W5R2-A-04）

#### W5R2-L-06 · `landlord-cards` 连输两次之后帮着挑一副能赢的牌 —— ✅ 本轮落地（测试员 W5R2-A-08，建议）

**来源思路**：测试员让「完全照着 💡 教练提示打」的玩家把 188 关各打一局，输了换一副再打——187 关都在 2 次以内翻到能赢的牌，**只有第 188 关要连输 5 次**，第 6 次才过第一次。

**现状**（本轮用同一套牌桌 `sim.runTable` 的 `coach` 座位 + 同档小牌灵复算，比测试员多扫出几关）：

```
最坏连输次数 6 次;要连输 ≥3 次的关共 7 关:
  第 81 关=5 次  第 188 关=6 次
  第 150 / 153 / 167 / 170 / 177 关各 3 次
```

**落地方式**：`levels.ts` 抽出 `levelDealSeed(lv, n)`（原来散在 `index.ts` 里的 `lv.seed + bump*104729`），新增 `coachCanWin(lv, n)` 与 `mercyRedeal(lv, n)`。头两次原样换牌——**摔两跤是塔的一部分**；从第三次起往后最多试 10 副，端第一副「照着教练提示打能赢」的上来，试不到就用原来那一副，绝不让孩子干等。

**为什么不是抬 `boost`**：`boost` 抬上去只是换一手更强的牌，而「牌强」和「这一局赢不赢」不是一回事。实测四种抬法都试过——

| 兜底口径 | 最坏连输 | 要连输 ≥3 次的关 |
| --- | --- | --- |
| 现状（不兜底） | 6 | 第 81 / 150 / 153 / 167 / 170 / 177 / 188 关 |
| 连输 2 次 → boost 1 | 6 | 变成第 81 / 131 / 138 / 150 / 153 / 158 / 165 / 177 / 178 关 |
| 连输 2 次 → boost 2 | 6 | 变成第 81 / 138 / 148 / 150 / 165 / 166 / 178 / 188 关 |
| 连输 3 次 → boost 2 | 5 | 变成第 81 / 150 / 153 / 167 / 170 / 177 / 188 关 |
| **按「能不能赢」挑** | **2** | **0 关** |

抬 `boost` 尾巴只是换了个地方长；直接按「能不能赢」挑才是对着问题本身下手。

**量化**（188 关全塔复算）：

| | 改前 | 改后 |
| --- | --- | --- |
| 最坏连输次数 | **6** | **2** |
| 要连输 ≥3 次的关 | **7 关** | **0 关** |
| 一把过的关数 | 134/188 | **134/188（没动）** |
| 兜底一次的开销 | — | 最多 10 次牌桌模拟，实测 <3ms，只发生在按下重开的那一刻 |

「一把过 134/188 一个数没变」是这条最要紧的一行：**没有任何一关因为这条兜底变得更容易一把过**，变的只是「卡住之后要卡多久」。

**受益 id**：`landlord-cards` 188 关战役（其中第 81 / 150 / 153 / 167 / 170 / 177 / 188 关直接受益）。

**⚠️ 需要签字的一点**：这条兜底是**全塔生效**的，包括第 81 关（≤99）。选择这么做的理由是——关卡表 `LEVELS` 一个数没改（`boost` / `seed` / `aiLevel` 全原样）、前 99 关摘要锁一个字没动、任何一关的**首次难度完全不变**（一把过 134/188 不动），改的只是「已经输了两次之后」的运行期行为，方向上属于「失败只鼓励」。若审阅认为前 99 关连这个也不该碰，`mercyRedeal()` 里加一句 `if (lv.index < 99) return n;` 即可收窄，是一行的事。

**风险与回滚**：新增 `mercy.test.ts` 16 条，含「188 关一关不落：谁都不用连输超过 2 次」的全量断言。单条 `git revert` 可回滚。
