## 四、双人键位：这一轮换的是**量法**

第 1 轮拿整屏指纹量，在 `mine-garden` 上误报过一次（两块盘同种子、长得一模一样，整屏指纹分辨不出第二个人）。这一轮改成三种按款式挑的量法，并且**每一轮都先采一遍「一根手指都不动」的空跑基线再做差集**，把自己会动的东西（动画、倒计时、对家 AI）先扣掉。

三种量法：

1. **分座（`split`）** —— 先找游戏自己的分边容器（`.bd-seats` / `.mg-seats` / `.mg-duo` / `.sp-seats` / `.oa-panes` / `.sr-panes`），它的每个直接子节点算一「座」，一座一份 DOM 摘要 + 一份画布分块像素摘要。判定标准是**存在只认朵朵的座、也存在只认星星的座**。
2. **按颜色分人（`realtime`）** —— 混战类两个人在同一个场地里，没有「左右两边」，改数朵朵的粉 `#F5A9C8` 和星星的蓝 `#A9C8F5` 各自的像素重心，做「按住左 → 按住右 → 按住左」三段来回，要求横坐标一去一回符号相反。
3. **看回合（`turn`）** —— 同一块盘轮流出手的四款，谁的回合只有谁能动，做差集没有意义。改成：读「轮到谁」，按**他自己**那套键看吃不吃得进去；回合还在他手上时，再拿**对家**那套键探一下会不会串台。

### `orb-arena` / `snake-royale` 的取证上限（不判缺陷）

这两款双人同屏是**两块 pane、每块一台跟着自己那个人跑的摄像机**（`.oa-panes×2` / `.sr-panes sr-split×2`）。两件事叠在一起，浏览器侧的行为取证就做不下去了：

- 场地每一帧都在动，**空跑基线里所有区域都会变**（`座0.canvas0.*`、`座1.canvas0.*`、`外.dom`、`座*.dom` 全都在名单上），差集扣完什么都不剩；
- 摄像机锁在自己人身上，所以**自己那团颜色永远待在 pane 正中**（量到的 Δx 只有 ±1 到 ±11px），而对家那团颜色的位移是「对方在动」和「摄像机在动」两件事叠出来的，符号会翻。

本轮能拿到的证据是**结构侧 + 代码侧**的：

- 结构侧：双人同屏确实是两块 pane，pane0 里朵朵的粉色像素 4055 个、星星 0 个；pane1 里星星的蓝色像素 3585 个 —— 一人一块，摄像机各锁各的；
- 代码侧：两款都把两套键位绑到了**不同的 owner** 上，不是同一份表：


`applyKey(duo.id, DUO_KEYS[k], …)` 与 `applyKey(target.id, STAR_KEYS[e.key], …)` 走的是两个不同的 id，`snake-royale` 同构。

**所以这两款不进问题清单**：没有任何证据说它坏，但也请后续别把「双人键位已在真浏览器里逐款量过」这句话套到它们头上 —— 它们只有结构与代码两侧的证据。要补行为侧的硬证据，得让这两款在测试模式下把两个人的坐标暴露出来，那属于改玩法，本轮不做。

## 五、第 2 轮猎到的遗留：逐条结论

### W1-10 · **结论：脚本挑点的问题，不是 AI 缺陷**（可以关掉）

把页面里的 `Math.random` 钉成固定 seed，跑 `smoke-1.2-step4-b` 那三个写死的落点 `(2,2) (6,6) (2,6)`，并且把**「我这一手落没落下去」和「AI 回没回」拆成两个独立判定**：

| seed | 手数 | (2,2) | (6,6) | (2,6) |
| --- | --- | --- | --- | --- |
| 1 | 0 → 6 | 我✓ / AI✓ | 我✓ / AI✓ | 我✓ / AI✓ |
| 7 | 0 → **4** | 我✓ / AI✓ | 我✓ / AI✓ | **我✗ / AI✗** |
| 20240601 | 0 → 6 | 我✓ / AI✓ | 我✓ / AI✓ | 我✓ / AI✓ |
| 424242 | 0 → 6 | 我✓ / AI✓ | 我✓ / AI✓ | 我✓ / AI✓ |
| 987654321 | 0 → **4** | 我✓ / AI✓ | 我✓ / AI✓ | **我✗ / AI✗** |

- **AI 缺回合的 seed 数：0/5** —— 只要我这一手落得下去，AI 每一次都在 4 秒内回了。
- 复现失败的 2/5 个 seed，挂的都是**我自己那一手就没落下去**：第三个写死的点 `(2,6)` 被前两手的应手占掉了，落子被判非法。

**修法建议给修复员**：`scripts/smoke-1.2-step4-b.mjs` 别用写死的三个点，改成每一手先读一下棋盘、挑个空交叉点再落；断言也拆成「我这一手落下去了」+「AI 回了一手」两条，失败时才看得出是谁的锅。

### W1-11 · **结论：固定 seed 下复现不出来，原失败是偶发**（可以关掉）

两步取证。先用纯函数看骰子流公不公平：`dice.ts` 的 `rollSeq(seed, 80)` 按四人轮流切开，八个 seed 下**每个座位都掷得出 6**（每座 1–8 次不等，合计 8–15 次），骰子流本身不偏心。

再把 `Math.random` 钉死（`flight-chess/index.ts:975` 的模式 seed 就是从它来的），在 **375×667** 真跑四人对战 90 秒：

| seed | 已掷 | 在路上 |
| --- | --- | --- |
| 1 | 0 → 79 | **9/16** |
| 20240611 | 0 → 72 | **9/16** |
| 987654321 | 0 → 79 | **10/16** |

`step4-c` 的阈值是「≥4 架在路上」，**三次全部远远越过**（9–10 架）。第 1 轮那次 `3/16` 复现不出来，判定为偶发（那一次多半是掷骰节奏被卡了一下），**不是缺陷**。

### W1-R2-02 · 一般 · `weiqi-garden` 双人同屏两套键位不分人

**现象**：双人同屏里，**轮到朵朵时按星星那套方向键 + `L` / `K`，棋盘照样动**（本轮量到 `几何.canvas0` 连同它的左半、右半、上半三块分块摘要一起变了）；反过来也一样。两个人共用同一个光标，谁都能替对方把子落下去。

**根因**（源码里写得很直白）：`keyAction()` **不带玩家参数**，`WASD` 和方向键返回同一个动作，`F` 和 `L` 都是 `confirm`，`G` 和 `K` 都是 `pass`：

```110:138:src/games/weiqi-garden/index.ts
export function keyAction(key: string): KeyAction {
  switch (key) {
    case "ArrowUp":
    case "w":
    case "W":
      return "up";
    // …
    case "f":
    case "F":
    case "l":
    case "L":
    case "Enter":
      return "confirm";
    case "g":
    case "G":
    case "k":
    case "K":
      return "pass";
```

双人模式的 `onKey` 直接用它，中间没有任何「这个键是谁的」判断：

```1047:1057:src/games/weiqi-garden/index.ts
  function onKey(e: KeyboardEvent): void {
    const act = keyAction(e.key);
    if (!act) return;
    e.preventDefault();
    if (act === "pause") {
      togglePause();
      return;
    }
    if (paused) return;
    if (act === "confirm") {
      tap(view.cursor);
      return;
    }
```

**对照组**：同为共用一块盘的 `mahjong-bloom` / `star-estate` / `flight-chess` 三款，本轮的串台探针都是**「毫无反应」**；`mine-garden` 的 `keyAction(key, "p1" | "p2")` 更是直接带了玩家参数。所以这不是「共用盘就只能这样」，是这一款漏了。

**影响**：不崩不卡，单人闯关完全没事（闯关本来就只有一个人）。但双人同屏下，手快的那个可以替对方落子 —— 对两个小朋友抢一台设备的场景来说，这就是会吵架的那种问题。

**建议**：给 `keyAction` 加一个玩家参数（照 `mine-garden` 的 `keyAction(key, who)` 写），双人模式下按当前该谁走来收键；单人闯关维持「两套键都认」的现状，别把闯关的手感改掉。
