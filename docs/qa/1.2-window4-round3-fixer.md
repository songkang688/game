### 三、C3-01 为什么维持现状

这是本轮唯一一个「查出来了却不改」的决定，所以把过程写全：

1. **先真改了一遍**：给 1.0 六章的 `return` 补上 `dedupe()`，25 关的 88 个重复格全部消失。
2. **改完当场打红了一把锁**：`levels188.test.ts` 里有

   ```ts
   it("前 99 关每关墙体与速度一笔未改（生成指纹回归）", () => {
     expect(fnv(JSON.stringify(LEVELS.slice(0, 99)))).toBe("dac35a05");
   });
   ```

   指纹从 `dac35a05` 变成 `a315c280`。这把锁的意思是「1.0 的前 99 关一笔未改」——
   去重虽然不改**墙的集合**，但确实改了 `walls` 这个数组，锁按定义就该红。
3. **于是原样回退**。理由和第 2 轮驳回 L2-08（`bubble-aim` 给新手主题加子弹）是同一条：
   拿「老关卡一字不动」这条对老玩家的保证，去换一个玩家根本看不见的数据洁癖，不划算。
   碰撞判定走 `wallSet()`（Set），画墙也是同一格画两遍、像素完全一致，
   `canvas.dataset.walls` 取的同样是 Set —— **这 88 格在屏幕上不存在**。
4. **代之以两道闸**（`qaC3.test.ts` / `qaC3fix.test.ts`）：
   - 范围钉死：重复只许出现在 1.0 的 99 关以内，**1.1 / 1.2 追加的 89 关一格都不许重**；
   - 性质钉死：它只是「多写了一遍」，去重后墙的集合一格不多一格不少。
   任何一条被破坏都会当场变红。
5. **留给 1.3**：真要清，正确做法是「拆锁 + 重新生成指纹 + 全量回归」，那是一次
   有意的数据版本升级，不该塞进发布前最后一轮。

### 二、W4A-17（轻微）· 精英被当成「单独打」来定价

**病根不是数值大，是定价的前提错了。** 精英的血量与气势是照「满状态迎战、打完就歇」
配出来的——首领关索性在门口摆一块整装石，就是承认了这个前提。可普通关没有整装石，
同一段歇脚石之间常常还塞着别的架，那些消耗全要算在这只精英头上。

第 2 轮的 `easeClimaxElite` 只认「它是不是收尾那一只」。本轮把尺子从 6 个种子加长到
40 个之后，露出了它管不到的另一种形状：**精英排在半路**，后面还接着一两场小怪。
第 121 关是「小怪 → 精英 → 小怪」，第 124 / 140 / 185 关是「精英 → 小怪 → 小怪」。

两种形状其实是同一件事：**这只精英不是单独打的**。所以修法分两步：

1. **`easeWornElite`（改判据）**：从「它是不是收尾」换成「同一段歇脚石之间还有没有别的架」，
   **前后都算**。夹着一场的松 `CLIMAX_EASE = 0.9`，夹着两场以上的（真正的车轮路）
   松到新加的 `DEEP_EASE = 0.85`。单独打的精英一点不松——那种情况本来就是照满状态配的。
2. **`offerBreather`（给一个选择）**：整关一处歇脚都没有、却要连打三场以上的关，
   在**岔路**上把一条支线换成歇脚石。这里刻意**不再往下削数值**——削到最后精英就不是精英了。
   歇脚石摆在岔路的最后一条，前面那条仍旧是架，所以「一路硬闯」这条最难的走法原样还在，
   走查量的仍是下限。「什么时候该坐下歇一口」本来就是这一关最该学会的事。

**效果（188 关 × 100 种子 × 三组不同种子族，机器人是达标勇者）**：

| 种子族 | 硬闯（永远走最左、一次不歇） | 会歇（岔路上有歇脚石就先坐下） |
| --- | --- | --- |
| A | 掉队 **15 关 → 6 关** | 掉队 **14 关 → 3 关** |
| B | 掉队 **8 关 → 2 关** | 掉队 **6 关 → 1 关** |
| C | 掉队 **7 关 → 3 关** | 掉队 **6 关 → 1 关** |

三组里次次垫底的第 140 关（「精英 → 小怪 → 小怪」，小怪气势 90 竟高过精英 85）
从 92%/95%/94% 抬到 95%/97%/97%，而且现在它半路能坐一下。
剩下的零星几关全是 99%（一百局里输一局），且不再是清一色「精英夹在车轮路里」——
**那一类已经收干净了**。

**没碰的东西**：一关最多一块歇脚石这条老规矩仍旧成立（有断言逐关盯）；首领关不进这两条路
（`if (!boss)`），门口那块整装石照旧；`CLIMAX_EASE` 的值一点没动。
唯一被牵动的既有断言是 `walkthrough.r2.test.ts` 里第 154 关那条——它原本要求
收尾精英的星芒上限 >1.3 倍小怪，第 154 关正是「车轮路」形状，松到 `DEEP_EASE` 之后
是 1.25 倍。门槛调成 1.2 倍，注释里写清了为什么调、调之前是多少。**这是本轮唯一一处
改既有断言的口径，没有删任何用例。**

### 三、W4A-18（中等）· 死胡同判负 = 没犯错却输了

第六章那几关（6x8 / 7x8、往左收拢、只给 2 次洗牌），一路挑「眼前能连的」往下消，
有时会把盘面消成一个谁也连不上的死局；这时两次洗牌已经用光，`index.ts` 直接判这一关没过，
还捎一句「洗牌是应急用的，下一局多留一次就够翻盘啦」。

**这句话是错怪。** 孩子并没有乱花洗牌——是这一手消除顺序刚好把自己堵死了。
188 关 × 60 种子的全量扫描里，第 **36 / 51 / 64 / 86 / 89 / 95 / 98** 关都撞得上，
七关全是 1.0 老关，共同点是「洗牌次数 ≤3 + 会收拢 + 没有免费自动洗牌」。
最扎眼的是**第 89 关：它发出去的那个固定种子就是会死**——每个走到第 89 关的孩子，
都会被同一个盘面按同一种方式堵一次。

**修法**：中途的死局跟开局的死盘本来就是同一回事，没有理由区别对待。
开局撞上死盘时游戏本来就免费救一次，现在两处统一走新加的 `rescue()`——
免费重排一次，接着连，配一句「这盘走进死胡同啦，不算你的——帮你重排一次，接着连！」。
重排走 `fairShuffle`，它保证**排完一定还走得动**，所以救完接着玩就行。

于是：棋盘死胡同还是会出现（那是这一手消除顺序的自然结果，躲不掉），
但它**不再让孩子输掉这一关**。现在整款只剩「时间到」一个输法——
正是 1.1 新章一开始的设计本意。**前 99 关的关表一个字节没动**（哈希锁照跑）：
改的是「撞上之后怎么办」，不是「会不会撞上」。那两句错怪的判负词一并拆干净。

### 二、本轮修的：B3-01

切水果整块是 canvas，果块抛飞、刀光拖尾、切开的迸溅全在帧循环里用 JS 画，
**没有 CSS 动画可以挂 `@media`**——前两轮只翻 `index.ts` 内联样式的走查就是这么漏过去的。
所以修法不是补一条 `@media`，而是自己读一次媒体查询，把**纯装饰**的那几样压下去：

| 压的是什么 | 平时 | 开了「减弱动态效果」 |
| --- | --- | --- |
| 刀光拖尾 | 留 16 个点 / 0.18 秒 | 留 5 个点 / 0.06 秒 |
| 迸溅、光圈 | 正常消退 | 消退快 5 倍（`FX_FADE`） |
| 飘分 | 一边淡出一边往上飘 | 停在原地只淡出（分数照样读得到） |
| 彩虹刀 | 逐帧刷色相 | 色相冻住，只留沿刀身的固定渐变（逐帧刷色相本身就是闪烁） |

**玩法一个字没动**：水果的抛物线、判定走廊、发射节奏、计时、炸弹率都不看这面开关。
这一条有专门的用例守着——逐行检查凡是出现 `reducedMotion` / `FX_FADE` 的行，
都不许同时出现 `gravity` / `launchTimer` / `bombChance` / `volley` / `hearts` 这些玩法字眼。

### 三、B2-05 为什么维持现状

沿用第 2 轮的判定，这里把理由补全：

1. `fruit-slice` 第 1~99 回合的关卡参数被一把 FNV 哈希锁钉着，锁的意思是
   「1.0 的老回合一笔未改」。第 70 / 81 / 92 三个快闪回合正好都在锁里。
2. 改这三个回合的密度会让 1.0 老玩家的**成绩线整体漂移**——他们在这三关刷出来的分数
   会突然变得不可比。
3. 收益是「三个回合紧一点」，代价是「一批老成绩失真」，不划算。
4. 代之以一条**说明性用例**（`fruit-slice/qa-b-r2-learn.test.ts`）把这个决定和它的理由
   钉在代码里，免得下一轮又当成新 bug 报一遍。
5. 真要改，正确做法是「拆锁 → 重新生成指纹 → 全量回归」，那是一次有意的数据版本升级，
   不该塞进发布前最后一轮。

### W4-FIX-A · Esc 弹两层暂停（严重，2 处）

外壳自己也在 `window` 上听 Esc，收到**没被接住**的就弹它那张「先歇一会儿」：

```ts
window.setTimeout(() => {
  if (disposed || dialog || pauseDialog || e.defaultPrevented) return;  // ← 就看这一句
  openPause();
}, 0);
```

窗口 1 在 `src/games/window1-pause.test.ts` 里把这条钉死过：自己接管 Esc 的游戏
**必须** `preventDefault()`，否则两层各记各的状态，真机上按第 2 下、第 3 下会走成
「面板挡着屏、游戏在后面跑」。窗口 4 有两处照样漏了：

| 处 | 位置 | 原样 |
| --- | --- | --- |
| `fruit-catch` 无尽 | `index.ts` 水果雨那条 keydown | `else if (e.key === "Escape") { back(); }`，前后两个方向键分支各自 `preventDefault`，唯独这一支没有 |
| `lianliankan` 无尽 | `index.ts` 连到底那条 keydown | `if (key === "Escape") back();`，整条回调一次 `preventDefault` 都没有 |

两处都补上了 `preventDefault()`。`fruit-catch` 双人那条其实是对的
（`else return;` 之后统一 `e.preventDefault()`），没动。

### W4-FIX-B · 暂停面板停不住游戏（严重，14 款）

外壳弹面板前会调游戏的 `pause()`、关掉时调 `resume()`：

```ts
function tellGame(method: "pause" | "resume"): void {
  const fn = (mounted as unknown as Record<string, unknown> | null)?.[method];
  if (typeof fn !== "function") return;   // ← 游戏不接就什么都不做
  ...
}
```

窗口 4 的 15 款**一款都没接**。也就是说：顶栏那颗 ⏸ 按下去、或者 Esc 弹出面板，
屏幕上写着「先歇一会儿」，后面照跑——倒计时继续掉秒、砖块球继续掉、
毛毛虫继续往墙上撞、地鼠一只只缩回去。孩子看着「暂停」两个字把这一关输掉。
全仓 87 款里此前只有 4 款接了这一对，所以三轮走查都没往这儿看。

按各款原有的资源管理方式分三种接法，一款不漏：

| 接法 | 款 | 做了什么 |

`box-hamster` 是纯回合推箱子，没有倒计时、没有会自己动的东西，孩子不动它就一直等着，

`setTimeout` 和 rAF 各只有一处装饰性用法」，哪天加了计时玩法就会红。
