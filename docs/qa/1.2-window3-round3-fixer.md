## 二、B1 `sky-squad`：放跑判罚是死代码

### 根因

`index.ts` 的 `stepFoes` 里两行顺序反了：

```ts
if (f.y > SKY_H + 60) f.hp = 0;                                  // 先把飞出下边界的敌机 hp 清零
...
const escaped = foes.filter((f) => f.hp > 0 && f.y > SKY_H + 60); // 筛子要求 hp > 0 —— 恒为空
```

`escaped` / `escapedTotal` 永远是 0，`sortieCleared` 拿到的「放跑数」永远是 0。
`logic.ts` 里的 `sortieCleared` / `escapeLimit` 本身是对的，只是从来没收到过真数据。
后果：8 个 Boss 关之外的 **180 关**，玩家一个键都不按、只靠自动射击，
敌机全部从下边界飞走，结算照样判「全部请回机库」三星。

### 修法

1. 撤掉 `index.ts` 里那句提前清零，让 `escaped` 筛子真的筛得到人（`hp` 该由伤害与出界收尾统一处理）。
2. `logic.ts` 的 `escapeLimit` 收紧一档：

```ts
return Math.min(Math.max(2, Math.floor(total * 0.25)), Math.floor(total / 3));
```

原来「最少容错 2 架」在小编队关是个洞：一波只有 3 架的关，放跑 2 架还算过关。
现在容错最多不超过总数的三分之一。大编队关的 25% 容错不变。

### 回归证据

- 新增常驻用例 `src/games/sky-squad/idle.test.ts`：走 `createSortie` → `stepFoes` → `onFinish`
  的**真实路径**（不是直接调 `logic.ts` 的纯函数），断言三件事——敌机飞出下边界要记进
  `escaped`、第 1 关摆烂放跑数超过容错且拿不到三星、**全 188 关摆烂一关都过不去**。
- `scripts/qa-window3/round3.qa.test.ts` 的 B1 取证由「量这个 bug 有多大」改成「钉住它已经修好」：
  源码里那句清零必须不存在、筛子必须还在、188 关摆烂 0 过关。
- 浏览器实测（`idleplay.mjs sky-squad 1 60`）：

| 关 | 修前 | 修后 |
| --- | --- | --- |
| 第 1 关 | 11 秒过关、**3 星**、「0 架全部请回机库」 | **11 秒判负**、0 星、「放跑了 3 架，超过 1 架就得重飞一趟」 |
| 第 60 关 | 8 秒过关、**3 星** | **8 秒判负**、0 星、「放跑了 4 架」 |

## 三、B3 `duo-vs-star`：对手自己走下台

测试员点出的方向是对的——不是 AI 档位问题（滑滑冰湖 0/19），
是**场地的可站范围跟小电脑的走位逻辑对不上**。拆下去一共七条，分两个提交修完。

### 3.1 第一层（`e0dfd13`）：72 → 19 关

| # | 根因 | 修法 |
| --- | --- | --- |
| 1 | `safeZone` 只认最大那块主平台。星光升降台 / 夜空跳台的主平台只有 140–200px 宽，**出生点却在两侧的台子上** —— 小电脑一出生就以为自己已经掉出场，二段跳在半空全按光，然后直直往下掉 | `stages.ts` 新增 `standSpan()`（全部台子的并集），`battle.ts` 把 `ground`（并集）与 `stand`（脚下这块）一起喂进 `AiView` |
| 2 | 空中横向加速没有真正封顶，追人追着追着横速跑到一千多，径直飞出场 | `battle.ts` 把空中操控的横速夹在跑速内；被打飞得来的高速照旧自然衰减，不影响手感 |
| 3 | 追人 / 捡道具时就把那唯一一次空中跳跃按掉了，真要回场时没跳可用 | 这两种情况只在**地上**起跳（地上起跳会把空中跳跃补满） |
| 4 | 轻松档 0.46 秒才想一次，掉下去 0.46 秒早就低于台面了 | 新增 `perilous()`：危险中的小电脑临时提速到 `PERIL_THINK`(0.06s)。**只对「自己走下去的」提速**，刚被打飞的那一下照旧吃反应延迟（`PERIL_GRACE`），不然谁都救得回来、对局再也打不出胜负 |
| 5 | 悬空没跳可用时还在「追人 / 回场」之间来回切，最后落进台子之间的缝 | 新增 `pickLanding()`：横着挪到最近那块落得上去的台子上方 |

### 3.2 收尾（`65a690d`）：19 → 6 关

| # | 根因 | 修法 |
| --- | --- | --- |
| 6 | **台沿保险只在决策里做是拦不住的。** 轻松档 0.46 秒想一次，按着方向键这段时间能跑 130px。云朵广场第 1 关的对手就是这么一路走到 x=790（主平台到 770 为止）踏空的 | `battle.ts` 新增 `ledgeSafeInput()`：**每一帧**都过一遍，脚下这块台子到头、那边又没有「比自己低、够得着」的台子接着，就松开那个方向（顺手收掉跳） |
| 7 | 云朵广场右边那块浮空台在 y=288（**头顶**），却被 `standSpan` 算进了「站得住的范围」，小电脑以为右边还有地 | `canLandBeyond()` 只认 `top >= self.y + 8` 的台子 —— 头顶那块落不上去 |
| 8 | 轻松档三成决策是随机乱走（`mistake` 分支），那条路上原本一点边缘判断都没有 | `decideAi` 每条出口都过 `guardLedge()`，把「闭眼往台下迈」的那一步换成往台子里侧挪 |
| 9 | 回场一律奔主平台中间。跳台图上明明左手边就有一块侧台，它偏要横穿整条缝往中间赶，半路高度就掉光了 | 回场改成奔 `pickLanding()` 挑出来的落脚点，起跳门槛也按那块台子的高度算；挑的时候为「掉头」付一点代价（正往左飘还硬选右边那块，多半两块都够不着） |
| 10 | `perilous` 用「比主平台低」判危险，在跳台图上会来回翻：升过主平台高度就以为安全了，转头继续追人往缝里走 | `perilous` 补一条：**悬在两块台子中间的缝上**跟飘出场外一样危险 |

## 四、B2 `prince-princess`：搭档一个人把整关的活干完

### 4.1 第一层（`37a0f63`）：城门只认真人手上那位

**根因不在「搭档太强」，在 `checkGoal` 只数人头：**

```ts
const atDoor = w.heroes.filter((h) => Math.abs(h.x - w.def.goalX) < 64 && h.y > -170);
const need = w.def.goalNeedsAll ? w.heroes.length : 1;
if (atDoor.length >= need) { /* 判赢 */ }
```

`goalNeedsAll` 为假的关卡，**托管搭档一个人走到门口就判赢**，
真人在出生点站着不动照样算过关。188 关里 110 关中招，94 关三星。

修法四条：

1. `checkGoal`：一个人玩的时候，城门口那几位里**必须有真人手上那位**（`world.active`）。
   两个人玩一字未改，`goalNeedsAll` 语义保留，关卡数据一个数都没动。
2. 新增 `humanHero(w, i)` 与 `world.playerKills / playerGems / playerHits`：
   搭档托管期间的战果单独记账，`swapActive` 换人以后跟着真人走。
3. `starGoals`：一个人玩、而且自己一下都没打中的时候，「路上的怪一只不剩」这颗星不算你的
   （纯跑图关和两人模式不受这条约束）。
4. `winMessage` 与 HUD：搭档打的怪、捡的宝石照实说（「这一路的怪都是搭档打倒的，
   下回你也上去砍两下」「宝石收了 N 颗（搭档帮着捡了 M 颗）」）；
   单人模式开门提示改成「城门开啦！**你自己跑过去才算过关**」，进度条同步。

### 4.2 第二层（`6dbe7fd`，同轮另一位 fixer）：给托管搭档系上绳子

第一层把摆烂过关归零了，但搭档跑的还是全功能 AI —— 孩子把手放开，
188 关跑下来搭档仍然清空了 112 关的怪、凑满了 129 关的宝石，还会冲到 3185px 外的城门口干等。
第二层把 `chooseTarget` / `botInput` 限成「只接真人身边的活」：
超前真人 300px 以上的怪不打，往城门那头最多探出 220px。
扫描口径同上：清空的关 112→0、凑满宝石的关 129→0、595 杀→84、1078 宝石→5、最远探出 3185→200px。

### 4.3 回归证据

- 新增常驻用例 `src/games/prince-princess/idle.test.ts`（照 `index.ts` `frame()` 原样喂输入：
  `active` 那位喂空输入、另一位喂 `botInput`）：第 1 关摆烂不过关、
  **全 188 关单人摆烂零过关**、双人摆烂照旧零过关、战果记账分得清（含换人后）、
  文案不把搭档战果说成玩家的、**机器人替真人操作时抽样 16 关照样通关且第 1 关三星**
  （这一条是防「修过头把关卡改成过不去」的反向守门）。另有第二层的 `escort.test.ts`。
- `scripts/qa-window3/round3.qa.test.ts`：单人模型按真机改回 `createWorld(def, 1)`
  （第 3 轮取证时传的是 2，`world` 就不知道「现在是一个人在玩」——而修 B2 用的正是这条信息），
  并断言摆烂过关关号列表为空。跑出来：**188 关中 0 关过关、0 关三星、判负 181、僵持 7**。
- 浏览器实测（`idleplay.mjs prince-princess 1`）：修前 13 秒三星过关；
  修后摆烂 70 秒**没有结算**。第 1 关是 `teach=true` `noRisk=true` 且不限时的教学关，
  本来就不会判负，所以摆烂的正确结果就是「一直不结束」——玩家得自己走到城门。
