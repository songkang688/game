## 三、B1 `sky-squad`：放跑判罚是死代码

### 根因

`index.ts` 的 `stepFoes` 里两行顺序反了：

```ts
if (f.y > SKY_H + 60) f.hp = 0;                                  // 先把飞出下边界的敌机 hp 清零
...
const escaped = foes.filter((f) => f.hp > 0 && f.y > SKY_H + 60); // 筛子要求 hp > 0 —— 恒为空
```

`escaped` / `escapedTotal` 永远是 0，`sortieCleared` 拿到的「放跑数」永远是 0。
`logic.ts` 里的 `sortieCleared` / `escapeLimit` 本身是对的，只是从来没收到过真数据。
后果：8 个 Boss 关之外的 **180 关**，玩家一个键都不按、只靠自动射击，
敌机全部从下边界飞走，结算照样判「**0 架**全部请回机库，漂亮的满分航线」三星。

### 修法

1. 撤掉 `index.ts` 里那句提前清零，让 `escaped` 筛子真的筛得到人
   （`hp` 该由伤害与出界收尾统一处理）。判定链一个字没改。
2. `logic.ts` 的 `escapeLimit` 收紧一档：

```ts
return Math.min(Math.max(2, Math.floor(total * 0.25)), Math.floor(total / 3));
```

原来「最少容错 2 架」在小编队关是个洞：一波只有 3 架的关，放跑 2 架还算过关。
现在容错最多不超过总数的三分之一，大编队关的 25% 容错不变。

### 回归证据

- 常驻用例 `src/games/sky-squad/idle.test.ts`（新建，3 条）走
  `createSortie → stepFoes → onFinish` 的**真实路径**（不是直接调 `logic.ts` 的纯函数），
  钉三件事：敌机飞出下边界要记进 `escaped`（`downed + escaped === total`）、
  第 1 关摆烂放跑数超过容错且拿不到三星、**全 188 关摆烂一关都过不去**。
- `scripts/qa-window3/round3.qa.test.ts` 的 B1 取证由「量这个 bug 有多大」改成「钉住它已经修好」。
- **我自己按同一模型重扫全 188 关：0 关过关。** `sky-squad` 7 文件 115 用例全绿。
- 浏览器实测（fixer 跑的 `idleplay.mjs sky-squad 1 60`，我未重跑浏览器层）：

| 关 | 修前 | 修后 |
| --- | --- | --- |
| 第 1 关 | 11 秒过关、**3 星**、「0 架全部请回机库」 | **11 秒判负**、0 星、「放跑了 3 架，超过 1 架就得重飞一趟」 |
| 第 60 关 | 8 秒过关、**3 星** | **8 秒判负**、0 星、「放跑了 4 架」 |

**B1 关闭。**

## 四、B2 `prince-princess`：搭档一个人把整关的活干完

这一款单人模式是「你一位 + AI 搭档一位」，`index.ts` 每帧把没被操作的那位喂给 `botInput`。
所以「玩家不动」≠「场上没人动」。修了两层，缺一层都堵不住。

### 4.1 第一层（`37a0f63`）：城门只认真人手上那位

**根因不在「搭档太强」，在 `checkGoal` 只数人头：**

```ts
const atDoor = w.heroes.filter((h) => Math.abs(h.x - w.def.goalX) < 64 && h.y > -170);
const need = w.def.goalNeedsAll ? w.heroes.length : 1;
if (atDoor.length >= need) { /* 判赢 */ }
```

`goalNeedsAll` 为假的关卡，**托管搭档一个人走到门口就判赢**，
真人在出生点站着不动照样算过关。188 关里 110 关中招，94 关三星。

修法四条：

1. `checkGoal` 加一条：`if (w.players === 1 && !atDoor.some((h) => h.index === w.active)) return;`
   ——一个人玩的时候，城门口那几位里**必须有真人手上那位**。
   两个人玩一字未改，`goalNeedsAll` 语义保留，关卡数据一个数都没动。
2. 新增 `humanHero(w, i)` 与 `world.playerKills / playerGems / playerHits`：
   搭档托管期间的战果单独记账，`swapActive` 换人以后跟着真人走。
3. `starGoals`：一个人玩、而且自己一下都没打中的时候，「路上的怪一只不剩」这颗星不算你的
   （纯跑图关和两人模式不受这条约束）。
4. `winMessage` 与 HUD：搭档打的怪、捡的宝石照实说；单人模式开门提示改成
   「城门开啦！**你自己跑过去才算过关**」，进度条同步。

### 4.2 第二层（`6dbe7fd`）：给托管搭档系上绳子

第一层把摆烂过关归零了，但搭档跑的还是全功能 AI——孩子把手放开，
188 关跑下来搭档仍然清空了 112 关的怪、凑满了 129 关的宝石，还会冲到 3185px 外的城门口干等。
**帮忙可以，包场不行。** 第二层把 `chooseTarget` / `botInput` 限成「只接真人身边的活」：
`ESCORT_ENGAGE = 300`（比真人超前 300px 以上的怪不接）、
`ESCORT_LEASH = 220`（往城门那头最多探这么远）、
`ESCORT_FOLLOW_GAP = 60`（没仗打就退到真人身后半步）。
**往回退不设限**——公主放星星本来就得站远，落在真人身后的漏网之鱼照打不误。

## 五、B3 `duo-vs-star`：对手自己走下台（修法）

测试员点出的方向是对的——不是 AI 档位问题（滑滑冰湖 0/19），
是**场地的可站范围跟小电脑的走位逻辑对不上**。拆下去一共十二条，分两个提交修完。

### 5.1 第一层（`e0dfd13`）：72 → 19 关

| # | 根因 | 修法 |
| --- | --- | --- |
| 1 | `safeZone` 只认最大那块主平台。星光升降台 / 夜空跳台的主平台只有 140–200px 宽，**出生点却在两侧的台子上** —— 小电脑一出生就以为自己已经掉出场，二段跳在半空全按光，然后直直往下掉 | `stages.ts` 新增 `standSpan()`（全部台子的并集，平移台按两头算），`battle.ts` 把 `ground`（并集）与 `stand`（脚下这块）一起喂进 `AiView` |
| 2 | 空中横向加速没有真正封顶（「先加 `AIR_ACCEL`、超了再乘 0.985」是慢一点的加速，不是封顶），追人追着追着横速跑到一千六百多、半秒横穿全场，径直飞出场 | `battle.ts` 把空中操控的横速夹在跑速内；被打飞得来的高速照旧自然衰减，手感不变 |
| 3 | 追人 / 捡道具时就把那唯一一次空中跳跃按掉了，真要回场时没跳可用 | 这两种情况只在**地上**起跳（地上起跳会把空中跳跃补满） |
| 4 | 轻松档 0.46 秒才想一次，掉下去 0.46 秒早就低于台面了 | 新增 `perilous()`：危险中的小电脑临时提速到 `PERIL_THINK`(0.06s)。**只对「自己走下去的」提速**，刚被打飞的那 1.4 秒照旧吃反应延迟（`PERIL_GRACE`），不然谁都救得回来、再也打不出胜负 |
| 5 | 悬空没跳可用时还在「追人 / 回场」之间来回切，最后落进台子之间的缝 | 新增 `pickLanding()`：横着挪到最近那块落得上去的台子上方 |

### 5.2 收尾（`65a690d`）：19 → 7 关

| # | 根因 | 修法 |
| --- | --- | --- |
| 6 | **台沿保险只在决策里做是拦不住的。** 轻松档 0.46 秒想一次，按着方向键这段时间能跑 130px。云朵广场第 1 关的对手就是这么一路走到 x=790（主平台到 770 为止）踏空的 | `battle.ts` 新增 `ledgeSafeInput()`：**每一帧**都过一遍，脚下这块台子到头、那边又没有「比自己低、够得着」的台子接着，就松开那个方向（顺手收掉跳） |
| 7 | 云朵广场右边那块浮空台在 y=288（**头顶**），却被 `standSpan` 算进了「站得住的范围」，小电脑以为右边还有地 | `canLandBeyond()` 只认 `top >= self.y + 8` 的台子 —— 头顶那块落不上去 |
| 8 | 轻松档三成决策是随机乱走（`mistake` 分支），那条路上原本一点边缘判断都没有 | `decideAi` 每条出口都过 `guardLedge()`，把「闭眼往台下迈」的那一步换成往台子里侧挪 |
| 9 | 回场一律奔主平台中间。跳台图上明明左手边就有一块侧台，它偏要横穿整条缝往中间赶，半路高度就掉光了 | 回场改成奔 `pickLanding()` 挑出来的落脚点，起跳门槛按那块台子的高度算；挑的时候为「掉头」付一点代价 |
| 10 | `perilous` 用「比主平台低」判危险，在跳台图上会来回翻：升过主平台高度就以为安全了，转头继续追人往缝里走 | `perilous` 补一条：**悬在两块台子中间的缝上**跟飘出场外一样危险 |
| 11 | 时间到判胜负比的是「还剩几条命」。战役关给玩家 3 条、对手 1 条，玩家一个键不按也是 3:1 稳赢 | `teamStats` / `timeoutWinner` 改成比「上场机会还剩几成」（`stocks / 开局条数`） |
| 12 | 结算只看玩家被撞飞几次，没看玩家有没有出过手 | `Actor.hits` 记真正打中的次数；`rateLevel(lost, hits)` 在 `hits === 0` 时最多一星；`index.ts` 的过关文案不再把对手自己掉下去说成玩家的战绩 |

第 12 条的文案（`index.ts:1612` 起），这一条改得好，值得抄下来：

```ts
me.hits === 0
  ? "这一局你一下都没出手，对手是自己站不住掉下去的。下次主动迎上去，把他撞出场外试试！"
```

## 七、S5 `bumper-cars`：我同意降为轻微（观察）

### 7.1 修法（`65c44d7`）

两条根因分开修：

1. **AI 自杀送关** —— `ai.ts` 加一层**与档位无关**的自保 `cliffGuard`：
   算出「现在松油门还会往悬崖那边探多远」（打滑 / 冰面 / 油渍上按实际摩擦放宽），
   余量不够就把方向按紧迫度掰回场内、点刹车、收掉冲刺与蓄力。
   新手档 `edgeCare` 只有 3、方向抖动却有 0.45 弧度，一路歪着开出场外，正是那 31 关的来源。
   四档之间的差别照旧留在瞄人、绕位、蓄力和挂在台沿能不能爬回来。
   新增 `openEdgeAt()` 只认没装护栏的边——贴着护栏开不再被当成危险。
2. **结算错误归因** —— `logic.ts` 把 `lastHitBy` 换成 `lastPushBy`：
   记的不再是「最后碰过我的人」，而是「最后把我往悬崖顶了一下的人」。
   要留名得三条同时成立：撞的人这一帧真的在开车、撞上那一刻确实朝对方开、
   这一撞给对方加的朝悬崖速度够 `SHOVE_MIN`。台沿救回来（`rescue`）即作废。
   `winLine` 一台都没撞飞时如实说是对手自己下的场；`rateLevel` 多收一个 `knocked`，
   一台都没撞飞的那一局**最多 1 星**。

### 7.3 降级的依据（四条，逐条有证据）

1. **星星拿不满。** 六关**全部 1 星**。`rateLevel` 多收的那个 `knocked` 参数生效了：
   一台都没撞飞，不管剩多少时间、掉没掉下去，都封顶 1 星。修前第 1 关是 10 秒三星。
2. **归因不再张冠李戴。** 六关里玩家名下的撞飞数**全是 0**，
   每一次对手出局的 `by` 字段**全是 `-1`（无人）**，没有一次被算到玩家头上。
3. **文案不再表扬。** 六关的 `winLine` 全部是「对手自己开下了悬崖，你一台都没撞飞」，
   一条都不含「撞飞 N 台」，一条都不含「走位和刹车配合得很好」。
   而且它还如实报了玩家自己掉下去几次——这六关里玩家其实一路在掉（1 到 5 次），
   是对手掉得更快。孩子读到的是一句「你没做到什么」的实话，不是一句假表扬。
