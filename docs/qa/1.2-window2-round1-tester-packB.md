## 一、走查计划（动代码前先立此计划）

对上面 5 款逐款执行下面 8 条铁则，每条都要在本文件里留证据（代码位置 / 用例名 / 实测数值）。

| 序号 | 铁则 | 取证方式 |
| --- | --- | --- |
| 1 | 首页进入 → 真实赢一次、输一次 → 退出再进 | 走 `src/main.ts` 首页卡片 → `mount()`；用 headless domStub 跑到 `win` / `lose` 结算；`destroy()` 后重新 `mount()` |
| 2 | 战役第 1 / 100 / 188 关；对战 / 无尽 / 双人 / 训练场各自玩到结算 | 直开第 N 关的入口 + 每种 `mode` 各跑一局到结算面板 |
| 3 | 双人键位：朵朵 `WASD+F+G`、星星 `方向键+L+K`、`Esc` 暂停 | 读键位映射表 + 派发 `keydown` 断言 |
| 4 | 360px 宽可玩、不溢出、热区 ≥ 44px；`fight-king` 另看触屏四钮与连段计数是否被 HUD 挡住 | 量 CSS 里的 `min-width/min-height/padding`，核对 360 视口下的布局与层级 |
| 5 | `meta.modes` / `levels` / `blurb` / `platform` 与实现一致 | 逐字段对 `index.ts` 的模式分支、关卡表长度、平台能力 |
| 6 | `destroy()` 后监听 / rAF / timer 归零 | 计数 `addEventListener` / `requestAnimationFrame` / `setTimeout` / `setInterval` 的注册与释放 |
| 7 | 商标黑名单 0 命中；无血无死亡描写；`fight-king` 无武器杀伤感 | 全量文案扫描（含 `meta` / `guide` / `levels` / `index` 内联字符串） |
| 8 | 问题分级：阻断 / 严重 / 一般 | 每条问题给出现象 + 位置 + 影响面 |

### 分级口径

- **阻断**：进不去、玩不了、结算不出、崩溃、构建或测试红。
- **严重**：能玩但关键规则/模式/键位/热区错，或 `meta` 与实现不符会误导首页。
- **一般**：文案、边界体验、可维护性一类，不影响本轮交付。

### 不做的事

- 不写 `docs/qa/1.2-round1-*.md` 全局路径。
- 不做第 27–29 步全集。
- 不改窗口 1 平台文件，不验 root 门。
- 不动别人的独占目录与别人的 Pack 报告段落。

## 二、走查结论

走查用的是**无头真跑**：把每款自带的 `domStub` 装上 360px 视口，真的从首页点进去、真的下完 / 打完一局、真的看结算浮层，再 `destroy()` 数监听与定时器。
下面每条结论后面括号里的都是实测到的原文或数值，不是照着代码猜的。

### 1. `dark-chess` 翻翻暗棋

**入口与四种玩法**：`mount()` 之后菜单上四个按钮实测是
`🚩 闯关 188 | ♾️ 无尽连胜 | ⚔️ 人机对战 | 👫 双人同屏`，与 `meta.modes = [campaign, versus, endless, twoPlayer]` 一一对上。

**真实胜负**（用「hell 档水平的人类」镜像着真下，不是随手乱点）：

| 场景 | 结果 | 结算原文 |
| --- | --- | --- |
| 闯关第 1 关 | **赢** ★★★ | `第 1 关过关！` / `把对方的将请去休息啦！` |
| 闯关第 100 关 | **赢** | 标题 `🧠 记牌 · 第 100 关`，HUD `第 100 关 · 普通`，记牌面板 `hidden=false` |
| 闯关第 188 关 | 平局判负 | 标题 `🏆 暗棋杯 · 第 188 关`，HUD `第 188 关 · 地狱`；结算 `就差一点点！/ 连着二十手不吃不翻，这一盘算平局。` |
| 人机对战（菜鸟档） | **赢** | 平台事件 `WIN:3:把对方的将请去休息啦！` |
| 人机对战（乱点） | **输** | `LOSE:这一盘对方先收官了，下一盘先把兵留住。` |
| 无尽连胜 | **输** | `LOSE:这一轮连胜 0 场，历史最好 0 场。再来一轮准能更远。` |
| 双人同屏 | 平局 | `LOSE:连着二十手不吃不翻，这一盘算平局。` |

**退出再进**：对战里点「◀ 换个玩法」回菜单，棋格从 32 个清到 0；连续三轮进出双人同屏，`window` 监听数不涨。

**键位**（双人同屏实测，`dc-cursor` 的格号会跟着动）：
朵朵回合 `D` → 光标 0→1、`S` → 1→9、`→` 无效（符合分键位的要求）；`F` 落子后提示 `翻开了一枚蓝子。`，HUD 变 `轮到星星`；星星回合 `→` → 9→10，`K` 取消可用；`Esc` 后 HUD 变 `已暂停`。
菜单底部提示原文：`朵朵：WASD 移光标，F 确认，G 取消｜星星：方向键 + L / K｜Esc 暂停。`

**360px**：`.dc-board` 是 `repeat(8,1fr)` + `gap:4px`，`.dc-btn` / `.dc-pick` 都写死 `min-height:44px`，按钮达标。**棋格 `.dc-cell` 只有 `min-height:40px`**，见问题 B-1。

**destroy**：`createTable` 的 AI `setTimeout`、`createBoard` 的动画 `setTimeout`、`window.keydown` 全部在 `destroy()` 里清掉；实测 `windowListenerCount = 0`、`root.children.length = 0`。本款不用 rAF。

**meta 一致性**：`levels: 188` 与 `CHAPTERS` 八章 24+24+24+24+22+22+24+24 = 188 对得上；`blurb` 与菜单副标题逐字一致；`platform: "both"` 成立（触屏点格 + 整套键盘）。

**文案**：商标黑名单 0 命中；`ai.ts` 的四档难度叫 `菜鸟 / 普通 / 高手 / 地狱`，见问题 B-3。

### 2. `hue-hand` 花色接龙

**入口**：`♾️ 无尽连胜 · 点我开始! | ⚔️ 对战 2–4 人 | 👫 双人同屏` 三个模式条 + 一张 `.l99-map` 选关地图，四种玩法齐。

**真实胜负**：

| 场景 | 结果 | 结算原文 |
| --- | --- | --- |
| 闯关第 1 关 | **赢** ★★★ | 标题 `🎨 对上颜色 · 第 1 关`，banner `2 人局 · 16 手之内出完手牌` |
| 闯关第 100 关 | **输** | 标题 `🔍 加四与质疑 · 第 100 关`；`就差一点点！/ 这一局牌不太顺,换个顺序试试,先把最多的那个颜色打掉。` |
| 闯关第 188 关 | **输** | 标题 `🏆 接龙杯 · 第 188 关`，`积分赛 · 先拿到 69 分`；`这一届接龙杯被对手先端走了。手上还剩 3 张…` |
| 对战 2–4 人 | **输** | 先出「⚔️ 摆一桌」选人数（2/3/4 人 + 🪑 四人桌），再「开打」；结算 `🤖 这局被 圆圆 拿下 / 这一局收了 46 分。` |
| 无尽连胜 | **输** | `这一局被对手先出完啦 / 连胜停在 0 局,最好成绩 0 连胜…`，chip 同步成 `♾️ 连胜 0 · 最好 0 · 累计 0 分` |
| 双人同屏 | **星星赢** | `🏆 星星先出完啦! / 这一局收了 14 分。总比分:朵朵 0 : 1 星星。` |

双人同屏的换人遮挡幕「我准备好了」实测能挡住对方的手牌（`🂠 牌先收起来啦`），轮到谁才摊谁的牌。

**键位**：`KEYS_P1 = a/d/w/s + f 出牌 + g 抽牌`，`KEYS_P2 = 方向键 + l 出牌 + k 抽牌`，与规格一致。
实测朵朵回合 `D` 光标 0→1、`A` 回 0、`→` 无效；`Esc` 弹出 `⏸ 先歇一会儿` 遮罩，再按 `Esc` 收起。见问题 B-4（提示行只写了 A/D）。

**360px**：`cardWidthFor(360) = 50`、`cardWidthFor(320) = 50`，都 ≥ 48px；`.hh-btn` / `.hh-open` / `.hh-goback` / `.hh-one` 一律 `min-height:44px`，`.hh-one` 另有 `min-width:88px`。见问题 B-5。

**destroy**：三种模式各跑完一局再 `destroy()`，实测 `window` 监听 0、桩里的定时器表 `timers.size = 0`、`root.children.length = 0`。

**meta 一致性**：`levels: 188`、四种 `modes`、`platform: "both"` 都与实现对得上；`blurb` 与攻略口径一致。

**文案**：商标黑名单 0 命中，无血无死亡描写；输局文案是「牌不太顺 / 已经很接近了」这类，没有批评孩子。

### 3. `hop-pads` 跳跳台

**入口**：`♾️ 无尽跳 · 点我开始! | ⚔️ 幽灵对战 | 👫 双人同屏` + 一张选关地图，四种玩法齐。

**真实胜负**（按住 `.hp-hot` 蓄力、`pointerup` 松手，蓄力时长由镜像 `requiredPower()` 算出来，等于「一个手很准的孩子」）：

| 场景 | 结果 | 证据 |
| --- | --- | --- |
| 闯关第 1 关 | **赢** ★★★ | 标题 `⭕ 直线台 · 第 1 关`，提示 `站住 5 座 · ⭕稳台 · 蓄力时会画出落点辅助圆`；连跳 6 次，画布 `data-hops=5 data-combo=5`，结算三颗星全亮 |
| 闯关第 1 关（满力飞过头） | **输** | `phase=over`；`就差一点点！/ 云朵接住你啦,再来一次。这次站住了 0 座,再站住 5 座就过关啦。` |
| 闯关第 100 关 | **赢** | 标题 `🌀 缩小台 · 第 100 关`，`站住 6 座 · ⭕稳台 🌀缩小台`，跳满 8 座 |
| 闯关第 188 关 | 手打输了 | 标题 `🏆 跳跳杯 · 第 188 关`，`站住 16 座 · ⭕稳台 ↔️移动台 🌀缩小台 🌸弹簧台 💠一次台`；实测站住 8 座掉下去 |
| 幽灵对战 | **输** | 先挑对手 `🐰 菜鸟 / 🐼 普通 / 🦊 高手 / 🐯 地狱` 再「开跳 ▶」；结算 `☁️ 云朵接住你啦 / 普通幽灵这次拿了 252 分,你 0 分。` |
| 无尽跳 | **输** | `☁️ 云朵接住你啦 / 这一局站住 0 座,拿了 0 分,最高连击 0。历史最好 0 分。` |
| 双人同屏 | 平手 | 两块画布 + 名牌 `🌸 朵朵 · F` / `⭐ 星星 · L`；结算 `🏁 这一局结束 / 0 比 0,平手!再来一局。` |

**第 188 关是可过的**：把这三关用纯逻辑全程踩圆心跑一遍——
第 1 关 5/5 完美 30 分 三星、第 100 关 6/6 完美 42 分 三星、第 188 关 18 跳 15 完美 104 分 三星，`levelPassed()` 全 `true`。上面第 188 关的失手是「手不够准」，不是关卡不可能。

**键位**（在第 1 关逐个键实测 `data-phase` 的变化）：
`w / a / s / d / ArrowUp / ArrowLeft / g / k` **一个都不起作用**，只有 `f` 和空格会进 `charging`。`Esc` 之后 `data-paused=1`、`aria-label` 变成 `站住 0 座,0 分,连击 0,已暂停`，再按一次回到 0。见问题 B-7。

**双人同屏输入串台 —— 见问题 B-6（本包唯一的严重级）。**

**360px**：`.hp-canvas` 是 `width:100%;height:auto`，`.hp-hot` 是 `position:absolute;inset:0`（整块画面都能按，热区远超 44px）；`.hp-open` `min-height:44px` 达标。**`.hp-back`（模式壳里的「← 返回」）只有 `min-height:40px`**，见问题 B-8。

**destroy**：`cancelAnimationFrame(raf)` + 六个 window 监听（`pointerup / pointercancel / touchend / keydown / keyup / resize`）+ 两个 `hot` 上的监听全部摘干净；三种模式各跑完再 `destroy()`，实测 `windowListenerCount = 0`、`root.children.length = 0`。

**meta 一致性**：`levels: 188` 与实现一致；`modes` 四种都真的能玩到结算。`blurb`「按住蓄力，松手跳到下一座台。踩中圆心连击一直涨，掉下去也会温柔地把你接住」与实测完全对得上（掉下去的文案就是「云朵接住你啦」）。`platform: "both"` 成立，但见 B-6 / B-7。

**文案**：商标黑名单 0 命中；掉下去写的是「云朵接住你啦」，没有任何死亡描写。
