对上面 5 款逐款执行下面 8 条铁则，每条都要在本文件里留证据（代码位置 / 用例名 / 实测数值）。

| 序号 | 铁则 | 取证方式 |
| --- | --- | --- |
| 1 | 首页进入 → 真实赢一次、输一次 → 退出再进 | 走 `src/main.ts` 首页卡片 → `mount()`；用 headless domStub 跑到 `win` / `lose` 结算；`destroy()` 后重新 `mount()` |
| 2 | 战役第 1 / 100 / 188 关；对战 / 无尽 / 双人 / 训练场各自玩到结算 | 直开第 N 关的入口 + 每种 `mode` 各跑一局到结算面板 |

| 5 | `meta.modes` / `levels` / `blurb` / `platform` 与实现一致 | 逐字段对 `index.ts` 的模式分支、关卡表长度、平台能力 |
| 6 | `destroy()` 后监听 / rAF / timer 归零 | 计数 `addEventListener` / `requestAnimationFrame` / `setTimeout` / `setInterval` 的注册与释放 |
| 7 | 商标黑名单 0 命中；无血无死亡描写；`fight-king` 无武器杀伤感 | 全量文案扫描（含 `meta` / `guide` / `levels` / `index` 内联字符串） |
| 8 | 问题分级：阻断 / 严重 / 一般 | 每条问题给出现象 + 位置 + 影响面 |

### 分级口径

- **阻断**：进不去、玩不了、结算不出、崩溃、构建或测试红。
- **严重**：能玩但关键规则/模式/键位/热区错，或 `meta` 与实现不符会误导首页。
- **一般**：文案、边界体验、可维护性一类，不影响本轮交付。

### 不做的事

- 不写 `docs/qa/1.2-round1-*.md` 全局路径。
- 不做第 27–29 步全集。
- 不改窗口 1 平台文件，不验 root 门。
- 不动别人的独占目录与别人的 Pack 报告段落。

### 3. `hop-pads` 跳跳台

**入口**：`♾️ 无尽跳 · 点我开始! | ⚔️ 幽灵对战 | 👫 双人同屏` + 一张选关地图，四种玩法齐。

**真实胜负**（按住 `.hp-hot` 蓄力、`pointerup` 松手，蓄力时长由镜像 `requiredPower()` 算出来，等于「一个手很准的孩子」）：

| 场景 | 结果 | 证据 |
| --- | --- | --- |
| 闯关第 1 关 | **赢** ★★★ | 标题 `⭕ 直线台 · 第 1 关`，提示 `站住 5 座 · ⭕稳台 · 蓄力时会画出落点辅助圆`；连跳 6 次，画布 `data-hops=5 data-combo=5`，结算三颗星全亮 |
| 闯关第 1 关（满力飞过头） | **输** | `phase=over`；`就差一点点！/ 云朵接住你啦,再来一次。这次站住了 0 座,再站住 5 座就过关啦。` |
| 闯关第 100 关 | **赢** | 标题 `🌀 缩小台 · 第 100 关`，`站住 6 座 · ⭕稳台 🌀缩小台`，跳满 8 座 |
| 闯关第 188 关 | 手打输了 | 标题 `🏆 跳跳杯 · 第 188 关`，`站住 16 座 · ⭕稳台 ↔️移动台 🌀缩小台 🌸弹簧台 💠一次台`；实测站住 8 座掉下去 |
| 幽灵对战 | **输** | 先挑对手 `🐰 菜鸟 / 🐼 普通 / 🦊 高手 / 🐯 地狱` 再「开跳 ▶」；结算 `☁️ 云朵接住你啦 / 普通幽灵这次拿了 252 分,你 0 分。` |
| 无尽跳 | **输** | `☁️ 云朵接住你啦 / 这一局站住 0 座,拿了 0 分,最高连击 0。历史最好 0 分。` |
| 双人同屏 | 平手 | 两块画布 + 名牌 `🌸 朵朵 · F` / `⭐ 星星 · L`；结算 `🏁 这一局结束 / 0 比 0,平手!再来一局。` |

**第 188 关是可过的**：把这三关用纯逻辑全程踩圆心跑一遍——
第 1 关 5/5 完美 30 分 三星、第 100 关 6/6 完美 42 分 三星、第 188 关 18 跳 15 完美 104 分 三星，`levelPassed()` 全 `true`。上面第 188 关的失手是「手不够准」，不是关卡不可能。

**键位**（在第 1 关逐个键实测 `data-phase` 的变化）：
`w / a / s / d / ArrowUp / ArrowLeft / g / k` **一个都不起作用**，只有 `f` 和空格会进 `charging`。`Esc` 之后 `data-paused=1`、`aria-label` 变成 `站住 0 座,0 分,连击 0,已暂停`，再按一次回到 0。见问题 B-7。

**双人同屏输入串台 —— 见问题 B-6（严重）。**

**360px**：`.hp-canvas` 是 `width:100%;height:auto`，`.hp-hot` 是 `position:absolute;inset:0`（整块画面都能按，热区远超 44px）；`.hp-open` `min-height:44px` 达标。**`.hp-back`（模式壳里的「← 返回」）只有 `min-height:40px`**，见问题 B-8。

**destroy**：`cancelAnimationFrame(raf)` + 六个 window 监听（`pointerup / pointercancel / touchend / keydown / keyup / resize`）+ 两个 `hot` 上的监听全部摘干净；三种模式各跑完再 `destroy()`，实测 `windowListenerCount = 0`、`root.children.length = 0`。

**meta 一致性**：`levels: 188` 与实现一致；`modes` 四种都真的能玩到结算。`blurb`「按住蓄力，松手跳到下一座台。踩中圆心连击一直涨，掉下去也会温柔地把你接住」与实测完全对得上（掉下去的文案就是「云朵接住你啦」）。`platform: "both"` 成立，但见 B-6 / B-7。

**文案**：商标黑名单 0 命中；掉下去写的是「云朵接住你啦」，没有任何死亡描写。

### 4. `tap-tiles` 音符下落

**键位**（`laneForKey()` 逐键实测）：
单人 `d→0 f→1 j→2 k→3`；分屏 `a→0 s→1 k→2 l→3`；`w / ArrowLeft / g` 三种都是 `-1`（不认）。
`Esc` 弹 `⏸ 先歇一会儿 / 谱面停在这里等你,回来接着弹。`，暂停钮同步成 `▶️ 继续`；再按一次收起、钮回到 `⏸ 暂停`。见问题 B-9。

**360px**：`stageWidth(360) = 336`、`laneWidthAt(360) = 84`（`MIN_LANE_PX = 80`），`stageHeight = 340`；320px 下 `stageWidth = 320`、轨宽 `80`。四条轨每条都比 44px 宽一倍，不溢出。`.tt-btn` / `.tt-open` / `.tt-goback` 都是 `min-height:44px`。这一款的 360px 表现是包 B 里最稳的。

**destroy**：`cancelAnimationFrame` + `keydown` / `keyup` / `pointer*` / `resize` 全摘；三种模式跑完各自的局再 `destroy()`，`windowListenerCount = 0`、`root.children.length = 0`。

**meta 一致性**：`levels: 188`、四种 `modes` 都真能玩到结算、`platform: "both"` 都成立；`blurb`「音符块落下来就点，空白格千万别碰」与 `emptyRule` 的两种实现（`combo` 断连击 / `end` 直接结束）对得上。

**文案**：商标黑名单 0 命中，无死亡描写。

## 四、问题清单（阻断 0 · 严重 2 · 一般 10）

### 严重

**B-2 · `tap-tiles` 同谱对战：满分打平被判输，高档幽灵实际上打不赢**

- 位置：`src/games/tap-tiles/index.ts:919` `const youWin = state.score > rivalScore;`
- 现象：`rivalScore` 由 `aiRun(chart, tier, seed+5)` 算出，高档幽灵在同一张谱上就是满分。人类**每一个音符都踩正点**（`playChartPerfect` 全 Perfect、0 Miss）拿到的也是同一个满分，`>` 判定下平局归对手。
- 实测第 1–10 局：地狱档 **10 局全部打平判输**，高手档 8/10 打平判输；菜鸟档全胜、普通档 4/10 胜。
- 结算面板同时会写出 `🤖 这局对手分高一点 / 你 7800 分 · 对手 7800 分`，**数字自己打自己的脸**——孩子看得见两边一样多，却告诉他对手分高。
- 影响面：对战模式最高两档成了「无论多完美都赢不了」，且文案自相矛盾。
- 建议（本轮只记录）：`>=` 判平局归玩家，或者补一档「打平」的结算文案。

**B-6 · `hop-pads` 双人同屏触屏串台：一个人抬手，两个人一起起跳**

- 位置：`src/games/hop-pads/index.ts:632`（`onUp` 不区分是谁的手指）+ `:661-663`（`pointerup` / `pointercancel` / `touchend` 都挂在 `window` 上，两块 stage 各挂一份）。
- 实测（`hp2.test.ts`，读两块 `.hp-canvas` 的 `data-phase`）：
  - 两人都按住 → `['charging','charging']`；只抬**一根**手指（一次 `window.pointerup`）→ `['flying','flying']`，**两个人一起被弹出去**。
  - 只有朵朵按住上半屏、星星在下半屏 `touchend` → `['flying','ready']`，**朵朵被强行起跳**，蓄力时长完全不由自己决定。
- 对照：键盘一侧是好的。`onKeyUp` 有 `keys.includes(k)` 把关，实测星星松 `L` → `['charging','flying']`、朵朵松 `F` → `['flying','flying']`，各松各的。
- 影响面：双人同屏在手机 / 平板上（也就是这款主要的玩法场景）基本没法正经玩，蓄力全靠对方配合。
- 建议（本轮只记录）：`onDown` 时记下 `pointerId`，`onUp` 比对 `ev.pointerId` 再决定放不放；或者把 `pointerup` 挂到各自的 `hot` 上并 `setPointerCapture`。

## 五、一句话小结

- `fight-king` 是本包完成度最高的一款：五个入口全通、键位与规格逐字吻合、360px 下四钮与连段计数的三条老账全部修完。

- 五款合计 905 条可见文案，商标 / 血腥 / 武器三张黑名单**全部 0 命中**。
