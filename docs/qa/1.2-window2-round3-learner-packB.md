### P3B-1 · `hue-hand` 牌都用完了就收成平局（R3B-1）

**先把问题量出来**（直接摆残局：`deck=[]`、台面粉 7、两人各一张接不上的牌）：

```
deck=0 pile=1
座位 0 能出的牌 0 张,座位 1 能出的牌 0 张
连摸 200 次:真摸到 0 张,手牌 1/1,finished=false,moves=200
```

`refill()` 的守卫（`deck.length > 0 || pile.length <= 1` 就直接返回）本身是对的 ——
弃牌堆只剩台面那一张，洗它就是把台面自己洗走。问题在**没有下一句**：
`pullCard()` 回 `null`，`drawFromDeck()` 就只把回合让给下一家，
于是每一家轮着摸空气，`moves` 一路往上涨，局面一格都不动。

**修法**（`rules.ts` 新增三个纯函数 + `drawFromDeck` 一个分支）：

| 函数 | 干什么 |
| --- | --- |
| `deckExhausted(state)` | 抽牌堆空着、弃牌堆也只剩台面那一张 |
| `noWayForward(state)` | 牌用完了**而且**没有任何一家接得上 —— 只要还有一个人出得了牌，弃牌堆下一手就会重新长出来，就不算走不动 |
| `isDraw(state)` | 这一局收在「牌用完了」的平局上（`finished` 且 `winner < 0`） |

摸不到牌那一刻，先问一句 `noWayForward()`：是就 `finished = true` / `winner = -1`，
并往牌局日志里记一句「牌都用完啦,谁也接不上,这一局算平局。」；不是就照旧只让手，一个字节没改。

**三条界面出口都跟着认平局**（这三处以前都假定 `winner >= 0`，真出平局会算错甚至取到 `BOT_FACES[-2]`）：

| 出口 | 改了什么 |
| --- | --- |
| 对战 | `totals[r.winner]` 加了 `winner >= 0` 的守卫；标题走新的 `versusTitle()`，平局写「🤝 牌都用完啦,这局算平手」，不给星 |
| 双人同屏 | `wins[r.winner]++` 同样加守卫，平局单独记一格「平 N」（和第 1 轮 B-2 给 `tap-tiles` 定的打平口径一致）；顶栏与结算共用新的 `duoScoreLine()` |
| 无尽 | 平局的结算标题不再写「被对手先出完啦」 |

**关卡表一个数都没动 —— 这条是逐关比对过的**：`buildLevel()` 是拿 `simulateGame()` 真打出来的，
所以先把 188 关的 `seed / handSize / maxTurns / goalScore / tiers / players` 全量导出，
改前改后各跑一遍，**`diff` 完全一致**。道理也简单：`simulateGame` 里这一路以前会一直空转到 `maxSteps`
才落进「打不动 → 手牌分最少的人算赢」那条分支，现在提前收口，**落点还是同一条分支**
（谁也接不上就意味着手牌一张都不会再变，算出来的赢家一模一样），所以
`duel()` 的胜负与 `buildLevel()` 的取舍与改前逐条相同。

- 测试：`rules.test.ts` **+5 条**（认得出牌用完 / 摸一次就收成平局且不再空转 / **还有人接得上时绝不误判** /
  弃牌堆还洗得出牌时老路径原样 / 正常开局离这儿还远）；
  `index.test.ts` **+3 条**（真挂一桌摸到平局，`winner=-1`、`gained=0`、屏上写平局；
  对战标题分得清赢 / 输 / 平；双人同屏「平 N」单记一格）；
  `ai.test.ts` **+2 条**（牌用完那一局按「打不动」算，`stalled=true`、赢家仍是手牌分最少的那个、`steps < 10` 不再空转；
  正常对局 60 局 `stalls` 仍是 0，胜率门槛没被碰过）。

### P3B-2 · `hop-pads` 方向键 / `WASD` 按到就指路（R2B-5 / P2B-9）

这一条从第 1 轮的 B-7 一路记到本轮，卡点一直是同一句：**这一款是单键蓄力玩法，四个方向本来就没有语义**，
硬接一个动作（比如按左右也起跳）比不接更糟。所以本轮做的不是「接语义」，是**指路**：

- 新增 `IDLE_KEYS`（四个方向键 + `WASD`）。按到其中任何一个：`phase` 一动不动、
  这一跳的判定一个字节不变，只在屏幕上闪一句 `singleKeyHint()`；
- 那句话按**这一路真正认的键**现编，所以双人同屏左右两边各说各的：
  朵朵那半屏写「按住 F 或 空格 蓄力,松手就跳,蓄过头了按 G 收力」，星星那半屏写的是 `L` 和 `K`；
- 闪的话同时挂到画布的 `data-flash` 上，`Stage` 多导出一个 `flash()` —— 不读画布像素也量得到
  （沿用 P2B-4 给满力信号定的那条路子）。

**第 1 轮 B-6 / 第 2 轮 R2B-2 修的那一段一个字节没碰**：`onDown` / `onUp` / 手指号账本 diff 为空，
`keys` / `cancelKeys` 两条分支都在原位，`IDLE_KEYS` 里也没有 `f` `l` `g` `k` 任何一个（用例逐个守住）。

- 测试：`index.test.ts` **+3 条**（八个键逐个按，`phase` 全程 `ready`、屏上出现指路话、座数仍是 0 /
  指路话按键位现编且不含任何一个真键位 / 中间穿插乱按之后，同样的力度跳出来的座数、分数、连击**一字不差**）。

### P3B-3 · `dark-chess` 记牌面板列到兵种

`remainingUnknown()` 一直是**按兵种**数的（函数注释写的就是「某一色还有哪些兵种没露过面」），
可 `view.ts` 把它 `reduce` 成一个总数就扔了 —— 屏幕上只剩「红还盖着 12 / 蓝还盖着 11」。
暗棋真正要学的那半截（**还剩一枚帅没露面，谁都不敢把士往前送**）就这么丢了。

现在按相克次序从大到小列出来：`红还盖着 16 · 帅1 仕2 相2 俥2 傌2 炮2 兵5`。
翻光了的兵种自动不占位置，全翻完写一句「都翻出来啦」，**还是两行，没占新地方**。

新增的 `counterLine(color, left)` 是纯函数，UI 只负责把它塞进两个 `<span>`。
记牌面板什么时候打开（`planFor().showCounter`，第 5 章起）一个字没改。

- 测试：`smoke.test.ts` **+4 条**（两色的整行字逐字对 / 翻光的兵种不占位置、全翻完那句话 /
  真开一盘：两行写全七个兵种，翻掉第 0 格之后**那个兵种的数正好少 1** / `showCounter=false` 时面板照旧收着）。

### P3B-4 · `hue-hand` 「就一张」抢按窗口给可见倒数

会点破的对手等 1800ms 才动手，可屏幕上没有任何「快按」的信号 ——
孩子只知道自己莫名其妙被罚抽了 2 张，根本不知道刚才该按哪儿。

- `CATCH_DELAY_MS = 1800` 与 `CATCH_TICKS = 3` 提成常量。**窗口时长一毫秒没动**（动它就是动难度），
  只是把「还剩多久」摆成钮上的三格倒数：`☝️ 就一张 3 → 2 → 1`，配色再催一档（`.hh-one-hot`）；
- 喊掉了、被点破了、或者窗口本来就不存在（对面是新手档，从来不点破人），倒数立刻收回去；
- 同一个窗口不会被后面几手重复开成两轮（`catchFor` 记着盯的是谁）—— 顺带把以前每走一手就重挂一个
  1800ms 计时器的重复排程也收干净了，**头一个计时器照旧按时到点，判罚时刻一点没变**。

- 测试：`index.test.ts` **+4 条**（有人盯着就摆倒数、一格一格往下走 / 喊掉了钮就收、之后罚不到 /
  **`CATCH_DELAY_MS - 1` 毫秒时还没罚、再走 2 毫秒就罚**，且这个数仍旧是 1800（守住难度）/
  对面是新手档时不摆倒数）。

### P3B-5 · `dark-chess` 手数上限也给倒数

P2B-5 给「连着 20 手不吃不翻判和」补了倒数，可另一条同样会收场的线 ——
`state.plies >= maxPlies` 就算平局收场 —— 一直一声不吭。
第 6 / 7 章是残局关，上限只有 **60 手**，走到头照样是「怎么突然就结束了」。

### P3B-6 的根因证据（本轮新量的，交给平衡专项）

四档两两互打各 120 局，**正反座位各跑一遍**（`duel(a, b, 120)` 与 `duel(b, a, 120)`）：

| 对局 | 正向 | 反向 | 合计（强的那一档） |
| --- | --- | --- | --- |
| 新手 vs 普通 | 62 : 58 | 55 : 65 | 普通 **123 / 240**（51%） |
| 新手 vs 高手 | 0 : 120 | 0 : 120 | 高手 **240 / 240**（100%） |
| 新手 vs 大师 | 0 : 120 | 0 : 120 | 大师 **240 / 240**（100%） |
| 普通 vs 高手 | 52 : 68 | 60 : 60 | 高手 **128 / 240**（53%） |
| 普通 vs 大师 | 50 : 70 | 58 : 62 | 大师 **132 / 240**（55%） |
| 高手 vs 大师 | 53 : 67 | 69 : 51 | **大师 118 / 240（49%）—— 大师其实不比高手强** |

两条结论摆在这儿，都不是「AI 写得不够聪明」那么笼统：

1. **真正的分水岭是「会不会点破忘喊」**（`aiCatchesOneCard`，rank ≥ 2 才会）。
   新手档自己不喊「就一张」，一到 1 张就被罚抽 2 张，于是对高手 / 大师是 **0 : 120** 的碾压；
   而普通档会喊，所以它对新手只是 51%。**`rate()` 那套打分在两档之间几乎不产生胜负差。**
2. **大师那层 `rank >= 3` 的加料反而是负收益**：合起来 118 : 122 输给高手。
   最可疑的两处是「加牌牌先攒着卡链」的 `-5`（`isDrawCard(card) && hand.length > 3` 时压低出加牌的优先级）
   和续链时 `pick = stacks[0]`（拿手牌里第一张能续的，而不是打分最高的那一张）。

所以要收 R3B-3，**该动的是这两处 + 给相邻两档各自补一个正交能力**，
而不是把噪声调大 —— 但无论动哪一处，188 关都要整张重算，属平衡专项的活。
