## 五、本轮记录的问题

### 阻断（0 项）

无。没有一款进不去、白屏、卡死或报错。

### 严重（4 项）

**S1 · `bowling-lane` 360px 关卡页横向溢出 24px**
360×720 下进第 1 关，`document.scrollWidth - clientWidth = 24`，页面能横向拖动。同一视口下首页溢出为 0，其余 18 款关卡页溢出也都是 0，只有这一款超。手机上小朋友一划就把球道拖歪。
证据：`window3-round1-browser.s?.json` → `bowling-lane.mobile.overflowLevel.doc = 24`。

**S2 · `candy-swing` 第 91 关「反向配送」不动手也会自己过**
该关 `solve.kind = "cut"`（设计意图是玩家自己剪绳），但建好仿真世界后**一下都不点、空跑 20 秒，糖果自己掉进怪物嘴里**（`ate=true`）。抽样的另外 8 关里，只有第 120 关「剪刀齿轮」也会自动吃到——但那一关 `solve.kind = "wait"`，等场上齿轮剪刀自己剪本来就是设计，不算问题。所以真正对不上的是第 91 关。
证据：`window3-sim.json` → candy-swing「不动手也自己吃到的关 91/120」。

**S3 · `duo-rush` 人机 2 档和 3 档跑不出差别**
固定 seed 各跑 90 秒，星星（AI 座位）成绩：0 档 318 米 / 撞 3 次，1 档 353 米 / 撞 1 次，2 档 353 米 / 撞 0 次，3 档 353 米 / 撞 0 次——**2 档与 3 档完全一致**。翻 `src/games/duo-rush/ai.ts` 看到 `AI_SPEED_MULT = {0:1, 1:1, 2:1, 3:1}`，四档速度一模一样，档位只作用在反应时间 / 失误率 / 吃金币贪心度 / 会不会挡人上；在直线赛道上这几项对「跑多远」几乎没有影响，最后只剩撞车次数在动，而 2/3 档都已经是 0 次，没有再往上的空间。
**这是单 seed 单样本的观察**，我不把它当成板上钉钉的缺陷。第 2 轮会用多 seed 多局重测后再下结论。

**S4 · `bowling-lane` 三档人机差距几乎不可感知**
10 格连打，冠军球手倒 94 瓶 / 记 136 分，新手球童倒 90 瓶——**三档只差 4 瓶**。「新手球童 / 熟练球手 / 冠军球手」三个名字给孩子的预期落差远大于实际。同样列为待第 2 轮多样本复核项。

### 轻微（5 项）

**M1 · 10 款的最小触控目标小于 44px**
360px 视口下量到的最小可点元素：`tank-battle` 23px（`tkb-mini-btn`）、`ice-fire-forest` 25px（`iff-btn--ghost`）、`shoot-range` 29px（`shr-toggle`）、`bumper-cars` 31px（`bc-btn--ghost`）、`puff-bros` 31px（`pfb-btn`）、`sky-squad` 31px（`sks-opt`）、`duo-vs-star` 32px（`dvs-back`）、`prince-princess` 37px（`pcp-mode`）、`bomb-buddies` 40px（`bmb-btn--ghost`）、`duo-rush` 43px（`dr-rulesbtn`）。其余款都 ≥ 44px。这些多是「次要/幽灵按钮」和返回键，不影响主玩法，但这是给孩子玩的产品，23px 的按钮小朋友很难点准。

**M2 · 四款的无尽压力曲线在中段就封顶**
`shoot-range`：出怪间隔 0 秒 1.50 → 30 秒 1.18 → 60 秒 0.87 → **120 秒 0.42 → 240 秒 0.42**，两分钟后不再加压。
`snow-fight` 雪季：**10 波和 20 波都是 6 人 / 命中 0.86 / 投掷间隔 1.70 秒**，只有「行进」还在动（0.94 → 1.10）。
`sling-birds` 打靶塔：1 轮 3 层 → 5 轮 7 层 → **10 轮 12 层 → 20 轮 12 层**。
`tank-battle` 无尽守巢：**1/5/10/20 波地图都是 13 行**。
封顶本身不一定是 bug（防止后期无解也是一种设计），但「无尽」的卖点是越来越难，玩到中段就恒定会让大孩子失去继续的理由。第 2 轮会专门查「无尽能不能持续」，届时给最终判断。

**M3 · `duo-arena` 一档到二档有断层**
四档各对最弱档打 40 局：rookie 对 rookie 53.8%（镜像，正常），normal 100.0%、pro 100.0%、master 100.0%。也就是说 normal 已经把 rookie 打穿，再往上的三档对新手而言没有区别。该款自己的用例「相邻两档对下 20 局，高的一档胜率明显占优」是绿的，说明相邻档之间确有梯度，问题只出在「对最弱档」这个切面上饱和了。归为观察项。

**M4 · `garden-guard` / `sprout-defense` 首屏没有任何 DOM 按钮**
两款是整屏 canvas，模式切换、选关全画在画布里。`garden-guard` 连一个可测的 DOM 按钮都没有（`sprout-defense` 只有一个 44px 的 `spd-skip`）。后果有两个：一是键盘 Tab 走不到任何控件、读屏软件拿不到信息；二是自动化走查进不去它们的无尽模式，本轮这两款的模式覆盖只能靠 B 层。其余 17 款都有 DOM 模式钮。

**M5 · `duo-vs-star` / `duo-arena` 把整段玩法说明印进按钮文本**
例如「👫 双人对战同屏两套键位，朵朵 WASD+F/G，星星 方向键+L/K」「🤖 人机混战最多 4 人一起打，小电脑有轻松 / 正常 / 高手三档」，单个按钮文案 40+ 字。360px 下这些按钮会撑得很高，一屏放不下几个。功能没问题，是信息层级问题。

## 六、本轮排掉的四个假警报（记下来免得下轮重犯）

走查工具第一版跑出过四处「摆烂（完全不操作）也能赢」，看着很像大 bug。逐条用 B 层对账后，**全部是走查工具自己的问题，不是产品缺陷**：

| 报的现象 | B 层对账 | 结论 |
| --- | --- | --- |
| `sky-squad` 第 1 关摆烂通关，文案「0 架全部请回机库」 | 第 1 关 3 架敌机；`escapeLimit(3) = 2`，全放跑时 `sortieCleared` 返回 `false` | 上一局的结算浮层没消干净被读到了 |
| `bumper-cars` 第 1 关摆烂通关 | 全体不动 → 清场 `false`、玩家出局 `false`（僵持） | 同上 |
| `prince-princess` 第 1 关摆烂通关 | 第 1 关不动 14400 步仍是 `playing` | 同上 |
| `duo-vs-star` 第 1 关摆烂拿三星 | — | 同上 |

三个根因，都已在 `driver.mjs` / `run.mjs` 里修掉并写进注释：

1. **hash 不变不会触发 `hashchange`，游戏根本不重挂**。两局之间必须先 `location.hash = ""` 回首页再进去，否则上一局的弹窗一直盖在那儿。
2. **把第 188 关也种成 3 星，第一次通关就会弹平台的「188 关全部走完」庆祝弹窗**，之后每一局的结算都被它盖住。改成末关留 0 星。
3. **常驻的「🗺️ 回地图」被当成了结算面板**。改成只认 `position: absolute/fixed` 的浮层，并收紧胜负关键词。

另外还纠了两处会让报告写错的取证错误：
