### 2.5 `R3-PA-PS-1`（一般）：**主体已消失，残一处 —— 本轮修掉（`30ec9ad`）**

这一条一共经手三拨人，各解决同一句话的不同半截：

1. 第 2 名测试员记下：`loseLine` 无条件在 reason 后面接一句「这一杆差一点点，换个角度再来。」，
   而最常见的那条 reason 自己就是这句话，浮层上连着说两遍；
2. `d324399` 拦住了含「这一杆差一点点」的那一条；
3. `82bdd3c` 把闸从一条词拉宽到三条词，另外两条自带收尾的 reason 也不再重复。

**我从 `levels.ts` 源码里把 `levelSuccess` 的失败 reason 全扫出来逐条过，发现拉宽之后还剩一个豁口**：

| reason | 拉宽之后的浮层 | 重复 | 有没有请他再来 |
|---|---|---|---|
| `母球掉袋了，这一杆不算数，换个角度再来。` | 原样 | 无 | ✅ |
| `这一关要先吃一次库，直接打过去不算数。` | + 整句鼓励语 | 无 | ✅ |
| `母球要先碰前面那颗球，才叫组合球。` | + 整句鼓励语 | 无 | ✅ |
| **`母球先碰到的不是自己那一组，这一杆差一点点。`** | **原样** | 无 | **❌ 六条里唯一一条没有「再来」** |
| `这一杆差一点点，换个角度再来。` | 原样 | 无 | ✅ |
| `进了，可惜不是指定的那个袋，再瞄一次。` | 原样 | 无 | ✅ |

根因是 `ENCOURAGE` 其实是**两件事**拼起来的：前半句「这一杆差一点点」说的是**这一杆的成色**，
后半句「换个角度再来。」是**请他再来一次**。前手把这两件事混在一张表里数，
于是这条 reason 只因为带了前半句就被整句放行，成了唯一一条没有邀请的收场话。
别的失手都请孩子再试一次，就这一条没有。

**改法**（`30ec9ad`，只动 `loseLine` 一个函数）：把两件事分开数——
自带邀请的一个字不加；只带成色的补后半句；什么都没带的补整句。
**这是把同一条闸再拉宽一格，不是回滚**：`ENCOURAGE` 导出与「补句号」那一手原样保留，
另外五条收场话**逐字未变**，只有那一条从
`母球先碰到的不是自己那一组，这一杆差一点点。`
变成
`母球先碰到的不是自己那一组，这一杆差一点点。换个角度再来。`

### 5.1 为什么严重项修好了还要再补一张网

`stall.test.ts`（`d324399` 留的）盯的是 `stepPhysics` 那一层——看门狗会不会醒、
醒了会不会放能、撑满 `FREEZE_MS` 会不会强制停稳。那是**根因层**，但不是孩子看到的东西。
孩子看到的是「这一局到底收不收得了场」，而从根因走到收场要穿过 `index.ts` 的三段接线：

```
update()  → overLine(world)                              判越线（只看已静止的果子）
update()  → opts.limited && left() <= 0 && allSettled()  判收摊
stepAi()  → if (!allSettled(world) || aiWait > 0) return; 电脑等自己那盆停稳才想下一手
```

**第三段一直没有任何测试**，而 `R3-PA-FS-2` 正落在这一段：电脑那盆一进死状态
`aiTarget` 永远是 `null`，对战的 `drops` 又是 9999（不存在「果子用完」），这一局就永远不结束。
哪天有人把看门狗的阈值调松、或者把 `stepAi` 的等待条件改回去，物理那一层的网未必红，这一张会红。

所以新增的 4 例**全部从界面驱动**：点进模式、按键投果、一帧一帧推，只认结算浮层出没出来。
另外把随机落点从第 188 关一关扩到第 1 / 132 关（三种盆宽 / 弹性 / 果子档各一遍）。
