#### W5-L-01 · `clock-house` 题面钟面的读屏标签不许把答案念出来 —— ✅ 本轮落地

- **来源思路**：无障碍工程里一条通行的规矩——**装饰性图形给空标签，信息性图形给等价描述，但「题目本身」不能在标签里把答案说了**。同一件事在题库类开源项目里通常靠一条「题面渲染出来的任何文本表示都不得包含 `answer`」的守门用例钉住。测试员的 W5-A-01 就是这条规矩的一个反例。
- **现状**：`levels.ts` 的老钟面 `clockSVG()` 把 `aria-label` 写死成 `formatClock(hour, quarter)`，`clockface.ts` 的新钟面 `faceSVG()` 默认 `label = formatClockMinute(time)`。于是「钟面上是几点？」这道题，题面那张 SVG 的标签就是「4 点」，而三个选项正是「6 点 / 4 点 / 2 点」。作者其实清楚这个风险——`qSetMin()` 给**选项**钟面显式传了 `label: "钟面"`——只是**题面**漏了。
- **落地方式**：把两个渲染器的默认标签一起改成 fail-closed：新导出常量 `FACE_LABEL = "钟面，自己读一读"`，`clockSVG()` 多一个 `label` 形参（默认 `FACE_LABEL`），`faceSVG()` 的 `opts.label` 默认值从时刻改成 `FACE_LABEL`；选钟面题（`qSet`）的三张选项统一显式给「钟面」；顺手给老 `clockSVG()` 补了缺的 `role="img"`。**拨一拨那个练手钟面照旧实时念读数**——它由 `dial.ts` 在拖动时改写标签，念的是「孩子现在把针拨到了哪」，不是答案，属于必要反馈。
- **量化**：`read` 413 道 + `readMin` 33 道 = **446 道**题的题面标签不再泄答案（这个数是我在本轮遍历 188 关重新点出来的，和测试员的 446 对得上）；选钟面题另有 96×3 张选项钟面一并收口。`clock-house` chunk 29.13 → **29.18 kB**（+0.05 kB）。
- **受益游戏 id**：`clock-house`。
- **守门用例**：新增 `src/games/clock-house/a11yLabels.test.ts`（4 条）——188 关题面与选项的每一个 `aria-label`①不许含数字、②不许包含本题答案；两个渲染器的默认标签与显式传参行为；`role="img"` 在位。另有一条自检「扫到的标签数 > 400」，防止将来标签被整体删光后这条用例空转变绿。
- **既有断言被迫修改（单独解释）**：`levels.test.ts` 有一条 `LEGACY_DIGEST` 摘要锁，钉「前 99 关一个字节都没被 1.2 碰过」。改了钟面的读屏属性以后它会红。**我没有换摘要值放水**，改的是比对方式：先把标签按钟面自己的 `data-h` / `data-q` 还原成 1.1 的写法、去掉新加的 `role`，还原完的字节流仍然必须等于**原来那串** `5a314f…296cf`。也就是说这条锁现在钉的是「除了那个读屏属性，前 99 关没有第二处改动」，比原来更明确。同时另补一条「前 99 关的钟面确实换上了不含时刻的标签（扫到 >300 个）」，两条一正一反。
- **风险与回滚**：风险是读屏用户失去了「不读钟也知道现在几点」的捷径——但这正是这道题要考的东西，且题面另有 `ask`（「钟面上是几点？」）与三个可读选项，题仍然做得下去。回滚：`git revert 3bc5fcf`，单条独立。

#### W5-L-02 · `word-garden` 题干不许写着要填的那个字 —— ✅ 本轮落地

- **来源思路**：题库工程里的「自指检查」——**题面（含释义、义项、提示词）不得包含 `answer` 的任何字面**。现有的「答案唯一」类用例只管三个选项之间的关系，管不到题干，是个常见盲区。测试员的 W5-A-02 与 A5 节点名的守门缺口就是这条。
- **现状**：两处自指。① 三张成语卡的 `meaning` 里带着被挖掉的那个字——「兴高采烈」挖「高」而释义写「**高**兴得神气十足」、「一心一意」挖「心」而释义写「**心**思全在一件事上」、「春暖花开」挖「暖」而释义写「天气转**暖**花都开了」；② 偏旁题反过来问「哪个字和「树木」有关？」时，答案可能正好就是义项词里那个「树」。
- **落地方式**：
  - 成语卡换三条不含答案字的说法：「只认准一件事去做」/「情绪很好、很神气」/「天气回温，花都开了」（都在既有用例要求的 ≤10 字以内，且互相不撞）；`IdiomCard.meaning` 的注释里把这条规矩写死。
  - 偏旁题不改文案改生成器：`logic.ts` 新增纯函数 `radicalTargets(card)`，**把义项词里出现过的字从候选答案里剔掉**，剔干净了一个都不剩就退回全表（数据写坏时宁可弱一点也要出得了题）。`levels.ts` 的 `qRadical()` 从 `pick(rand, card.chars)` 改成 `pick(rand, radicalTargets(card))`——`pick` 无论数组多长都只消耗一次随机数，**题库的确定性生成序列不受影响**。
- **量化**：成语这一路修掉 **21 道**白送题（8 + 8 + 5，与测试员的统计逐条对得上）。偏旁这一路测试员点名了 2 张卡（`木/树木` → 树、`讠/说话` → 说），本轮实际堵上的是 **4 张**——顺带扫出 `艹/花草植物` 里的「花」「草」和 `目/眼睛` 里的「眼」「睛」，同样是义项词自己写着答案。四张卡剔完各自还剩 4–5 个字可问，出题面不变窄。`word-garden` chunk 67.28 → **67.38 kB**（+0.10 kB）。
- **受益游戏 id**：`word-garden`。
- **守门用例**：新增 `src/games/word-garden/noSpoiler.test.ts`（3 条）——成语卡释义不含挖空字；偏旁卡剔完仍剩 ≥3 个字且候选一个都不在义项词里（带「确实有 ≥2 张卡被剔过」的自检，防空转）；188 关每一道成语题与偏旁题的 `ask` 都不含正确答案（覆盖 195 道，断言 `checked > 150`）。近反义 / 多音字 / 看字选意思那几类题干点名的是**被问的那个词**、不是答案，属玩法本身，明确不在这条线里。
- **风险与回滚**：唯一的内容风险是新释义与相邻成语的释义撞车（「一心一意」和「专心致志」本来就近），我挑词时避开了原来的「一门心思」句式；`bank.test.ts` 既有的「成语题答案唯一」与 `levels188.test.ts` 的「答案能从字词库反查」两条全绿，说明没撞。回滚：`git revert e738590`。

#### W5-L-04 · `color-fun` 自由画室要把背后的选关地图关进 `inert` 并接管焦点 —— ✅ 本轮落地

- **来源思路**：模态浮层的标准三件套——**背景 `inert` + `aria-hidden`、打开时焦点进浮层、关闭时焦点回到触发它的那颗按钮**。仓库自己的平台层其实已经有这套（`src/ui/dialogs.ts` 的焦点陷阱、`a11y.test.ts` 的「Esc 关闭、关闭后焦点归位」），画室是关卡外自建的一层纸，没吃到。
- **现状**：画室是 `position:absolute; inset:0; z-index:9` 的 `.clf-sheet`，视觉上盖满了 host，可底下的模式条与选关地图 `display:block`、没有 `inert`、没有 `aria-hidden`，**11 个看不见的控件仍然可聚焦**。测试员实测 Tab 要先走 20 站才轮到「✖ 关上画室」，中途还可能误触「开始冒险」直接跳出画室。
- **落地方式**：`sandboxUi.ts` 新增纯函数 `muteBehind(targets)`——给每个节点挂 `inert` + `aria-hidden="true"`，并**按原值**返回一个还原函数（本来就写着这两个属性的节点不会被顺手擦掉）。`openSandbox()` 里把 `host` 除画室以外的孩子交给它；开画室前记下 `doc.activeElement`，开完把焦点直接放到「✖ 关上画室」；`destroy()` 里**先还原属性再把焦点还回去**（顺序反了会把焦点丢给一个还是 `inert` 的节点）。
- **量化**：画室打开时 Tab 的第一站从**第 21 站**变成**第 1 站**；host 内可聚焦的隐藏控件从 11 个降到 0 个。`color-fun` chunk 58.52 → **59.10 kB**（+0.58 kB，两条 a11y 逻辑加注释的全部代价）。
- **受益游戏 id**：`color-fun`。
- **守门用例**：新增 `src/games/color-fun/sandboxA11y.test.ts`（8 条）。仓库的 vitest 跑在 node 环境、按既定约定**不引 jsdom**，所以分两路验：纯函数 `muteBehind` 拿极简元素桩逐条验（挂上、按原值还原、空数组不炸），`openSandbox` 里怎么用它用源码巡检钉住（交给 `muteBehind` 的是 `host.children` 里除 sheet 以外的孩子；初始焦点是 `closeBtn`；`destroy` 里 `restoreBehind()` 排在 `opener?.focus?.()` 前面）——这和本款既有的 `upgrade12.test.ts` 是一个路数。
- **已知余量**：`inert` 只盖得住 `host` 里面的东西。平台壳层那三颗（返回 / 攻略 / 暂停）在 `host` 之外，画室开着的时候仍然 Tab 得到。要把它们也关进去就得动 `src/ui/gameShell.ts`，属**窗口1**，本轮不越界；而且「暂停」在浮层里仍然可达其实不算坏事，登记在此供后续判断。
- **风险与回滚**：`inert` 在目标浏览器（Chrome 105+ / Safari 15.5+）都支持，不支持的老环境上 `aria-hidden` 仍然生效，属渐进增强；副作用是画室开着时「🎨 自由涂色（不计分）」那颗切换按钮不再能点第二下关闭——但它本来就被 `inset:0` 的画室整个盖住、点不着，行为没变。回滚：`git revert 4e17521`。

#### W5-L-05 · `color-fun` 自由画室支持 Esc 关闭 —— ✅ 本轮落地

- **来源思路**：同上那套弹窗惯例的最后一件——**Esc 一定要能关掉浮层**。平台的 `dialogs.ts` 有 `isDismissKey`（`Escape` 和老浏览器上的旧名字 `Esc` 都认），画室没吃到。
- **现状**：画室只能靠点「✖ 关上画室」退出，键盘用户没有退路。
- **落地方式**：`sandboxUi.ts` 导出 `isSandboxDismissKey(key)`，在 `.clf-sheet` 上挂一个 `keydown`，认到就 `preventDefault` + `stopPropagation` 后走 `opts.onClose?.()`——**关闭仍然由外面那套 `closeSandbox()` 统一收口**，画室自己不偷偷拆 DOM，`destroy()` 该做的还原与焦点归位一件都不会漏。`stopPropagation` 是为了不让这一下 Esc 顺着冒到平台壳层再触发一次别的关闭。判定逻辑没有 `import` 平台文件，自己写了一行——本档不许碰 `src/ui/**`，连引用都省掉，少一条跨窗依赖。
- **量化**：画室的键盘退出路径从 0 条变 1 条；配合 W5-L-04 的初始焦点，键盘用户「开画室 → Esc → 焦点回到开画室那颗按钮」整条链闭合。
- **受益游戏 id**：`color-fun`。
- **守门用例**：并在 `sandboxA11y.test.ts` 里——`isSandboxDismissKey` 认 `Escape` / `Esc`、不认 `Enter` / 空格 / `Tab` / 小写 `escape`；源码巡检钉住 keydown 分支走的是 `opts.onClose?.()` 且带 `stopPropagation()`。
- **风险与回滚**：唯一的风险是和平台某个全局 Esc 撞车；扫了一遍 `src/ui/**`，只有 `collection.ts` 与 `guide.ts` 的弹窗在听 Esc，都是各自弹窗自己的监听，且我们这一下已经 `stopPropagation`。回滚：和 W5-L-04 同在 `4e17521`，一起 revert。

#### W5-L-08 · `red-blue-race` 战役对手的动态难度（追赶时手抖、领先时收力） —— ❌ 本轮不落地

- **来源思路**：休闲竞速类里很成熟的一条——**会失误的对手比完美对手好玩**，再叠一层温和的橡皮筋（落后方拿一点点助推、领先方节奏抖一下），能把「一边倒」的局面压成「咬得很紧」。
- **现状**：本款其实已经做得相当好——`ai.ts` 把四档建模成「目标节奏 + 稳定度 + 失误率 + 反应时间」，`tapsPerSec` 一律不许超过 `HUMAN_TAP_CAP_HZ`（赢在稳不赢在开挂），`runAiLane()` 给定同一个 `rand` 完全确定、四档强度单调有断言钉着。缺的只是**局内的动态调节**：目前一档从头到尾一个参数。另外本款已有「🤝 让分」这颗人工助推开关，动态难度和它是同一个位置上的两套东西，得先想清楚要不要叠。
- **为什么本轮不落地**：这是**直接动玩法手感**的改动，本轮纪律写着「改动要小而稳，不许推翻既有玩法手感」。要落地得先补一批 `runAiLane` 的对局分布回归（胜率带宽、领先差值分布），不是一条断言能兜住的。**建议第 2 轮**，和让分开关的定位一起定。

#### W5-L-09 · `clock-house` 错题回顾的「同类换数字」覆盖率做成可回放的种子用例 —— ❌ 本轮不落地

- **来源思路**：确定性随机 + 可回放输入序列。既然 `reviewSeed` / `makeReviewQuestions` 已经是纯函数，那「错了哪几类 → 回顾轮出的是不是这几类、是不是换了数字而不是原题重放」完全可以拿一组固定种子跑成快照。
- **现状**：`mistakes.ts` 的统计与 `makeReviewQuestions` 各自有用例，但**「统计 → 回顾题型」这条链**目前只有测试员的一次实玩记录（第 1 关错一次，确实多出一轮同题型换数字的题），没有机器钉着。
- **为什么本轮不落地**：不是缺陷、是覆盖率，属锦上添花；本轮的 5 条落地已经把测试员记的一般级问题清完，再堆用例会稀释这一轮的可复核性。**建议第 2 轮**，本档目录内即可完成，不碰任何共用文件。

#### W5-L-10 · `landlord-cards` 三档牌力提示的「不泄底」守门用例 —— ❌ 本轮不落地

- **来源思路**：和 W5-L-06 同源——**提示只许给方法，不许给答案**。本款的「💡 提示」有三档强度，测试员这轮实玩确认没泄底，但和 `clock-house` / `word-garden` 那两条一样，**没有机器钉着就会长回来**。
- **现状**：`hint.ts` 有 `hint.test.ts` 覆盖提示的挡位与内容生成，但没有一条断言说「提示文案里不许出现对手手上具体是哪几张牌」。
- **为什么本轮不落地**：这条要先和 `hint.ts` 的作者对齐口径——三档里最强的那一档本来就带「建议出哪一手」，那算不算泄底得先定义清楚（教学型提示和泄底之间的线，在纸牌类里和在题库类里不一样）。定义没定之前写用例是拍脑袋。**建议第 2 轮**，先在报告里把口径讨论完再写断言。
