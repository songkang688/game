## 1. 已修：2 条严重

### 1.1 `R3-PA-FS-1` / `R3-PA-FS-2` · `fruit-stack` 果盆进极限环，这一局收不了场（严重）

**症状（第 2 名的取证）：**

- 随机落点（不挑最差）下第 **188 关 20 盆全中**、第 132 关 9/20、第 1 关 2/20；
  第 188 关平均投到第 22 / 38 颗就卡住；
- 界面上第 132 关落点一步不挪投完 43 颗，**空跑 100 秒不出结算浮层**，
  盆里 16 颗有 10 颗速度仍有 58～130px/s；
- **人机对战里电脑自己会把自己冻住**：人一次都不碰键，电脑投到第 29 颗后空转 283 秒再没出手
  （`stepAi` 也卡在 `allSettled` 前面），这一局怎么等都不结束。

**根因：** 两条判负通路（果子投完判负、越界判负）与 `stepAi` 都挂在 `allSettled` 上，
而 `allSettled` 在极限环里**永远回不了真** —— 果堆里几颗果子互相顶着，
每一次碰撞都按恢复系数弹回一点点，能量既不增长也不衰减到零，就这么循环下去。

**修法（`physics.ts`，三段兜底，一段比一段硬）：**

| 段 | 做法 | 门槛 |
| --- | --- | --- |
| ① 恢复系数下限 | `resolveCircles` / `resolveBounds` 里，相对速度低于 `BOUNCE_MIN_SPEED` 就**不再回弹**，只做位置分离 | 掐掉「越弹越小但永不为零」这条尾巴 |
| ② 蠕动阻尼 | `substep` 里速度低于 `CREEP_SPEED` 的果子每帧乘 `CREEP_KEEP` | 慢速漂移被主动拉停 |
| ③ 看门狗 | `stepPhysics` 累计 `stallMs`：超过 `STALL_MS` 上强阻尼 `STALL_KEEP`；超过 `FREEZE_MS` 直接 `forceSettle` 全盆 | **兜底保证有限时间内一定收敛** |

三段是递进的：①②让绝大多数情形自然停稳，③只在前两段都没拽住时才出手，
所以正常玩法的手感、落点、合成判定**一点没变**。

**回归网：** 新增 `src/games/fruit-stack/stall.test.ts`，直接把当初卡住的果堆摆回去，
断言在 `FREEZE_MS` 之内一定 `allSettled`；另外覆盖了「正常果堆不会被看门狗提前冻住」这一面。

**复验：** 第 132 关落点不挪投完 43 颗 → **收得了场**；人机对战电脑不再空转。

### 1.2 `R3-PA-FS-3` · `fruit-stack` 双盆同帧达标永远判朵朵赢，「打平」是死文案（严重）

**症状：** `checkEnd` 的双盆分支按 0 号 → 1 号顺序问，同帧都达标就永远是 0 号（朵朵）赢。
实测两人同步投，投放数 **81 : 81 却是 3 : 0**；`roundOver` 里那句「这一局打平」够不着。

**修法：** 把判定从 `checkEnd` 里抽成纯函数 `decideRound(bowls): RoundVerdict | null`，
**先把两盆的收场状态都读出来再一起裁**：

- 两盆同帧都达标 → **判平**（那句死文案活了）；
- 两盆同帧都出局 → **判平**；
- 只有一盆达标 / 出局 → 按实际那一盆报赢家与原因；
- 都没到 → 返回 `null`，这一局继续。

`checkEnd` 现在只负责把 `decideRound` 的结论加上分数 / 层数 / 连锁 / 投放数交给 `settle`。

**回归网：** 新增 `src/games/fruit-stack/round.test.ts`，把单盆 / 双盆 / 同帧双赢 /
同帧双负 / 一赢一负五种组合逐个摆出来断言。
