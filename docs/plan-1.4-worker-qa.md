# 1.4 · 每窗三轮验收（测试员 / 学习优化员 / 监督修复员；整份粘贴，替换 `{{WINDOW}}` / `{{BRANCH}}` / `{{GAMES}}` / `{{ROUND}}`）

> 本包在本窗口全部工单（每款 t1 + t2，窗口 5 另有 t3）IDLE 且 `npm test` / `npm run build` 全绿后才派。每轮先派测试员；测试员 IDLE 后再并行派学习优化员与监督修复员。三轮串行。
> 报告路径固定：`docs/qa/1.4/window{{WINDOW}}-round{{ROUND}}-tester.md` / `-learner.md` / `-fixer.md`。别人的报告一个字不碰。
> 与 1.3 不同：**本轮验收是全科**（可通关 / bug / 手感 / UI / 曲线 / 建模 / 纵深），不只视觉。

## 角色 3 · 测试员（只测不修，可新增测试）

范围：**只验本窗口游戏** `{{GAMES}}`。零改 `src/games/<id>/` 非测试文件。

必做矩阵（每款都要有一行结论，数字进报告）：

| 项 | 做法 | 通过线 |
| --- | --- | --- |
| 188 关审计 | `npx vitest run src/games/<id>/levels.audit.test.ts`；再用种子 `[7, 11, 13]`（工人没用过的）跑一遍 `runCampaign` | 失败清单空；新种子下 `mode:"any"` 仍空 |
| 实机抽玩 | 无头 Chrome 走 UI：L1、章首一关、L100、L188（🔑 密码门 UI 解锁，不种 storage）、无尽 / 对战首局；每关至少打到结算 | 能开始、能结束、能重试、能返回；控制台 0 error |
| Bug 回归 | 对照该款 `audit.md` 的 P0/P1 条目逐条复现 | 全部不再复现 |
| 手感 | 读代码确认 `feedback(` 接入点 ≥ 事件表条数；`reduced` 契约测试存在；实机开 `prefers-reduced-motion` 后无 shake | 契约测试绿；reduced 无位移 |

| 宪法 | 第二节负面清单六条逐条 | 全「无」 |
| 纵深（窗口 5） | 四件套 + reduced 降级 + flat 等价测试 | 齐 |
| 商标 / 依赖 | `rg -i "<黑名单>" src/ README.md --glob '!.cursor/skills/**'`；`git diff origin/game-1.4 -- package.json` | 0 命中；无新依赖 |

新伤编号：先 `rg -o "V-[0-9]+" docs/qa/1.4 | sort -u` 取最大号续编（1.4 用 **V 系列**），撞号改号不覆盖。每条写：对象、复现、数字、性质（🔧 必修 / 🟡 降级 / 👀 观察）、建议修法、归哪张工单。

## 角色 4 · 学习优化员（只学习只记录，零代码）

读本轮 tester 报告 + 本窗所有 `audit.md`，输出：
1. 本窗共性病（≥ 5 条）与「配方」（哪款修得最好，抄哪段）。
2. 对五个 gamedev skill 的本仓落地笔记（每个 ≤ 8 行：哪条原则在本窗哪款落了地、哪条落不了为什么）。
3. 给下一轮 fixer 的排序建议与给其他窗口的提醒（写清不要越界）。
4. 若发现框架 / 共享文件问题 → 写成需求单段落「给窗口 1 / 窗口 5」。

## 角色 5 · 监督修复员（修，按序，每修一处一 commit）

先读本轮 tester（必须）与 learner（若已出）报告。顺序：🔧 P0（跳不过去 / HARD-OUT / 崩溃）→ P1（bug / 不合理 / 红灯）→ 手感契约缺失 → 热区与正文 → 曲线跳变 → 宪法负面项 → 建议项。
规则同单款工序：审计测试先红后绿、测试只增不减、不改存档 key / 总关数 / 500 档原文、不越本窗目录、共享文件只写需求单。
报告末尾：修了哪些 V 号、各自 commit、新增用例数、`npm test` 水位、未修与原因。
