## 三、现状审查（回复里逐条回答）

1. 两个角色的属性差异（冰只能过冰池、火只能过火池、双方都不能过泥沼？）是否有纯函数判定？

5. 摄像机怎么处理两人分散（拉远？分屏？拉回？）
6. 死亡（掉池）后是整关重来还是回检查点？

## 四、1.2 玩法升级

| 项 | 规格 |
| --- | --- |
| **手感常量化** | 重力 / 跳跃 / 土狼时间 ~90ms / 跳跃缓冲 ~120ms / 边缘吸附，全部抽常量并单测；30fps 与 60fps 位移差 < 2%。 |
| **合作机关补齐** | 至少 6 种：双人按钮、顶举、绳索拉伸、可推箱、传送门配对、需要两人同时踩的电梯。每种一个纯函数 + 用例。 |
| **单人模式** | 补「切换控制 + 另一角色留在原地」的单人玩法（`Tab` / 触屏切换按钮）。**这是让家里独生孩子也能玩的关键**，不做就写明理由。 |
| **检查点** | 每关 2–3 个检查点；掉池后回最近检查点并保留已开机关状态，不许整关重来。 |
| **摄像机** | 两人分散时先拉远（有上限），超限则给「另一位在这边」的箭头提示，不要硬拽玩家。 |

## 五、模式矩阵

`campaign` 188 保留（**前 99 关关卡数据不改**）；`coop` / `twoPlayer` 保留；无尽**不做**（合作解谜不适合无限拼接，写明理由）。

## 六、2.5D / 3D 决策

**保持 2D 侧视**。可加背景视差与前景遮挡（不影响判定）。

## 七、视觉 · 建模 · 手感

- 冰 / 火池用形状 + 纹理区分，不能只靠颜色（色觉友好）。
- 掉池是「变成小云朵飘回检查点」，**无死亡描写**。
- 机关联动有明显光路提示（哪个按钮开哪扇门）。
- `prefers-reduced-motion`：关抖动与闪烁。

## 八、手机 360px

- 左右半屏各一套（方向 + 跳），热区 ≥ 44px；单人模式下切换按钮固定在中间上方。
- 关卡在窄屏要能整屏或平滑跟随，不许角色贴边看不到前方。

## 九、平台接线

- `openCampaignLevel(n)` / `initialLevel` / `?level=` 直开第 N 关；Skip 走 `requestSkip`，本关 0 星并解锁下一关。
- `meta.platform` 按实测填（双人键盘偏桌面，触屏双人也行 → 多半 `"both"`）；`blurb` 与事实对齐。
